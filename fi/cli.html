6. Komentoriviliittymä (CLI)

6.1. Johdanto

blunderDB sisältää täydellisen komentoriviliittymän (CLI) samassa suoritettavassa tiedostossa kuin graafinen käyttöliittymä. CLI on erityisen hyödyllinen seuraaviin tarkoituksiin:

  • ottelujen massatuonti: koko hakemistollinen ottelutiedostoja (XG, SGF, MAT, BGF…) tuodaan yhdellä komennolla,

  • automaatio: blunderDB:n integrointi shell-skripteihin säännöllisiä varmuuskopioita, ajastettuja vientejä tai käsittelyputkia varten,

  • palvelinkäyttö: tietokantojen hallinta koneilla, joilla ei ole graafista ympäristöä,

  • nopea tarkastus: tietokannan sisällön tai eheyden tarkistaminen käynnistämättä graafista käyttöliittymää.

CLI käyttää täsmälleen samaa tietokantamuotoa kuin graafinen käyttöliittymä. Mikä tahansa CLI:llä tehty toimenpide näkyy välittömästi graafisessa käyttöliittymässä ja päinvastoin.

6.2. Yleinen syntaksi

Tila tunnistetaan automaattisesti: jos ensimmäinen argumentti on CLI-komento, blunderDB käynnistyy headless-tilassa, muuten se käynnistää graafisen käyttöliittymän.

# Mode graphique (aucun argument)
./blunderdb

# Mode CLI
./blunderdb <commande> [options]

6.4. create — Luo tietokanta

Luo uusi tietokantatiedosto valinnaisilla metatiedoilla.

./blunderdb create --db <chemin> [--user <nom>] [--description <texte>] [--force]

Valitsimet:

  • --db — Luotavan tietokantatiedoston polku (pakollinen).

  • --user — Tietokannan omistajan nimi.

  • --description — Tietokannan kuvaus.

  • --force — Korvaa tiedosto, jos se on jo olemassa.

  • --format — Tulostusmuoto: text (oletus) tai json (polku, versio, käyttäjä, kuvaus, luontipäivä).

.db-pääte lisätään automaattisesti, jos se puuttuu. Ylähakemistot luodaan tarvittaessa.

Esimerkki:

./blunderdb create --db mes_matchs.db --user "Jean" --description "Matchs de tournoi 2025"

6.5. import — Tuo tietoja

Tuo ottelu- tai asematiedostoja tietokantaan.

./blunderdb import --db <chemin> --type <type> [options]

Valitsimet:

  • --db — Tietokannan polku (pakollinen).

  • --type — Tuontityyppi: match, position tai batch (pakollinen).

  • --file — Tuotava tiedosto (tyypeille match ja position).

  • --dir — Tuotava hakemisto (tyypille batch).

  • --recursive — Selaa alihakemistot rekursiivisesti (oletus: kyllä).

  • --format — Tulostusmuoto: text (oletus) tai json.

  • --fail-on-error — Epäonnistuu, jos edes yhtä kohdetta (position tai batch) ei voitu tuoda, vaikka muut onnistuisivat.

Se, ettei mitään tuoda lainkaan, on aina virhe riippumatta siitä, annetaanko --fail-on-error: tiedosto tai hakemisto, josta ei tuotu mitään, ei koskaan ole hiljainen onnistuminen. Osittainen epäonnistuminen (osa kohteista tuotiin, osaa ei) kaataa komennon vain, jos --fail-on-error on annettu.

6.5.1. Ottelun tuonti

Tuetut muodot: eXtreme Gammon (.xg, .xgp), GNUbg (.sgf), Jellyfish (.mat, .txt) ja BGBlitz (.bgf).

./blunderdb import --db base.db --type match --file match.xg

6.5.2. Asemien tuonti

Tuo asemia tekstitiedostosta (yksi JSON-asema riviä kohden):

./blunderdb import --db base.db --type position --file positions.txt

6.5.3. Erätuonti

Tuo kaikki hakemiston ottelutiedostot yhdellä toimenpiteellä. Tämä on tehokkain tapa tuoda suuri määrä otteluita.

# Import récursif (par défaut)
./blunderdb import --db base.db --type batch --dir ./matchs/

# Import non récursif
./blunderdb import --db base.db --type batch --dir ./matchs/ --recursive=false

# Sortie exploitable par un script, échec si un fichier a été refusé
./blunderdb import --db base.db --type batch --dir ./matchs/ --format json --fail-on-error

Yhteenvetotaulukko näyttää jokaisen tiedoston kohdalla, onnistuiko tuonti (✓), epäonnistuiko (✗) vai oliko kyseessä kaksoiskappale (⊘). Kaksoiskappale ei ole sinänsä epäonnistuminen: eräajon uudelleensuorittaminen jo tuodulle hakemistolle, ilman uusia tiedostoja, pysyy onnistumisena.

6.6. export — Vie tietoja

Vie tietokannan sisältö tiedostoihin.

./blunderdb export --db <chemin> --type <type> --file <sortie> [options]

Valitsimet:

  • --db — Lähdetietokanta (pakollinen).

  • --type — Vientityyppi: database, positions, matches tai mat (yhden tai useamman ottelun vienti Jellyfish .mat -transkriptioon) (pakollinen).

  • --file — Tulostiedosto (pakollinen, paitsi --type mat -vaihtoehdolle yhdessä --dir kanssa).

  • --dir — Erävientinä tehtävän .mat-viennin tulostushakemisto (useita otteluita, yksi tiedosto ottelua kohden; ilman --match-ids viedään kaikki ottelut).

  • --analysis — Sisällytä analyysit (oletus: kyllä).

  • --comments — Sisällytä kommentit (oletus: kyllä).

  • --filters — Sisällytä suodatinkirjasto (oletus: kyllä).

  • --played-moves — Sisällytä pelatut siirrot (oletus: kyllä).

  • --matches — Sisällytä ottelut (oletus: kyllä).

  • --collections — Sisällytä kokoelmat (oletus: ei).

  • --collection-ids — Vietävien kokoelmien tunnukset (pilkulla eroteltuna).

  • --match-ids — Vietävien otteluiden tunnukset (pilkulla eroteltuna, tyhjä = kaikki).

  • --tournament-ids — Vietävien turnausten tunnukset (pilkulla eroteltuna).

  • --password — Kääri tuloksen salattuun säiliöön (.dbx).

  • --watermark — Kirjoittaa allekirjoitetun alkuperäilmoituksen vietyyn tiedostoon (katso Tietokannan jakaminen: alkuperä ja salasana).

  • --watermark-note — Vesileimaan liitettävä vapaa teksti (käyttöehdot, yhteystieto); käytetään yhdessä --watermark-valitsimen kanssa.

  • --format — Tulostusmuoto: text (oletus) tai json (vientiä kokoava asiakirja: polku, koko tavuina, määrät).

Esimerkkejä:

# Export complet de la base
./blunderdb export --db base.db --type database --file sauvegarde.db

# Export des positions en JSON
./blunderdb export --db base.db --type positions --file positions.txt

# Export de matchs spécifiques
./blunderdb export --db base.db --type matches --file selection.db --match-ids 1,3,5

# Export d'un match en transcription .mat (Jellyfish)
./blunderdb export --db base.db --type mat --match-ids 5 --file match5.mat

# Export de plusieurs matchs (ou de tous) en .mat dans un répertoire
./blunderdb export --db base.db --type mat --match-ids 5,9,12 --dir sorties/
./blunderdb export --db base.db --type mat --dir sorties/

# Export filigrané et protégé par mot de passe (fichier .dbx)
./blunderdb export --db cours.db --type database --file cours-diffusion.dbx \
    --watermark "Cours de Jean Dupont — 12 mars 2026" \
    --watermark-note "Merci de ne pas rediffuser." \
    --password secret

Vesileima allekirjoitetaan paikallisella liikkeeseenlaskijan identiteetillä (katso identity-komento alla): sitä ei voi väärentää, mutta sen voi poistaa — tiedosto pysyy tavallisena SQLite-tietokantana. Se ei suojaa mitään, se vain kertoo, mistä tiedosto on peräisin. Salasana suojaa tiedoston kuljetusta (kadonnut kopio, vahingossa lähetetty liite), ei itse tietokantaa: kuka tahansa salasanan saanut voi avata sen. blunderDB ei koskaan kirjaa mitään vastaanottajan puolelle (ei rekisteriä, ei lokia) — katso ADR-0007.

6.7. identity — Liikkeeseenlaskijan identiteetti

Näyttää tai siirtää liikkeeseenlaskijan identiteettisi: Ed25519-avaimen, joka allekirjoittaa jokaisen vesileiman. Se syntyy itsestään ensimmäisen vesileiman yhteydessä; mitään ei tarvitse asettaa. Se kuuluu henkilölle, ei tietokannalle: kaikki merkitsemäsi kantaa yhtä ja samaa julkista sormenjälkeä.

./blunderdb identity                                       # nom et empreinte
./blunderdb identity --name "Jean Dupont"                  # renommer
./blunderdb identity --export jean.bdbid --passphrase pw   # exporter vers une autre machine
./blunderdb identity --import jean.bdbid --passphrase pw

Valitsimet:

  • --name — Vaihtaa identiteetin näyttönimen.

  • --export — Vie identiteetin .bdbid-tiedostoon.

  • --import — Tuo identiteetin .bdbid-tiedostosta.

  • --passphrase — Valinnainen tunnuslause, joka suojaa viedyn/tuodun tiedoston (paikallinen identiteetti jätetään tarkoituksella suojaamatta).

  • --format — Tulostusmuoto: text (oletus) tai json (nimi, sormenjälki, tallennuspolku).

Viety tiedosto antaa kenelle tahansa sen haltijalle mahdollisuuden allekirjoittaa sinun nimissäsi — älä jaa sitä. Uudelleennimeäminen muuttaa vain nimilapun: jo merkityt tiedostot säilyttävät nimen, jolla ne sinetöitiin, ja ne todentuvat edelleen.

6.8. open — Suojatun tiedoston avaaminen

Muuntaa salasanalla suojatun tiedoston (.dbx) tavalliseksi tietokannaksi. Salasanaa kysytään vain kerran; sen jälkeen kyseessä on tavallinen tiedosto.

./blunderdb open --db cours.dbx --password secret
./blunderdb open --db cours.dbx --password secret --file ./mon-cours.db

Valitsimet:

  • --db — Avattava .dbx-tiedosto (pakollinen).

  • --password — Säiliön salasana (pakollinen).

  • --file — Tavallisen tietokannan tulostuspolku (oletus: sama nimi, pääte .db).

Mitä salasana suojaa: tiedoston kuljetusta — latauskansioon unohtunutta kopiota, vahingossa lähetettyä liitettä. Ei tietokantaa: kuka tahansa salasanan saanut voi avata sen. Säiliön otsake on selkokielinen, joten blunderdb info lukee suojatun tiedoston alkuperän ilman salasanaa.

6.9. search — Hae asemia

Hae asemia tietokannasta yhdisteltävien kriteerien avulla.

./blunderdb search --db <chemin> [options]

Pääasialliset valitsimet:

  • --db — Tietokanta (pakollinen).

  • --format — Tulostusmuoto: table, json tai xgid (oletus: table).

  • --limit — Tulosten enimmäismäärä (0 = rajoittamaton).

  • --export — Vie tulokset uuteen tietokantaan.

Käytettävissä olevat suodattimet:

  • --decision — Päätöstyyppi: checker tai cube.

  • --dice — Nopanheitto. 5,3 hakee asemat, joissa molemmat nopat täsmäävät (järjestyksellä ei ole väliä). 5 hakee asemat, joissa 5 esiintyy jommassakummassa nopassa (toisen nopan arvo jätetään huomiotta). Sisältää --decision checker, jos --decision-arvoa ei ole annettu.

  • --pip-min / --pip-max — Pip-eron väli.

  • --winrate-min / --winrate-max — Voittoprosentin väli (%).

  • --cube — Tuplauskuution arvo.

  • --score1 / --score2 — Pelaajien pisteet.

  • --match-length — Ottelun pituus.

  • --error-min — Vähimmäisekvitettivirhe.

  • --move-error-min / --move-error-max — Pelatun siirron virhe (millipistettä).

  • --has-analysis — Vain asemat, joissa on analyysi.

  • --off1-min / --off2-min — Vähimmäismäärä ulospelattuja nappuloita (pelaaja 1/2).

  • --match-ids — Suodata otteluiden tunnusten mukaan (pilkulla eroteltuna).

  • --tournament-ids — Suodata turnausten tunnusten mukaan (pilkulla eroteltuna).

  • --position-ids — Suodata asemien tunnusten mukaan: väli 2,7 (asemat 2–7) tai puolipisteillä eroteltu eksplisiittinen luettelo 5;10;15.

  • --individual — Vain erikseen tuodut asemat, eli ne jotka lisäsit itse, eikä niitä jotka ottelun tuonti toi mukanaan.

  • --flagged — Vain asemat, jotka on merkitty (flag) tutkittaviksi alkuperäisessä ohjelmassa (eXtreme Gammonin merkinnät). Ei takautuva: jo tuodut ottelut on tuotava uudelleen, jotta merkinnät saadaan.

  • --has-comment — Vain asemat, joissa on kommentti. Alkuperää ei eroteta: käsin kirjoitettu muistiinpano ja ottelun tuonnin mukana tullut kommentti lasketaan molemmat. Ottelun tai turnauksen kommentteja ei katsota.

  • --no-comment — Vain asemat ilman kommenttia. Toisensa poissulkeva --has-comment-valitsimen kanssa.

Kyselykieli:

Yllä olevat valitsimet kattavat vain osan suodattimista. --query antaa pääsyn sovelluksen kyselykieleen — komentorivin kieleen, joka kuvataan sivulla Komentoluettelo — ja siten kaikkiin suodattimiin, joita ei piirretä laudalle: siirtokuvio, kommenttiteksti, pelaaja, päivämäärä, equity, poissuljetut heitot, vyöhykkeet ja blotit.

# Décisions de videau, 30 pips de retard, 50 millipoints d'erreur
./blunderdb search --db base.db --query 's cube p>30 E>50'

# Filtres qu'aucun drapeau n'expose
./blunderdb search --db base.db --query 's m"13/11" t"blunder" pl"Alice" T>2026/01/01'

# La liste des jetons compris
./blunderdb search --query-help

--query korvaa suodatinvalitsimet sen sijaan että täydentäisi niitä: niiden yhdistäminen hylätään, ja virheellinen valitsin nimetään. Valitsimet, jotka kertovat mistä haetaan ja miten näytetään — --db, --format, --limit, --offset, --export — pysyvät voimassa.

Tunnistamaton osanen kaataa komennon sen sijaan että kaventaisi hakua hiljaisesti. Kaksi rajoitusta seuraa siitä, ettei komentorivillä ole lautaa: nappulakuviota ei voi kirjoittaa, ja cube, score ja D vertautuvat hakulautaan, joka on täällä tyhjä — käytä valitsimia --dice, --cube ja --score1/--score2.

Esimerkkejä:

# Rechercher les décisions de videau
./blunderdb search --db base.db --decision cube

# Retrouver les positions que vous avez ajoutées vous-même
./blunderdb search --db base.db --individual

# Rechercher les positions avec erreur >= 0.1
./blunderdb search --db base.db --error-min 0.1

# Rechercher dans un tournoi et exporter
./blunderdb search --db base.db --tournament-ids 1 --export cubes.db

# Rechercher les positions avec un lancer de dés 6-5 (peu importe l'ordre)
./blunderdb search --db base.db --dice 6,5

# Rechercher les positions où un 6 a été obtenu sur l'un des deux dés
./blunderdb search --db base.db --dice 6

# Sortie JSON limitée à 10 résultats
./blunderdb search --db base.db --format json --limit 10

6.10. list — Luettele sisältö

Näytä tietokannan sisältö.

./blunderdb list --db <chemin> --type <type> [--limit <n>]

Tyypit:

  • matches — Luettelo tuoduista otteluista.

  • tournaments — Luettelo turnauksista.

  • positions — Luettelo asemista (oletuksena rajoitettu 10:een).

  • stats — Suorituskykytilastojen raportti: PR / Snowie ER / MWC (kokonais, nappulat, kuutio), liukuva PR viimeisten N päätöksen osalta, pahimmat virheet, jakauma kuutiotoiminnoittain ja virhesuuruuksien histogrammi.

  • players — Vertailutaulukko, yksi rivi kutakin tietokannan pelaajaa kohden: ottelut, voitot/tappiot, lasketut päätökset, PR yhteensä / nappulat / kuutio, Snowie ER, virheet, karkeat virheet ja tuuri. Tämä on tilastopaneelin Pelaajat-välilehden komentorivivastine.

Valinnat (vain ``stats``-tyyppi):

  • --metric — Näytettävä mittari: pr tai mwc (oletus: pr).

  • --player — Rajaa ilmoitettuun pelaajaan.

  • --tournament — Rajaa yhteen tai useampaan turnauksen tunnukseen (pilkulla eroteltuna).

  • --from — Aloituspäivä (VVVV-KK-PP).

  • --to — Lopetuspäivä (VVVV-KK-PP).

  • --decision-type — Päätöstyyppi: all, checker tai cube (oletus: all).

  • --top-blunders — Lueteltavien pahimpien virheiden määrä (oletus: 10).

  • --format — Tulostusmuoto: text tai json (oletus: text).

Valitsimet (vain tyyppi ``players``):

  • --from / --to — Päivämäärärajat (VVVV-KK-PP), esimerkiksi kilpailun päivät.

  • --tournament — Rajaa yhteen tai useampaan turnaustunnukseen.

  • --format — Tulostusmuoto: text, json tai csv (oletus: text).

--player ja --decision-type eivät koske tätä tyyppiä: taulukko kattaa kaikki pelaajat ja erittelee nappulat ja kuution jo omiin sarakkeisiinsa.

Muista

Viiva ”—” (CSV:ssä tyhjä kenttä) merkitsee arvoa, jota ei ole koskaan mitattu; sitä ei pidä sekoittaa nollaan. Näin on tuurin kohdalla kaikissa otteluissa, jotka tuotiin ennen skeemaversiota 2.15.0, sekä muodoissa, jotka eivät sitä kuljeta (BGF, Jellyfish .mat): tuo lähdetiedostot uudelleen saadaksesi sen. Sarake luck_rolls kertoo, kuinka monesta heitosta keskiarvo on laskettu.

Esimerkkejä:

# Statistiques de la base
./blunderdb list --db base.db --type stats

# Statistiques en MWC pour un joueur donné
./blunderdb list --db base.db --type stats --metric mwc --player "Alice"

# Coups de pions uniquement, depuis une date
./blunderdb list --db base.db --type stats --decision-type checker --from 2026-01-01

# Sortie JSON (pour un script)
./blunderdb list --db base.db --type stats --format json

# Un tableau par joueur, borné aux dates d'une compétition
./blunderdb list --db base.db --type players --from 2026-03-01 --to 2026-03-08

# Le même tableau en CSV (tableur ou script)
./blunderdb list --db base.db --type players --format csv

# Liste des matchs
./blunderdb list --db base.db --type matches

# Premières 20 positions
./blunderdb list --db base.db --type positions --limit 20

6.11. match — Näytä ottelu

Näytä tuodun ottelun asemat ja analyysit.

./blunderdb match --db <chemin> --id <id_match> [--format <format>] [--output <fichier>]

Valitsimet:

  • --db — Tietokanta (pakollinen).

  • --id — Näytettävän ottelun tunnus (pakollinen).

  • --format — Tulostusmuoto: json, text tai summary (oletus: json).

  • --output — Tulostiedosto (oletus: vakiotuloste).

Esimerkkejä:

# Résumé d'un match
./blunderdb match --db base.db --id 1 --format summary

# Détails de chaque position
./blunderdb match --db base.db --id 1 --format text

# Export JSON vers un fichier
./blunderdb match --db base.db --id 1 --output match1.json

6.12. collection — Kokoelmien hallinta

Hallitsee kokoelmia, näitä käyttöliittymän Kokoelmat-paneelissa käsin valittuja asemajoukkoja. Jokainen alikomento ottaa parametrin --db; list ja show hyväksyvät parametrin --format text (oletus), json tai csv, kuten list.

./blunderdb collection <sous-commande> [options]

Alikomennot:

  • list — Kokoelmien luettelo: tunnus, nimi, asemien määrä, kuvaus.

  • show --id <id> — Kokoelman asemat: tunnus, indeksi (käyttöliittymän tilarivillä näytetty 1-pohjainen numero), pistetilanne, päätöstyyppi ja XGID.

  • create --name <nom> [--description <texte>] — Luo tyhjän kokoelman.

  • rename --id <id> --name <nom> [--description <texte>] — Nimeää kokoelman uudelleen (kuvaus säilyy, jos sitä ei anneta).

  • delete --id <id> [--confirm] — Poistaa kokoelman; sen asemat säilyvät tietokannassa.

  • export --id <id[,id…]> --out <fichier.db> [--analysis=false] [--comments=false] [--watermark <texte>] [--watermark-note <texte>] — Vie yhden tai useamman kokoelman uuteen tietokantatiedostoon samalla kutsulla kuin käyttöliittymän vienti-ikkuna (katso vesileimasta komento export).

show-komennon näyttämä XGID on aseman analyysin yhteydessä tallennettu XGID, jos sellainen on olemassa (BGF- ja XGP-tuonnit); muutoin se generoidaan laudalta täsmälleen samoin kuin käyttöliittymän Kopioi asema -toiminto tekee — ottelun pituudeksi tulee tällöin suurempi kahdesta jäljellä olevasta pistemäärästä, sillä tallennettu asema ei säilytä todellista ottelun pituutta.

Esimerkkejä:

# Toutes les collections
./blunderdb collection list --db base.db

# Positions de la collection 3, en CSV pour un tableur
./blunderdb collection show --db base.db --id 3 --format csv

# Créer, renommer, supprimer
./blunderdb collection create --db base.db --name "Ouvertures blitz"
./blunderdb collection rename --db base.db --id 3 --name "Ouvertures"
./blunderdb collection delete --db base.db --id 3 --confirm

# Exporter deux collections, marquées de leur origine
./blunderdb collection export --db base.db --id 3,4 --out ouvertures.db \
    --watermark "Cours de Jean Dupont - 12 mars 2026"

6.13. anki — Välitoistopakat

Tarkastelee ja ylläpitää käyttöliittymän Anki-paneelin välitoistopakkoja (FSRS). Kortin kertaaminen vaatii laudan ja tapahtuu käyttöliittymässä; CLI listaa, mittaa ja synkronoi uudelleen.

./blunderdb anki <sous-commande> [options]

Alikomennot:

  • decks [--format text|json|csv] — Pakkojen luettelo: lähde, korttien määrä, erääntyneet kortit, uudet kortit.

  • stats --deck <id> [--format text|json] — Pakan kertaustilastot: yhteensä, uudet, opittavana, kerrattavat, nyt erääntyvät, sekä sen FSRS-parametrit.

  • forecast [--deck <id>] [--days <n>] [--format text|json|csv] — Erääntyvät kortit kalenteripäivittäin (UTC) seuraavien n päivän aikana (oletus 30, enintään 365); päivä 0 sisältää kaikki myöhässä olevat kortit; --deck 0 (oletus) kattaa kaikki pakat.

  • sync --deck <id> — Lisää kortin jokaiselle pakan lähteen asemalle, jolla ei vielä ole korttia; olemassa olevat kortit säilyttävät ajoituksensa.

  • retention --deck <id> [--format text|json] — pakan mitattu muistiinjäänti verrattuna omistajan valitsemaan tavoitteeseen.

  • card --id <id> --action suspend|unsuspend|bury|remove [--format text|json] — kohdistuu yhteen korttiin. Hyllytys siirtää sen syrjään historiaa menettämättä (se ei enää tule vastaan istunnossa); hautaus piilottaa sen seuraavaan päivään sanomatta mitään sen arvosta; poisto poistaa sen pakasta — asema itse jää kirjastoon, sillä pakka on vain sen päälle asetettu opiskelulista.

  • log [--deck <id>] [--limit <n>] [--format text|json] — kertausloki, tuorein ensin (--deck 0, oletus, kattaa kaikki pakat; --limit on oletuksena 20). Loki on se, mitä ajoittajalle todella kerrottiin, vastakohtana sille, mitä se tänään suunnittelee: ainoa paikka, jossa vahingossa annettu arvosana näkyy.

Kokoelmaan perustuva pakka lukee kokoelmansa uudelleen. Hakuun perustuva pakka säilyttää haun sellaisena kuin käyttöliittymä sen tallensi (komento, lauta ja tuolloin löydettyjen asemien tunnukset): hakusyntaksi elää käyttöliittymässä, joten CLI synkronoi uudelleen tallennetuista tunnuksista ja ilmoittaa siitä virhetulosteeseen — avaa pakka käyttöliittymässä toistaaksesi itse haun.

Esimerkkejä:

./blunderdb anki decks --db base.db
./blunderdb anki stats --db base.db --deck 2 --format json
./blunderdb anki forecast --db base.db --deck 2 --days 14
./blunderdb anki sync --db base.db --deck 2
./blunderdb anki card --db base.db --id 12 --action suspend
./blunderdb anki log --db base.db --deck 2 --limit 50

# Day         Due
# ---         ---
# 2026-09-02  12
# 2026-09-03  4
# ...
#
# 37 card(s) due over 14 day(s)

6.14. epc — EPC-laskin

Laskee XGID:nä annetun ulosajoaseman Effective Pip Countin, voittotodennäköisyyden ja rahapelin kuutiotuomion. Puhdas laskenta: mikään tietokantatiedosto ei ole mukana.

./blunderdb epc [options] '<XGID>'

Valitsimet:

  • --format — Tulostusmuoto: text tai json (oletus: text).

  • --bearoff-ts — Valinnainen kaksipuolinen bearoff-tietokanta (.bd), joka laajentaa sisäänrakennettua TS-06-06:ta (luetaan myös ympäristömuuttujasta BLUNDERDB_TS_PATH). Laajin kelvollinen tietokanta voittaa; kelvoton tiedosto ohitetaan varoituksella.

Toimintatilat. Kaksipuolisen tietokannan kattamalla alueella voittotodennäköisyys ja rahapelin kuutioanalyysi (cubeless, ND, D/T, D/P, tuomio) ovat tarkkoja. Sen ulkopuolella voittotodennäköisyys arvioidaan (yksipuolisten heittojakaumien konvoluutio ja kalibroitu korjaus) ja näytetään mitatun virhemarginaalinsa kanssa; kuutiotuomiota ei tarkoituksella arvioida koskaan (katso ADR-0009).

Esimerkkejä:

# Régime exact (les deux joueurs ont 6 pions ou moins)
./blunderdb epc 'XGID=-BBB------------------bbb-:0:0:1:00:0:0:0:0:10'

# Avec la base TS-06-11 calculée (exact jusqu'à 11 pions par joueur)
./blunderdb epc --bearoff-ts ~/.local/share/blunderdb/gnubg_ts6x11.bd 'XGID=…'

6.15. bearoff — Bearoff-tietokannat

Luo ja hallinnoi bearoff-tietokantoja. Mitään ei ladata eikä mitään ole upotettu: taulukko lasketaan täällä ja tarkistetaan sitä sormenjälkeä vasten, jonka gnubg tuottaa sen alueelle. Yksikään alikomento ei puhu tietokannan kanssa — bearoff-taulukko on aritmetiikkaa pelistä, ei kenenkään asemista — joten yksikään ei ota --db.

./blunderdb bearoff generate --ts <domaine> [options]
./blunderdb bearoff list [options]
./blunderdb bearoff verify <fichier.bd> [options]
./blunderdb bearoff delete --ts <domaine> [options]

Alue kirjoitetaan kuten makebearoff-työkalussa: 6x9 kaksipuoliselle taulukolle yhdeksällä nappulalla pelaajaa kohden, os8 kahdeksan pisteen yksipuoliselle taulukolle (pelkkä os tarkoittaa os6).

Kaksi perhettä eivät vastaa samaan kysymykseen. Kaksipuolinen taulukko laajentaa aluetta, jolla voittotodennäköisyys ja kuution tuomio ovat tarkkoja; yksipuolinen laajentaa sitä, kuinka kaukana kotoa nappula saa olla ilman että EPC vaikenee (enintään kymmenen pistettä).

generate. Kertoo koon, muistintarpeen ja arvioidun ajan ennen aloitusta, sitten näyttää prosenttiosuuden ja mitatun jäljellä olevan ajan.

  • --ts — Laskettava kaksipuolinen alue, esimerkiksi 6x9.

  • --os — Laskettava yksipuolinen alue pisteiden määränä: 6–12. Näistä kahdesta tarvitaan täsmälleen yksi.

  • --cores — Käytettävät ytimet (oletus: kaikki paitsi yksi).

  • --data-dir — Minne kirjoitetaan (oletus: sovelluksen datakansio).

  • --quiet — Ei edistymisriviä.

CTRL-C keskeyttää tauolle. Signaali otetaan kiinni: tila kirjoitetaan taulukon viereen, ja sama komento uudelleen ajettuna jatkaa siitä mihin jäi sen sijaan että laskisi kaiken uudelleen. Puoli tuntia aritmetiikkaa kannattaa kirjoittaa muistiin. bearoff delete heittää odottavan jatkon pois. Vain kaksipuolinen ajo menee tauolle; yksipuolinen on peräkkäinen eikä --cores hyödytä sitä.

list. Hinnoittelee jokaisen alueen — koko, muisti, aika tällä koneella — ja kertoo mitkä ovat jo olemassa, tuomioineen, ja millä on tauolla oleva ajo. --format json skriptiä varten, --cores arvion oletuksen muuttamiseen.

verify. Vastaa verified (samat tavut kuin viitteessä), unverified (hyvin muodostettu, mutta alueelle ei ole tallennettu sormenjälkeä) tai corrupt (tiedosto on ristiriidassa itsensä kanssa). Päättyy virheeseen viimeisessä tapauksessa: tämä komento on tehty skriptiin pantavaksi.

delete. Poistaa taulukon, odottavan jatkon ja kuolleen ajon jäänteet. Oletusalue lasketaan uudelleen sovelluksen seuraavalla käynnistyksellä; laajempaa ei.

Esimerkkejä:

# Ce que cette machine a, et ce que chaque domaine coûterait
./blunderdb bearoff list

# Calculer TS-06-09 sur quatre cœurs
./blunderdb bearoff generate --ts 6x9 --cores 4

# Calculer OS-08 : l'EPC répond alors jusqu'à un pion sur la 8
./blunderdb bearoff generate --os 8

# Sur un serveur, dans le volume que lit le démon
./blunderdb bearoff generate --ts 6x11 --data-dir /srv/bearoff

# Vérifier une table reçue d'ailleurs
./blunderdb bearoff verify /srv/bearoff/gnubg_ts6x11.bd

6.16. analyze — gammonNet-täydennysanalyysi

Kirjoittaa gammonNet-analyysin jokaiselle asemalle, jolla ei ole yhtään analyysiä — ennen tämän toiminnon olemassaoloa kootun kirjaston täydentäminen (ADR-0013, ADR-0015). Kyseessä on sama toiminto kuin tuonnin jälkeinen automaattinen käynnistys ja graafisen käyttöliittymän painike « Analysoi nyt » sekä serve-daemonin päätepiste /v1/gammonnet.analyzeMissing yhdelle vuokralaiselle — saman toiminnon kolme eri muotoa, ei kolmea erillistä logiikkaa (katso Headless-tila (palvelin)).

./blunderdb analyze --db <chemin> [options]

Valitsimet:

  • --db — Tietokanta (pakollinen).

  • --ply — Hakusyvyys (oletus: 2, kanoninen asetus).

  • --prune-k — Karsinnan leveys (oletus: 12, kanoninen asetus).

  • --candidates — Siirtopäätöstä kohden säilytettävien ehdokassiirtojen määrä (oletus: 10).

  • --jobs — Rinnakkain analysoitavien asemien määrä (oletus: koneen ydinten määrä).

  • --format — Tulostusmuoto: text (oletus, edistymisen kanssa) tai json (yksi yhteenvetoasiakirja, tulostetaan lopussa).

Rinnakkaisuus (``–jobs``). Erän asemat ovat toisistaan riippumattomia — mikään haku ei vaikuta seuraavaan — joten ne jaetaan --jobs säikeelle, joista jokaisella on oma evaluaattorinsa. Kirjoitetut analyysit ovat identtiset riippumatta siitä, mikä arvo on annettu valitsimelle --jobs; vain laskenta-aika muuttuu. --jobs 1 jättää koneen vapaaksi muuhun käyttöön. Keskeytys ei muutu: Ctrl-C pysäyttää erän ennen jokaista uutta asemaa, ja kaikki jo laskettu kirjoitetaan.

Aukkosääntö (ADR-0013). Asemaan, jolla on jo analyysi — XG, GNUbg, BGBlitz tai aiempi gammonNet-ajo — ei koskaan kosketa riippumatta siitä, mikä moottori puuttuu. Vain asema, jolla ei ole yhtään analyysiä, kirjoitetaan. Komennon voi siis käynnistää uudelleen milloin tahansa ilman riskiä ja keskeyttää siististi: Ctrl-C peruuttaa menettämättä mitään jo kirjoitettua, ja seuraava ajo jatkaa täsmälleen siitä, mihin edellinen jäi — lokia ei tarvita, koska « asemat ilman analyysiä » lasketaan uudelleen jokaisella käynnistyksellä.

Esimerkki:

./blunderdb analyze --db base.db

# Analyzing 1204 position(s) with gammonNet (2-ply, k=12, 16 job(s))...
#   1/1204 (0%)
#   61/1204 (5%)
#   ...
#   1204/1204 (100%)
# Done.

# Sur un seul cœur, pour laisser la machine à autre chose
./blunderdb analyze --db base.db --jobs 1

6.19. verify — Tarkista eheys

Tarkista tietokannan eheys ja valinnaisesti vertaa ottelua sen lähdetiedostoon.

./blunderdb verify --db <chemin> [--match <id>] [--mat <fichier.mat>]

Valitsimet:

  • --db — Tietokanta (pakollinen).

  • --match — Tarkistettavan ottelun tunnus.

  • --mat — Verrattava MAT-tiedosto (käytetään yhdessä --match:n kanssa).

  • --format — Tulostusmuoto: text (oletus) tai json (tilastot, orvot rivit, skeemapoikkeama ja mahdollinen ottelun tarkistus).

Ilman --match-valitsinta komento näyttää tietokannan yleiset tilastot. --match-valitsimen kanssa se tarkistaa ottelun tiedot ja voi verrata niitä alkuperäiseen lähdetiedostoon.

Jokainen ajo tarkistaa myös viite-eheyden: se laskee orvot rivit — pelit ilman ottelua, siirrot ilman peliä, siirtoanalyysit ilman siirtoa, analyysit ilman asemaa, kertauspäiväkirjan merkinnät ilman pakkaa tai ilman asemaa — ja tulostaa WARNING-rivin kokonaismäärällä, jos niitä on. Terve tietokanta vastaa Orphaned rows: none. Orpoja voi jäädä tietokantaan, jonka kirjoitti versio joka ei valvonut vierasavaimia jokaisella yhteydellä, tai ennen kuin kertauspäiväkirjalla oli omansa; ne eivät kuulu mihinkään otteluun eivätkä mihinkään pakkaan ja vievät vain tilaa. Komento päättyy silti paluukoodiin 0.

Jokainen ajo vertaa myös skeemaa viite-DDL:ään ja luettelee taulut, sarakkeet ja indeksit, jotka tietokannasta puuttuvat. Tietokannan avaaminen lisää puuttuvat osat, kun se on mahdollista, ja vain kirjaa lokiin sen, mitä se ei voi lisätä (tyypillisesti UNIQUE-indeksin, jonka uudelleenrakentamisen kaksoisrivit estävät): tässä tuo puute tulee näkyviin, ja kysely, joka nimeää jonkin näistä osista, epäonnistuu, kunnes syy on korjattu. Terve tietokanta vastaa Schema: matches the reference DDL. Kuten orporivit, skeemapoikkeama on havainto, ei virhe: paluukoodi pysyy nollana.

Jokainen ajo tarkistaa lopuksi säännöt, jotka nykyinen DDL esittää mutta joita SQLite ei osaa lisätä jo olemassa olevaan tauluun: CHECK-rajoitteet (nopat välillä 0–6, tuplauskuutio ja pipit ei-negatiivisia, 0–15 ulos kannettua nappulaa, kertausarvosana välillä 1–4), Zobrist-tiivisteen, jota riviltä ei koskaan pitäisi puuttua, sekä yhden analyysin asemaa kohden. Skeemaversiosta 2.18.0 alkaen luotu tietokanta valvoo niitä; vanhempi voi yhä sisältää rivejä, jotka uusi tietokanta hylkäisi, ja juuri ne lasketaan tässä sääntö kerrallaan. Terve tietokanta vastaa Constraints: every row satisfies the current DDL. Yksi havainto lisää: mitään ei korjata ja paluukoodi pysyy nollassa.

Jokainen ajo laskee lopuksi uudelleen kaksi denormalisoitua laskuria, match.game_count ja game.move_count, niistä riveistä joita ne väittävät laskevansa, ja kertoo kuinka moni on eri mieltä ja kuinka paljon pahimmillaan. Molemmat kirjoitetaan kerran, tuonnin yhteydessä, sen mukaan mitä lähdetiedosto sisälsi, ja juuri ne näkyvät otteluluettelossa ja pelinäkymässä: pieni ero on useimmiten tuonti, joka ohitti sen mitä ei osannut muuntaa. Mitään ei kirjoiteta uudelleen — laskurin korvaaminen tallennetulla pyyhkisi juuri sen eron, jota kannattaa katsoa. Terve tietokanta vastaa Counters: game_count and move_count agree with the rows.

Esimerkkejä:

# Vérification globale
./blunderdb verify --db base.db

# Vérifier un match spécifique
./blunderdb verify --db base.db --match 1

# Comparer avec le fichier source
./blunderdb verify --db base.db --match 1 --mat original.mat

6.20. vacuum — Tietokannan tiivistäminen

Ottaa takaisin levytilan, jonka poistot (ottelut, turnaukset, siivoukset) ovat jättäneet: SQLite ei koskaan pienennä tiedostoa itsestään dataa poistettaessa, sitä on pyydettävä nimenomaisesti. Tämä on ainoa tapa käynnistää tiivistys — se ei tapahdu koskaan automaattisesti tietokantaa avattaessa, koska sen kustannus on suuressa tietokannassa arvaamaton.

./blunderdb vacuum --db <chemin>

Valitsimet:

  • --db — Tietokanta (pakollinen).

  • --format — Tulostusmuoto: text (oletus) tai json ({"size_before", "size_after", "reclaimed"}, tavuina).

Komento aloittaa suorituksella wal_checkpoint(TRUNCATE), jotta ennen tiivistystä näytetty koko on rehellinen, tarkistaa, että levyllä on jäljellä noin kaksi kertaa tiedoston nykyinen koko (SQLite rakentaa koko tietokannan uudelleen ennen siihen siirtymistä), suorittaa VACUUM-toiminnon ja sen jälkeen ANALYZE-toiminnon virittääkseen kyselysuunnittelijan käyttämät tilastot. Jos levytila ei riitä, komento kieltäytyy käynnistymästä selkeällä viestillä sen sijaan, että riskeeraisi keskeytyneen tiivistyksen.

Esimerkki:

./blunderdb vacuum --db base.db

# Compacting database...
#   Before: 128.4 MiB
#   After:  41.2 MiB
#   Reclaimed: 87.2 MiB

6.21. repair — Laske analyysisarakkeet uudelleen

Laskee jokaisen analyysin skalaarisarakkeet uudelleen itse analyysistä, jonka projektio ne vain ovat. Analyyseihin ei kosketa: uusiksi tehdään niistä johdetut arvot.

./blunderdb repair --db <chemin>

Valitsimet:

  • --db — Tietokanta (pakollinen).

  • --format — Tulostusmuoto: text (oletus) tai json ({"changes": [...]}).

Hyödyllinen sen jälkeen, kun tuodun analyysin lukutapaa on korjattu. Tapaus on jo sattunut: XG-tuoja kirjoittaa ”ei tuplausta” kahdella tavalla, ja jälkimmäinen tulkittiin oikeaksi tuplaukseksi — sarake kantoi silloin sellaisen tuplauksen virhettä, jota ei koskaan tapahtunut. Lukijan korjaaminen ei muuttanut mitään jo kirjoitetuille riveille; tämä komento tekee ne uudelleen.

Mikään ei käynnistä sitä automaattisesti, ja se on tarkoituksellista: kaikkien analyysisarakkeiden uudelleenkirjoittaminen pelkästä tietokannan avaamisesta ei ole jotain, mitä työkalun tulisi tehdä käyttäjänsä selän takana.

Esimerkki:

./blunderdb repair --db base.db

# 42 analyses repaired.

6.23. healthcheck — Taustaprosessin tarkistus

Kysyy käynnissä olevalta serve-taustaprosessilta (ks. Headless-tila (palvelin)), onko se valmis: yksi GET /readyz-pyyntö, paluukoodi 0, jos taustaprosessi vastaa 200 (tallennus tavoitettavissa, skeema odotetussa versiossa), muuten 1 — tallennus ei tavoitettavissa, vanhentunut skeema tai osoitteessa ei kuuntele mikään. Tietokantatiedostoa ei avata.

./blunderdb healthcheck [--addr hôte:port] [--timeout 2s]

Valitsimet:

  • --addr — Osoite, jota taustaprosessi kuuntelee (oletus BLUNDERDB_ADDR, muuten :8080). Osoite ilman isäntää (:8080) tai yleisisännällä (0.0.0.0, [::]) tarkistetaan loopback-liitännän kautta.

  • --timeout — Aika, jonka jälkeen tarkistus luovuttaa (oletuksena 2s).

Tämä on komento, jonka konttikuvan HEALTHCHECK suorittaa (distroless-kuva, ilman curl-ohjelmaa); myös cmd/serve-hakemistosta käännetty serve-binääri ymmärtää sen. Se sopii yhtä hyvin skriptiin tai systemd-yksikköön.

Esimerkki:

./blunderdb serve --db base.db --addr 127.0.0.1:8080 &
./blunderdb healthcheck --addr 127.0.0.1:8080 && echo "démon disponible"

6.24. completion — Shell-täydennys

Tulostaa vakiotulosteeseen täydennysskriptin alikomentojen nimille. Jokaiseen skriptiin sisällytetty komentoluettelo generoidaan samasta taulukosta, jota myös blunderdb help ja main.go:n reititys (handlers()) lukevat: uusi alikomento tarjotaan siis täydennyksessä heti, kun se on kytketty, eikä mitään tarvitse ylläpitää käsin.

./blunderdb completion <bash|zsh|fish>

Esimerkkejä:

# bash : charger pour la session en cours
source <(blunderdb completion bash)

# bash : installation système (Debian/Ubuntu/Arch)
blunderdb completion bash | sudo tee /etc/bash_completion.d/blunderdb > /dev/null

# zsh : installer dans un répertoire déjà sur $fpath
blunderdb completion zsh > "${fpath[1]}/_blunderdb"

# fish : charger pour la session en cours
blunderdb completion fish | source

Paketit asentavat tämän automaattisesti: .deb/.rpm (nfpm) ja AUR-paketti tuottavat kolme skriptiä paketoidusta binääristä käännöshetkellä, ja Homebrew-cask suorittaa blunderdb completion <shell> kerran asennuksen yhteydessä komennolla generate_completions_from_executable. Mitään ei tallenneta arkistoon, joten täydennys ei voi koskaan poiketa alikomentotaulukosta.

6.25. Työnkulkuesimerkkejä

6.25.1. Turnaushakemiston tuonti

# Créer une base dédiée au tournoi
./blunderdb create --db tournoi_paris.db --user "Jean" --description "Open de Paris 2025"

# Importer tous les matchs du répertoire
./blunderdb import --db tournoi_paris.db --type batch --dir ./matchs_open_paris/

# Vérifier le résultat
./blunderdb list --db tournoi_paris.db --type stats

6.25.2. Säännöllinen varmuuskopiointi

# Export complet pour sauvegarde
./blunderdb export --db production.db --type database --file sauvegarde-$(date +%Y%m%d).db

6.25.3. Virheiden analysointi

# Extraire les blunders dans une base séparée
./blunderdb search --db production.db --error-min 0.1 --export blunders.db

# Extraire les erreurs de videau
./blunderdb search --db production.db --decision cube --error-min 0.05 --export cube_errors.db

6.26. Paluukoodit

  • 0 — Onnistui.

  • 1 — Virhe.

Tämä tekee CLI:stä sopivan käytettäväksi skripteissä virheenkäsittelyn kanssa:

if ./blunderdb import --db base.db --type match --file match.xg; then
    echo "Import réussi"
else
    echo "Échec de l'import"
    exit 1
fi
