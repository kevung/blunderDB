Tuonti, vienti, siirto

create — Luo tietokanta

Luo uusi tietokantatiedosto valinnaisilla metatiedoilla.

./blunderdb create --db <path> [--user <name>] [--description <text>] [--force]

Valitsimet:

  • --db — Luotavan tietokantatiedoston polku (pakollinen).

  • --user — Tietokannan omistajan nimi.

  • --description — Tietokannan kuvaus.

  • --force — Korvaa tiedosto, jos se on jo olemassa.

  • --format — Tulostusmuoto: text (oletus) tai json (polku, versio, käyttäjä, kuvaus, luontipäivä).

.db-pääte lisätään automaattisesti, jos se puuttuu. Ylähakemistot luodaan tarvittaessa.

Esimerkki:

./blunderdb create --db mes_matchs.db --user "Jean" --description "Matchs de tournoi 2025"

import — Tuo tietoja

Tuo ottelu- tai asematiedostoja tietokantaan.

./blunderdb import --db <path> --type <type> [options]

Valitsimet:

  • --db — Tietokannan polku (pakollinen).

  • --type — Tuontityyppi: match, position tai batch (pakollinen).

  • --file — Tuotava tiedosto (tyypeille match ja position).

  • --dir — Tuotava hakemisto (tyypille batch).

  • --recursive — Selaa alihakemistot rekursiivisesti (oletus: kyllä).

  • --watch — Yhdessä --type batch-valitsimen kanssa: ei pysähdy, vaan tuo jokaisen ottelutiedoston heti kun se ilmestyy hakemistoon --dir (Ctrl-C lopettaa).

  • --watch-every — Kuinka usein --watch katsoo (oletus: 10s, alaraja 2s).

  • --resume — Valitsimen --type batch kanssa: jatkaa tämän numeroista erää (näytetään tuonnin alussa, tai batch_id JSON-muodossa). Tiedostot, joilla on sama polku, koko ja päivämäärä kuin sen lokissa, ohitetaan lukematta, ne joilla on sama sisältö luetaan mutta niitä ei analysoida; virheelliset tiedostot yritetään uudelleen.

  • --format — Tulostusmuoto: text (oletus) tai json.

  • --fail-on-error — Epäonnistuu, jos edes yhtä kohdetta (position tai batch) ei voitu tuoda, vaikka muut onnistuisivat.

  • --skip-duplicates — Ohittaa jo tietokannassa olevan ottelun ottamatta sen syvempiä analyyseja (opiskelumerkinnät tuodaan silti). Oletuksena kaksoiskappale korvaa kunkin tallennetun analyysin omallaan, kun se on aidosti syvempi, ja rivi kertoo sen: DUPLICATE (N analyses deepened).

Päätös, jonka analyysissä on arvo, joka ei ole äärellinen luku (NaN tai ääretön), tuodaan ilman tätä analyysiä, ja muu ottelu tuodaan tavalliseen tapaan; erän raportti kertoo niiden määrän (Decisions imported without their analysis).

Paluukoodi noudattaa neljää sääntöä:

  • mitään ei tunnistettu (jokainen tiedosto epäonnistui): virhe, oli --fail-on-error annettu tai ei;

  • pelkkiä kaksoiskappaleita (jokainen tiedosto oli jo tietokannassa): onnistuminen. Hakemisto, joka ajetaan uudelleen ilman uutta tiedostoa — skriptin tavallinen yö — päättyy koodiin 0, ja duplicates on ainoa nollasta poikkeava;

  • osittainen epäonnistuminen (osa kohteista tuotiin, osa hylättiin): virhe vain, jos --fail-on-error on annettu;

  • vähintään yksi uusi kohde tuotiin ilman --fail-on-error-valitsinta: onnistuminen, ja hylätyt tiedostot luetellaan taulukossa.

Kansion valvonta

--watch muuttaa hakemistotuonnin valvonnaksi: komento ei palaa, vaan tuo jokaisen ottelutiedoston, joka kansioon ilmestyy. Se on sovelluksen valvotun kansion käyttöliittymätön muoto.

# Importer ce que le dossier contient déjà, puis surveiller ce qui arrive
./blunderdb import --db base.db --type batch --dir ~/XG/Matches
./blunderdb import --db base.db --type batch --dir ~/XG/Matches --watch

Vain ilmestyvät tiedostot tuodaan: se mitä kansiossa on käynnistyshetkellä kirjataan tunnetuksi ja jätetään rauhaan — valvonnan osoittaminen neljän vuoden otteluihin ei saa tuoda niitä kaikkia. Yllä olevat kaksi komentoa siis täydentävät toisiaan juuri niin kuin toivoisi.

Tiedosto tuodaan vasta kun sen koko on vakiintunut, eli se on nähty kahdesti muuttumattomana: ottelu, jota toinen ohjelma kirjoittaa, kasvaa katsomasta toiseen, ja puoliksi kirjoitettuna tuotuna siitä tulisi syntaksivirhe, jolle kukaan ei voi mitään. Kansiota ei käydä läpi rekursiivisesti. Lukukelvottomaksi muuttunut verkkojako ei pysäytä valvontaa, eikä sen sisältö käy uudesta sen palatessa.

Kansioon ilmestyvä .db-tietokanta yhdistetään samoin kuin komennolla import --type database: näin toisen koneen inkrementaalinen vienti saapuu (katso Kahden koneen synkronointi).

Ctrl-C pysäyttää tiedostojen välissä, ei koskaan kesken yhden: tuotava tiedosto viedään loppuun ja sen raportti tulostetaan ennen kuin komento palaa.

Ottelun tuonti

Tuetut muodot: eXtreme Gammon (.xg, .xgp), GNUbg (.sgf), Jellyfish (.mat, .txt), BGBlitz (.bgf) ja HedgeHog (.ogxm).

./blunderdb import --db base.db --type match --file match.xg

# Successfully imported match (ID: 1)
#
# Match Details:
#   Players: Kévin Unger vs Maxence Job
#   Event: HSBT Paris 2023
#   Match Length: 7
#   Games: 7

--format json antaa samat kentät yhtenä dokumenttina:

{
  "type": "match",
  "match_id": 1,
  "player1": "Kévin Unger",
  "player2": "Maxence Job",
  "event": "HSBT Paris 2023",
  "location": "Paris, Fédération Française de Bridge",
  "match_length": 7,
  "games": 7
}

Asemien tuonti

Tuo asemia tekstitiedostosta, yksi JSON-asema riviä kohti. Tämä on täsmälleen se, mitä export --type positions kirjoittaa: komennot vastaavat toisiaan, ja vienti tuodaan takaisin sellaisenaan ilman mitään muokkausta.

./blunderdb import --db base.db --type position --file positions.txt

# Successfully imported 4 positions

Yksi rivi sellaisena kuin export sen tuottaa — lauta vie siitä valtaosan, kaksikymmentäkuusi pistettä ja niiden perässä ulos kannetut nappulat:

{"id":1,"board":{"points":[{"checkers":0,"color":0},{"checkers":1,"color":1},…],"bearoff":[0,0]},"cube":{"owner":-1,"value":0},"dice":[0,0],"score":[7,7],"player_on_roll":0,"decision_type":1,"has_jacoby":0,"has_beaver":0,"individually_imported":true,"flagged":false}

Analyysit ja kommentit eivät kulje tässä muodossa: se kantaa aseman, ei mitään muuta. Kokonaisen kirjaston siirtämiseen tarvitaan export --type database.

Tietokannan tuonti

Yhdistää toisen blunderDB-tietokannan (.db) --db:n tietokantaan työpöytäsovelluksen yhdistämisen ja palvelintilan imports.db:n sääntöjen mukaan (Tietokannan yhdistäminen): positiot, ottelut, turnaukset, kokoelmat, oppitunnit, Anki-pakat, luonnokset ja aliakset sekä turnausten Johto ja niiden Kohtaaminen. Saman tiedoston tuominen kahdesti ei muuta mitään. Tekstitulosteessa lasketaan lisätyt ja jo olemassa olleet ottelut sekä takaisin luetut Johdot ja Kohtaamiset, ja nimetään jäädytetyt tai käsin tehdylle listalle jätetyt elävät kokoelmat ja ne perheet, joita tietokanta on liian vanha sisältämään.

./blunderdb import --db base.db --type database --file club.db
./blunderdb import --db base.db --type database --file club.db --format json

Erätuonti

Tuo kaikki hakemiston ottelutiedostot yhdellä toimenpiteellä. Tämä on tehokkain tapa tuoda suuri määrä otteluita.

./blunderdb import --db base.db --type batch --dir ./matchs/
./blunderdb import --db base.db --type batch --dir ./matchs/ --recursive=false
./blunderdb import --db base.db --type batch --dir ./matchs/ --format json --fail-on-error

Yhteenvetotaulukko näyttää jokaisen tiedoston kohdalla, onnistuiko tuonti (✓), epäonnistuiko (✗) vai oliko kyseessä kaksoiskappale (⊘). Kaksoiskappaletta ei lasketa epäonnistumiseksi, ja erä, jossa on pelkkiä kaksoiskappaleita, on onnistuminen (ks. säännöt yllä).

Jokainen erän tiedosto kirjataan lokiin (polku, koko, päivämäärä, SHA-256, saatu ottelu tai virhe). Erän numero näytetään alussa; jos tuonti keskeytyy, --resume jatkaa sitä analysoimatta uudelleen jo päätettyä. Valitsimella --format json lopullinen olio sisältää kentän batch_id ja taulukon journal.

./blunderdb import --db base.db --type batch --dir ./matchs/ --resume 12

Batch importing from: ./matchs/ (recursive: true)

--format json antaa samat tiedot skriptille sopivassa muodossa: yksi olio tiedostoa kohti kentässä files, sitten kokonaissummat. Rauhallisen yön jäljiltä duplicates on ainoa nollasta poikkeava, failed on nolla ja paluukoodi on 0; vain erä, jossa mitään ei tunnistettu, päättyy virheeseen.

export — Vie tietoja

Vie tietokannan sisältö tiedostoihin.

./blunderdb export --db <path> --type <type> --file <output> [options]

Valitsimet:

  • --db — Lähdetietokanta (pakollinen).

  • --type — Vientityyppi: database, positions, matches tai mat (yhden tai useamman ottelun vienti Jellyfish .mat -transkriptioon) (pakollinen).

  • --file — Tulostiedosto (pakollinen, paitsi --type mat -vaihtoehdolle yhdessä --dir kanssa).

  • --dir — Erävientinä tehtävän .mat-viennin tulostushakemisto (useita otteluita, yksi tiedosto ottelua kohden; ilman --match-ids viedään kaikki ottelut).

  • --analysis — Sisällytä analyysit (oletus: kyllä).

  • --comments — Sisällytä kommentit (oletus: kyllä).

  • --filters — Sisällytä suodatinkirjasto (oletus: kyllä).

  • --played-moves — Sisällytä pelatut siirrot (oletus: kyllä).

  • --matches — Sisällytä ottelut (oletus: kyllä).

  • --transcriptions — Sisällytä kunkin viedyn ottelun litterointiluonnos (oletus: kyllä).

  • --aliases — Sisällytä pelaajien ja tapahtumien aliakset, joita viedyt ottelut kirjoittavat, jotta pelaajien yhdistäminen seuraa niitä (oletus: kyllä).

  • --collections — Sisällytä kokoelmat (oletus: kyllä).

  • --tournaments — Sisällytä turnaukset (oletus: kyllä).

  • --decks — Sisällytä Anki-pakat (oletus: kyllä).

  • --lessons — Sisällytä oppitunnit sekä kokoelmat ja asemat, jotka niiden vaiheet näyttävät (oletus: kyllä).

  • --anki-history — Vie mukana viedyn pakan kertaushistoria: kunkin kortin tila ja sen kertausten loki (oletus: kyllä).

  • --collection-ids — Vietävien kokoelmien tunnukset (pilkulla eroteltuna, tyhjä = kaikki).

  • --match-ids — Vietävien otteluiden tunnukset (pilkulla eroteltuna, tyhjä = kaikki).

  • --tournament-ids — Vietävien turnausten tunnukset (pilkulla eroteltuna, tyhjä = kaikki).

  • --deck-ids — Asemineen vietävien Anki-pakkojen tunnukset (pilkulla eroteltuna, tyhjä = kaikki).

  • --lesson-ids — Viedyistä oppitunneista tunnisteet (pilkuilla erotettuina, tyhjä = kaikki).

  • --password — Kääri tuloksen salattuun säiliöön (.dbx).

  • --watermark — Kirjoittaa allekirjoitetun alkuperäilmoituksen vietyyn tiedostoon (katso Tietokannan jakaminen: alkuperä ja salasana).

  • --watermark-note — Vesileimaan liitettävä vapaa teksti (käyttöehdot, yhteystieto); käytetään yhdessä --watermark-valitsimen kanssa.

  • --format — Tulostusmuoto: text (oletus) tai json (vientiä kokoava asiakirja: polku, koko tavuina, määrät).

  • --incremental — Valitsimen --type database kanssa: vie vain sen, mikä on tullut kirjastoon samaan kansioon tehdyn edellisen inkrementaalisen viennin jälkeen, ja siirtää sitten tätä merkkiä eteenpäin viedyssä tietokannassa. --file voi tällöin olla kansio, johon luodaan tiedosto sync-<machine>-<date>.db (katso Kahden koneen synkronointi). Jo käytössä oleva tiedostonimi hylätään: paikalla oleva tiedosto sisältää edellisen muutoserän, jota toinen kone ei ehkä ole vielä yhdistänyt.

  • --sync-cursor — Valitsimen --incremental kanssa: luetun ja eteenpäin siirretyn merkin nimi kohdekansion sijaan.

  • --plan — Valitsimilla --type database tai matches: laskee perhe kerrallaan, mitä vienti kirjoittaisi, kirjoittamatta tiedostoa (--file on tällöin valinnainen). Luvut ovat samat, jotka vienti raportoi jälkeenpäin; jäädytettyinä lähtevät elävät kokoelmat ja „recherche“-pakat, joiden lähde menettäisi osan, nimetään. Muun tyypin kanssa valinta hylätään.

  • --plan-ids <famille> — Kuten --plan, mutta palauttaa sivun luvun takana olevia tunnisteita: positions, comments (ne asemat, jotka niitä kantavat), matches, tournaments, directions (turnaukset, joiden johto viedään mukana), rencontres (tapahtumat, jotka viedään jonkin turnauksensa mukana), collections, lessons, ankiDecks, transcriptions tai filters. --offset ja --limit valitsevat sivun (enintään 1000 tunnistetta).

--type database vie koko kirjaston, kuten palvelimen vienti ja vientiikkuna, kun näytetty luettelo on kirjasto: asemat, ottelut, turnaukset (johtoineen: loki, parit, pöydät ja viedyn ottelun liittäminen; niiden tapahtuma viedään heti, kun yksi sen turnauksista viedään), kokoelmat, oppitunnit, Anki-pakat, litteroinnit, aliakset ja suodattimet. Arvoon false asetettu valitsin poistaa oman ryhmänsä (--collections=false); tunnusluettelo rajaa ryhmän näihin kohteisiin ja sisällyttää sen. Litterointiluonnos viedään sen ottelun mukana, jonka se tuotti; luonnos, josta ei vielä ole syntynyt ottelua, viedään vain, jos kaikki ottelut viedään. --type matches ottaa mukaan myös kunkin ottelun luonnoksen.

Esimerkkejä:

./blunderdb export --db base.db --type database --file sauvegarde.db
./blunderdb export --db base.db --type positions --file positions.txt
./blunderdb export --db base.db --type matches --file selection.db --match-ids 1,3,5

# .mat : un match, puis plusieurs (ou tous) dans un répertoire
./blunderdb export --db base.db --type mat --match-ids 5 --file match5.mat
./blunderdb export --db base.db --type mat --match-ids 5,9,12 --dir sorties/
./blunderdb export --db base.db --type mat --dir sorties/

# Ce qui est nouveau depuis le dernier export vers ce dossier, pour une
# autre machine qui le surveille
./blunderdb export --db base.db --type database --incremental --file ~/Sync/vers-portable/

# .dbx : filigrané et protégé par mot de passe
./blunderdb export --db cours.db --type database --file cours-diffusion.dbx \
    --watermark "Cours de Jean Dupont — 12 mars 2026" \
    --watermark-note "Merci de ne pas rediffuser." \
    --password secret

Vesileima allekirjoitetaan paikallisella liikkeeseenlaskijan identiteetillä (katso identity-komento alla): sitä ei voi väärentää, mutta sen voi poistaa — tiedosto pysyy tavallisena SQLite-tietokantana. Se ei suojaa mitään, se vain kertoo, mistä tiedosto on peräisin. Salasana suojaa tiedoston kuljetusta (kadonnut kopio, vahingossa lähetetty liite), ei itse tietokantaa: kuka tahansa salasanan saanut voi avata sen. blunderDB ei koskaan kirjaa mitään vastaanottajan puolelle (ei rekisteriä, ei lokia) — katso ADR-0007.

transfer — Kopiointi kirjastosta toiseen

Kopioi osan kirjastosta toiseen ilman käsiteltävää välitiedostoa. Valinta on sama kuin komennossa export --type database; yhdistäminen on sama kuin .db-tietokannan tuonnissa: asemaa, jonka kohde jo omistaa, ei lisätä toiseen kertaan (se tunnistetaan sen tiivisteestä), sen analyysit ja kommentit yhdistetään, eikä jo olemassa olevaa ottelua, kokoelmaa, oppituntia tai Anki-pakkaa kahdenneta. A:sta B:hen ja sitten B:stä A:han kopioiminen ei siis luo kaksoiskappaleita.

./blunderdb transfer --from <source.db> --to <destination.db> [options]

Valitsimet:

  • --from — Lähdekirjasto (pakollinen; sen on oltava olemassa ja sen skeeman on vastattava tämän blunderDB-version skeemaa). Vanhempi kirjasto hylätään, koska sen päivittäminen tarkoittaisi siihen kirjoittamista: avaa se kerran blunderDB:ssä. Myös uudempi kirjasto hylätään: päivitä blunderDB.

  • --to — Kohdekirjasto (pakollinen; luodaan, jos sitä ei ole). Se ei voi olla lähde.

  • --analysis, --comments, --played-moves, --matches, --transcriptions, --aliases, --collections, --tournaments, --decks, --lessons — Kuten komennossa export: arvoon false asetettu valinta poistaa oman ryhmänsä (oletus: kyllä kaikille).

  • --collection-ids, --match-ids, --tournament-ids, --deck-ids, --lesson-ids — Lähteen ID-luettelo rajaa oman ryhmänsä näihin kohteisiin ja sisällyttää sen. ID, jota lähde ei sisällä, on virhe, eikä mitään kopioida.

  • --format — text (oletus) tai json (mitä lähteestä luettiin ja mitä kohde siitä otti).

Mitkä asemat siirtyvät. Ilman ID-luetteloa kaikki lähteen asemat siirtyvät, järjestetyt tai ei. Heti kun ID-luettelo annetaan, siirtyvät vain ne asemat, jotka valitut ryhmät tavoittavat (kokoelman jäsenet, ottelun siirrot, oppitunnin vaiheet, pakan kortit) analyyseineen ja kommentteineen. Kokoelma siirtyy aina jäsenineen. --match-ids-valitsimella nimetty ottelu tuo mukanaan turnauksensa tiedot (nimi, päivämäärä, paikka), mutta ei saman turnauksen muita otteluita; valitsimella --tournaments=false se saapuu ilman turnausta.

Mitään ei kirjoiteta, joka kertoisi, mistä kopio tulee: ei vesileimaa, ei tuontilokia, ei lähteen metatietoja; kohde säilyttää omansa, eikä lähde saa mitään. Suodatinkirjastoa ja Anki-pakkojen kertaushistoriaa ei kopioida: pakka saapuu ilman historiaa, ja jo olemassa oleva samanniminen pakka säilyttää omansa.

Esimerkkejä:

# Toute une bibliothèque dans une autre
./blunderdb transfer --from club.db --to perso.db

# Deux collections et leurs positions, rien d'autre
./blunderdb transfer --from club.db --to perso.db --collection-ids 3,7 \
    --matches=false --tournaments=false --lessons=false --decks=false

# Un match, ses positions et son tournoi, en retour
./blunderdb transfer --from perso.db --to club.db --match-ids 12 \
    --collections=false --lessons=false --decks=false

Palvelin tarjoaa saman siirron kahden tenantin välillä, vastaanottavan tenantin vetämänä (ks. Kopion vetäminen luetusta tenantista).

identity — Liikkeeseenlaskijan identiteetti

Näyttää tai siirtää liikkeeseenlaskijan identiteettisi: Ed25519-avaimen, joka allekirjoittaa jokaisen vesileiman. Se syntyy itsestään ensimmäisen vesileiman yhteydessä; mitään ei tarvitse asettaa. Se kuuluu henkilölle, ei tietokannalle: kaikki merkitsemäsi kantaa yhtä ja samaa julkista sormenjälkeä.

./blunderdb identity
./blunderdb identity --name "Jean Dupont"
./blunderdb identity --export jean.bdbid --passphrase pw
./blunderdb identity --import jean.bdbid --passphrase pw

Valitsimet:

  • --name — Vaihtaa identiteetin näyttönimen.

  • --export — Vie identiteetin .bdbid-tiedostoon.

  • --import — Tuo identiteetin .bdbid-tiedostosta.

  • --passphrase — Valinnainen tunnuslause, joka suojaa viedyn/tuodun tiedoston (paikallinen identiteetti jätetään tarkoituksella suojaamatta).

  • --format — Tulostusmuoto: text (oletus) tai json (nimi, sormenjälki, tallennuspolku).

Viety tiedosto antaa kenelle tahansa sen haltijalle mahdollisuuden allekirjoittaa sinun nimissäsi — älä jaa sitä. Uudelleennimeäminen muuttaa vain nimilapun: jo merkityt tiedostot säilyttävät nimen, jolla ne sinetöitiin, ja ne todentuvat edelleen.

open — Suojatun tiedoston avaaminen

Muuntaa salasanalla suojatun tiedoston (.dbx) tavalliseksi tietokannaksi. Salasanaa kysytään vain kerran; sen jälkeen kyseessä on tavallinen tiedosto.

./blunderdb open --db cours.dbx --password secret
./blunderdb open --db cours.dbx --password secret --file ./mon-cours.db

Valitsimet:

  • --db — Avattava .dbx-tiedosto (pakollinen).

  • --password — Säiliön salasana (pakollinen).

  • --file — Tavallisen tietokannan tulostuspolku (oletus: sama nimi, pääte .db).

Mitä salasana suojaa: tiedoston kuljetusta — latauskansioon unohtunutta kopiota, vahingossa lähetettyä liitettä. Ei tietokantaa: kuka tahansa salasanan saanut voi avata sen. Säiliön otsake on selkokielinen, joten blunderdb info lukee suojatun tiedoston alkuperän ilman salasanaa.
