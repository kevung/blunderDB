Descarga e instalación

blunderDB es un único ejecutable que no requiere ninguna instalación.

La última versión de blunderDB está disponible bajo licencia MIT:

  • para Windows: https://github.com/kevung/blunderDB/releases/latest/download/blunderDB-windows-0.36.0.exe

    En el primer arranque, Windows muestra una advertencia de SmartScreen («Windows protegió su equipo»). Esto es previsible: el ejecutable no está firmado digitalmente. Consulte qué hacer.

  • para Linux: https://github.com/kevung/blunderDB/releases/latest/download/blunderDB-linux-0.36.0

  • para Mac: https://github.com/kevung/blunderDB/releases/latest/download/blunderDB-macos-0.36.0.zip

    macOS emite una advertencia comparable, por la misma razón: consulte qué hacer.

Para una consulta sin conexión, también puede descargar esta documentación en formato PDF: https://github.com/kevung/blunderDB/releases/latest/download/blunderDB-0.36.0-es.pdf

Nota

blunderDB utiliza Webview2 para renderizar la interfaz gráfica. Es muy probable que Webview2 ya esté presente de forma nativa en su sistema operativo. Si no es así, la primera ejecución de blunderDB propondrá descargarlo e instalarlo. No se espera ninguna acción por parte del usuario.

Nota

Siempre en el primer arranque, blunderDB calcula en segundo plano las dos tablas de bearoff que utiliza el panel Eval: unos seis segundos en un núcleo, sin pedir nada, y la aplicación se usa con normalidad durante ese tiempo. Véase la pestaña Bearoff de la configuración.

Los archivos amd64 y x86_64 son para un procesador Intel o AMD, es decir, casi todos los ordenadores de escritorio. Los archivos arm64 y aarch64 son para un procesador ARM de 64 bits: Raspberry Pi 4 y 5, Mac con chip Apple ejecutando Linux, servidores ARM. En caso de duda, uname -m responde: x86_64 o aarch64. El paquete AUR blunderdb-bin cubre ambos y elige solo.

Los demás archivos de la página son los binarios Linux sin empaquetar (véase más abajo), los manifiestos winget y Homebrew (véase Manifiestos winget y Homebrew), la documentación en PDF en nueve idiomas y las huellas .sha256.

Verificar una descarga

Las dos verificaciones descritas aquí son opcionales y están destinadas a usuarios avanzados: se realizan en línea de comandos y no forman parte de la instalación. Omitir esta sección no impide nada.

Cada archivo publicado va acompañado de su huella SHA-256, en un archivo del mismo nombre seguido de .sha256. Descargue ambos en la misma carpeta y compruebe que el archivo recibido es el que se publicó:

sha256sum -c blunderdb_x.y.z_amd64.deb.sha256        # Linux
shasum -a 256 -c blunderDB-macos-x.y.z.zip.sha256   # macOS

Get-FileHash .\blunderDB-windows-x.y.z.exe -Algorithm SHA256   # Windows

En Linux y macOS el comando muestra OK; en Windows, compare el valor mostrado con el contenido del archivo .sha256. Esta comprobación es la garantía disponible a falta de firma de código (véase Anexo Windows: qué hacer si Windows bloquea el inicio y Anexo Mac: posible bloqueo de blunderDB).

Cada archivo publicado va acompañado también de una atestación de procedencia (SLSA, mediante Sigstore), que demuestra que fue efectivamente producido por la ejecución de compilación oficial del repositorio en GitHub, sin necesidad de gestionar ninguna clave:

gh attestation verify blunderdb_x.y.z_amd64.deb --repo kevung/blunderDB

Instalación en Linux

Se ofrecen varios formatos para Linux. Los paquetes y archivos siguientes hacen que blunderDB sea ejecutable automáticamente: a diferencia del binario sin procesar descargado a través de un navegador, evitan tener que ejecutar chmod +x en cada descarga o actualización. También crean una entrada en el menú de aplicaciones.

Nota

Los paquetes .deb y .rpm asocian la extensión .dbx (una base exportada con contraseña, véase Distribuir una base de datos: origen y contraseña) a blunderDB: hacer doble clic en un archivo .dbx recibido de un tercero lo abre directamente. La extensión .db de una base ordinaria no se asocia deliberadamente — es demasiado genérica y compartida con otros programas — pero sigue abriéndose normalmente desde el menú Abrir de blunderDB.

Paquetes nativos (.deb / .rpm)

Método recomendado en Debian, Ubuntu y Linux Mint (.deb), así como en Fedora y openSUSE (.rpm). El gestor de paquetes instala automáticamente la dependencia webkit2gtk adecuada. Reemplace x.y.z por la versión descargada:

sudo apt install ./blunderdb_x.y.z_amd64.deb     # Debian / Ubuntu / Mint
sudo dnf install ./blunderdb-x.y.z.x86_64.rpm    # Fedora / openSUSE

Arch Linux (AUR)

El paquete blunderdb-bin está disponible en el AUR y se actualiza automáticamente mediante los asistentes de AUR:

yay -S blunderdb-bin      # ou : paru -S blunderdb-bin

Flatpak

El bundle blunderDB-x.y.z.flatpak funciona en cualquier distribución donde Flatpak esté instalado. Se apoya en el entorno GNOME 47, que Flatpak descarga de Flathub si falta:

flatpak install ./blunderDB-x.y.z.flatpak
flatpak run io.github.kevung.blunderDB

El bundle se instala desde el archivo descargado y se actualiza instalando el de la versión siguiente. La aplicación tiene acceso a la carpeta personal para abrir y guardar bases. La línea de comandos (Interfaz de línea de comandos (CLI)) se obtiene con flatpak run io.github.kevung.blunderDB <comando>.

Archivo .tar.gz

Para otras distribuciones. La extracción de un archivo conserva el bit de ejecución, por lo que no es necesario chmod:

tar xzf blunderDB-linux-webkit2gtk-4.1-x.y.z.tar.gz
cd blunderDB-linux-webkit2gtk-4.1-x.y.z
./blunderDB

Nota

El ejecutable del archivo se llama blunderDB, con mayúsculas. Los paquetes .deb, .rpm, AUR y Flatpak instalan además el enlace blunderdb en minúsculas, el nombre que usa la documentación de la línea de comandos (Interfaz de línea de comandos (CLI)); el archivo contiene el mismo enlace junto al ejecutable. Para tenerlo en su PATH: ln -s "$PWD/blunderDB" ~/.local/bin/blunderdb.

Binario sin procesar (método avanzado)

El binario sin procesar https://github.com/kevung/blunderDB/releases/latest/download/blunderDB-linux-0.36.0 sigue estando disponible. Como un navegador elimina el bit de ejecución al descargar, debe restablecerlo antes de la primera ejecución:

chmod +x ./blunderDB-linux-x.y.z

Nota

Se publican dos variantes de Linux según la versión de la biblioteca webkit2gtk. Si obtiene el error libwebkit2gtk-4.0.so.37: cannot open shared object file, su distribución utiliza webkit2gtk-4.1: utilice el paquete .deb/.rpm, el paquete AUR o descargue la versión dedicada https://github.com/kevung/blunderDB/releases/latest/download/blunderDB-linux-webkit2gtk-4.1-0.36.0. Los paquetes nativos seleccionan la dependencia correcta automáticamente.

Imagen Docker (modo servidor)

El modo servidor (Modo headless (servidor)) no necesita la aplicación de escritorio: cada versión publica la imagen ghcr.io/kevung/blunderdb-serve en el registro de GitHub, para linux/amd64 y linux/arm64, bajo la etiqueta de la versión y bajo latest:

docker pull ghcr.io/kevung/blunderdb-serve:x.y.z

El arranque, la configuración y la advertencia sobre el proxy de autenticación se describen en Imagen publicada.

Manifiestos winget y Homebrew

Cada release proporciona en la página de releases un manifiesto winget (blunderDB-winget-manifests-x.y.z.zip) y una fórmula Homebrew (blunderdb-x.y.z.rb), para quien desee instalar blunderDB mediante estos gestores desde un archivo local. Ninguno de los dos figura en los repositorios públicos de winget ni de Homebrew. Ninguno de los dos cambia la naturaleza del ejecutable: sigue sin firmar, y las advertencias descritas más abajo se aplican tal cual.
