8. Preguntas frecuentes (FAQ)

8.1. ¿Cuál es la utilidad de blunderDB?

blunderDB permite constituir una base de datos personalizada de posiciones. Su fuerza reside en no presuponer ninguna clasificación a priori. El usuario tiene así la libertad de interrogar las posiciones con gran flexibilidad combinando a su gusto diferentes criterios (carrera, estructura, cubo, marcador, fichas rezagadas, fichas en la zona, probabilidades de ganar/gammon/backgammon, …).

Otro uso práctico de blunderDB es la creación de catálogos de posiciones de referencia. Con la posibilidad de etiquetar posiciones, el usuario puede reunir todas sus posiciones de referencia de manera estructurada en un único archivo. Deseo que blunderDB facilite el intercambio de posiciones entre jugadores.

8.2. ¿Qué motivó la creación de blunderDB?

Tenía la costumbre de guardar en distintas carpetas posiciones interesantes o blunders. Sin embargo, encontraba dificultades para recuperar posiciones según criterios no previstos inicialmente por mi elección de categorías temáticas. Por ejemplo, si las posiciones se habían clasificado según el tipo de juego (carrera, holding game, blitz, backgame, …), ¿cómo recuperar todas las posiciones a un marcador determinado? ¿o a un nivel de cubo dado? Por último, algunas posiciones antiguas tendían a caer en el olvido. Quería una herramienta que agregara todas mis posiciones y que no presupusiera a priori categorías temáticas, para después poder hacer preguntas a la base de datos. Con este enfoque flexible, se pueden añadir nuevos filtros sin romper la organización de las posiciones. Este tipo de software es bastante habitual en el ajedrez, como ChessBase.

8.3. ¿Cómo guardar el estado de la base de datos actual?

La base de datos se actualiza inmediatamente tras la validación de la consulta. No es necesaria ninguna operación de guardado explícita.

8.4. ¿Debo crear distintas bases de datos para distintas categorías de posiciones?

Salvo por razones bien identificadas, es esencial no repartir las posiciones en bases de datos separadas, con el riesgo de no poder relacionarlas en búsquedas futuras. La filosofía de blunderDB consiste en no presuponer categorías de posiciones a priori y permitir al usuario interrogarlas de manera flexible. Cuando las posiciones se han encontrado en condiciones particulares o por razones específicas, puede ser conveniente guardarlas en bases de datos distintas. Por ejemplo, se pueden constituir bases de datos de posiciones distintas para:

  • las posiciones de referencia,

  • los blunders en torneos presenciales,

  • los blunders en línea.

8.5. ¿Cómo fusionar varias bases de datos?

Si tiene varias bases de datos de blunderDB que desea fusionar, utilice la función «Import Database»:

  1. Abra la base de datos principal (la que recibirá las posiciones importadas)

  2. Haga clic en el botón «Import Database» de la barra de herramientas

  3. Seleccione la base de datos que desea importar

  4. blunderDB fusionará automáticamente las posiciones

Durante la fusión, blunderDB evita los duplicados y combina de forma inteligente los análisis y comentarios. Las posiciones idénticas no se duplicarán, pero sus análisis y comentarios se combinarán.

Nota

Se recomienda hacer una copia de seguridad de su base de datos principal antes de importar otra base de datos.

8.6. ¿Qué formatos de archivos de match son compatibles?

blunderDB es compatible con los siguientes formatos de match:

  • eXtreme Gammon (XG): archivos .xg, con análisis completo de jugadas, decisiones de cubo, jugadas realizadas y soporte multimotor. Archivos .xgp para importar posiciones individuales con análisis.

  • GNUbg: archivos .sgf (Smart Game Format), con análisis.

  • Jellyfish: archivos .mat y .txt.

  • BGBlitz: archivos .bgf y posiciones en texto.

La importación puede realizarse mediante un archivo único, selección múltiple, carpeta recursiva, pegado desde el portapapeles o arrastrar y soltar.

blunderDB detecta automáticamente los duplicados e impide la importación de un match ya presente en la base de datos.

8.7. ¿Necesito eXtreme Gammon para usar blunderDB?

No. blunderDB también lee archivos de GNUbg, BGBlitz y Jellyfish, y su evaluador integrado (gammonNet) analiza cualquier posición sin depender de un software de terceros — ver «¿Qué vale el evaluador integrado?» más abajo. Sin embargo, una importación de XG aporta el análisis más completo (jugadas, decisiones de cubo, marcas, suerte de la tirada): es el formato más ricamente explotado por las estadísticas.

8.8. ¿Qué es una colección?

Una colección es una agrupación personalizada de posiciones. A diferencia de una búsqueda por filtros, que es dinámica, una colección es un conjunto fijo de posiciones elegidas manualmente por el usuario. Las colecciones permiten, por ejemplo, agrupar posiciones de referencia sobre una temática particular.

8.9. ¿Qué es el EPC?

El EPC (Effective Pip Count) es una medida más precisa que el simple pip count para evaluar las posiciones de bearoff. El panel Eval de blunderDB utiliza la base de datos de bearoff de 6 puntos de GNUbg y calcula en tiempo real el EPC, el número medio de tiradas, la desviación típica, el pip count y el wastage.

En las posiciones de bearoff puro, el panel muestra también la probabilidad de victoria del jugador al tiro y, cuando la posición está cubierta por una base two-sided (base integrada hasta 6 fichas por jugador, base descargable hasta 11), el veredicto de cubo money exacto. Fuera de este dominio, la probabilidad se estima con su margen de error y el veredicto, deliberadamente, no se muestra. Véase la sección « Metodología e hipótesis del panel Eval » del manual para el detalle de las hipótesis.

8.10. ¿Qué vale el evaluador integrado (gammonNet)?

gammonNet es una red neuronal entrenada por un tercero (ver Créditos), portada a Go y compilada en blunderDB: ningún software externo, ninguna conexión de red. Desempeña el papel de XG o de GNUbg para las posiciones no importadas — búsqueda a 0 o 2 tiradas de profundidad, decisión de cubo según Janowski y la tabla de equidad de partida de blunderDB, respetando el marcador. No es ni el único ni necesariamente el mejor motor del mercado: es el que funciona sin conexión, sin cuenta ni suscripción, sobre la posición que está mirando. Nada impide además importar los análisis de XG o de GNUbg cuando existen — las dos fuentes conviven, y una columna indica el origen de cada análisis. Ver la sección «Panel Eval» y «Metodología e hipótesis del panel Eval» del manual.

8.11. ¿Cuál es la diferencia entre el PR y el Snowie Error Rate?

El PR (Performance Rating) es la media de los errores de equidad (normalizada, en milésimas de punto) sobre el conjunto de las decisiones contabilizadas; cuanto más bajo, mejor se juega. El Snowie Error Rate expresa esa misma media en función del número de jugadas en lugar del número de decisiones — una partida más larga no empeora por tanto mecánicamente el SER. blunderDB muestra ambos en el panel Stats, alineados con las convenciones de eXtreme Gammon y de GNUbg (ver Anexo: Modelo de estadísticas — alineación XG / gnuBG / blunderDB para el detalle de las reglas de recuento).

8.12. ¿Dispone blunderDB de una interfaz de línea de comandos?

Sí, blunderDB dispone de una interfaz de línea de comandos (CLI) que permite realizar, sin interfaz gráfica, operaciones como la creación de bases de datos, la importación de matchs, la exportación, la búsqueda de posiciones, la visualización de estadísticas, etc. Consulte la documentación de la CLI para más detalles.

8.13. ¿Ofrece blunderDB un modo servidor?

Sí, un modo «headless» opcional: el mismo binario, lanzado con serve, expone el motor de blunderDB en HTTP + JSON detrás de un proxy inverso que autentica (blunderDB en sí no realiza ninguna autenticación). Puede apoyarse en SQLite o en PostgreSQL multiusuario, y sirve por ejemplo para consultar o importar partidas desde un navegador, integrar blunderDB en otra herramienta, o compartir una base de datos entre varios jugadores. El uso normal sigue siendo la aplicación de escritorio; ver Modo headless (servidor) para los detalles (incluida la imagen Docker lista para usar) y el tutorial «Desplegar el modo servidor detrás de un proxy» de la guía del usuario.

8.14. ¿Puedo modificar, copiar y compartir blunderDB?

Sí, por supuesto (¡e incluso se anima a ello!). blunderDB está bajo licencia MIT.

8.15. ¿Dónde se almacenan mis datos?

En su disco, en el archivo .db que eligió al crear la base: ninguna cuenta, ningún servidor, ninguna sincronización por defecto. La aplicación de escritorio abre ese archivo directamente; solo el modo servidor opcional (ver más abajo) hace funcionar blunderDB a distancia, y en ese caso es usted quien aloja ese servidor.

8.16. ¿Puedo compartir una base de datos con otro jugador?

Sí: una base de datos de blunderDB es un simple archivo, basta con copiarlo o enviarlo. Para difundir una base a un tercero, dos mecanismos opcionales, elegidos en el momento de la exportación, convierten esto en una difusión controlada en lugar de una simple copia: una marca de agua de origen firma el archivo con su identidad de emisor (infalsificable, legible en el panel Metadatos o mediante blunderdb info, sin registrar nunca nada del lado del destinatario), y una protección con contraseña produce un archivo .dbx cifrado. Ver Distribuir una base de datos: origen y contraseña en el manual.

8.17. ¿Qué formato de datos utiliza blunderDB?

La base de datos es un simple archivo SQLite. En ausencia de blunderDB, puede abrirse con cualquier editor de archivos SQLite.

8.18. ¿Cuáles fueron los principios de diseño de blunderDB?

Quería una interfaz accesible, pero pensada ante todo para un uso avanzado y sostenido, en el que se encadenan las posiciones y las búsquedas. La línea de comandos, que se abre pulsando la barra ESPACIADORA, y los atajos de teclado sirven a ese uso, sin ser un paso obligado.

Quería además que blunderDB fuera ligero, autónomo, sin instalación y disponible para distintas plataformas, de ahí mi elección del lenguaje Go y de la biblioteca Svelte. Para la serialización de la base de datos, el formato de archivo debía ser multiplataforma y adecuado para contener una base de datos. El formato de archivo sqlite parecía la opción idónea.

También quería que una base siguiera siendo un simple archivo, que se pueda copiar, guardar o enviar a otro jugador.

Por último, blunderDB ya no se limita a la aplicación de escritorio: el mismo binario ofrece una interfaz de línea de comandos y un modo servidor opcional, que puede apoyarse en PostgreSQL para los despliegues multiusuario. No obstante, el uso normal sigue siendo la aplicación de escritorio. Véase Interfaz de línea de comandos (CLI) y Modo headless (servidor).

8.19. ¿Cuál es la arquitectura de software de blunderDB?

  • El backend está programado en Go. Se encarga de todas las operaciones sobre la base de datos SQLite que almacena las posiciones.

  • El frontend está programado en Svelte. Se encarga del renderizado de la interfaz gráfica y del tablero de Backgammon.

  • La aplicación se encapsula con Wails, lo que permite generar aplicaciones de escritorio nativas para Windows, Linux y macOS.

  • La base de datos se gestiona con SQLite.

  • El modo servidor opcional puede apoyarse en PostgreSQL en lugar de SQLite para los despliegues multiusuario.

  • El evaluador integrado (gammonNet, MIT) es una red neuronal portada a Go y compilada en blunderDB: evalúa cualquier posición sin conexión, sin XG ni GNUbg. Ver «¿Qué vale el evaluador integrado?» más abajo.

Para más información, consulte el repositorio GitHub de blunderDB.

8.20. ¿En qué plataformas funciona blunderDB?

blunderDB funciona en Windows, Linux y Mac.

8.21. ¿De dónde proviene el icono de blunderDB?

El icono de blunderDB es el emoticono «goggling» de la serie SMirC.
