1. Download e installazione

blunderDB si presenta come un unico eseguibile che non richiede alcuna installazione.

L’ultima versione di blunderDB è disponibile con licenza MIT:

  • per Windows: https://github.com/kevung/blunderDB/releases/latest/download/blunderDB-windows-0.36.0.exe

  • per Linux: https://github.com/kevung/blunderDB/releases/latest/download/blunderDB-linux-0.36.0

  • per Mac: https://github.com/kevung/blunderDB/releases/latest/download/blunderDB-macos-0.36.0.zip

Per una consultazione offline, è possibile scaricare anche questa documentazione in formato PDF: https://github.com/kevung/blunderDB/releases/latest/download/blunderDB-0.36.0-it.pdf

Nota

blunderDB utilizza Webview2 per il rendering dell’interfaccia grafica. È molto probabile che Webview2 sia già presente nativamente nel vostro sistema operativo. In caso contrario, la prima esecuzione di blunderDB proporrà di scaricarlo e installarlo. Non è richiesta alcuna azione da parte dell’utente.

Ogni versione pubblicata sulla pagina delle release è accompagnata da una trentina di file. La tabella seguente indica quale prendere secondo il proprio sistema; sostituire x.y.z con il numero di versione.

I file amd64 e x86_64 sono per un processore Intel o AMD, cioè quasi tutti i computer da scrivania. I file arm64 e aarch64 sono per un processore ARM a 64 bit: Raspberry Pi 4 e 5, Mac con chip Apple che eseguono Linux, server ARM. Nel dubbio, uname -m risponde: x86_64 oppure aarch64. Il pacchetto AUR blunderdb-bin copre entrambi e sceglie da solo.

Gli altri file della pagina sono i binari Linux grezzi (vedere più avanti), i manifesti winget e Homebrew (vedere Gestori di pacchetti Windows e Mac (in arrivo)), la documentazione in PDF in nove lingue e le impronte .sha256.

1.2. Verificare un download

Ogni file pubblicato è accompagnato dalla sua impronta SHA-256, in un file con lo stesso nome seguito da .sha256. Scaricare entrambi nella stessa cartella e verificare che il file ricevuto sia quello pubblicato:

sha256sum -c blunderdb_x.y.z_amd64.deb.sha256        # Linux
shasum -a 256 -c blunderDB-macos-x.y.z.zip.sha256   # macOS

Get-FileHash .\blunderDB-windows-x.y.z.exe -Algorithm SHA256   # Windows

Su Linux e macOS il comando mostra OK; su Windows, confrontare il valore mostrato con il contenuto del file .sha256. Questa verifica è la garanzia disponibile in assenza di firma del codice (vedere Sezione 16 e Sezione 17).

Ogni file pubblicato è inoltre accompagnato da un’attestazione di provenienza (SLSA, tramite Sigstore), che dimostra che è stato effettivamente prodotto dall’esecuzione di build ufficiale del repository su GitHub, senza alcuna chiave da gestire:

gh attestation verify blunderdb_x.y.z_amd64.deb --repo kevung/blunderDB

1.3. Installazione su Linux

Per Linux sono disponibili diversi formati. I pacchetti e gli archivi seguenti rendono blunderDB eseguibile automaticamente: a differenza del binario grezzo scaricato tramite un browser, evitano di dover eseguire chmod +x a ogni download o aggiornamento. Creano inoltre una voce nel menu delle applicazioni.

Nota

I pacchetti .deb e .rpm associano l’estensione .dbx (un database esportato con password, vedi Distribuire un database: origine e password) a blunderDB: fare doppio clic su un file .dbx ricevuto da un terzo lo apre direttamente. L’estensione .db di un database ordinario non viene associata di proposito — è troppo generica e condivisa con altri programmi — ma resta apribile normalmente dal menu Apri di blunderDB.

1.3.1. Pacchetti nativi (.deb / .rpm)

Metodo consigliato su Debian, Ubuntu e Linux Mint (.deb) nonché su Fedora e openSUSE (.rpm). Il gestore di pacchetti installa automaticamente la dipendenza webkit2gtk appropriata. Sostituire x.y.z con la versione scaricata:

sudo apt install ./blunderdb_x.y.z_amd64.deb     # Debian / Ubuntu / Mint
sudo dnf install ./blunderdb-x.y.z.x86_64.rpm    # Fedora / openSUSE

1.3.2. Arch Linux (AUR)

Il pacchetto blunderdb-bin è disponibile sull’AUR e viene aggiornato automaticamente dagli assistenti AUR:

yay -S blunderdb-bin      # ou : paru -S blunderdb-bin

1.3.3. Flatpak

Il bundle blunderDB-x.y.z.flatpak funziona su qualsiasi distribuzione in cui Flatpak è installato. Si basa sull’ambiente GNOME 47, che Flatpak scarica da Flathub se manca:

flatpak install ./blunderDB-x.y.z.flatpak
flatpak run io.github.kevung.blunderDB

blunderDB non è ancora pubblicato su Flathub: il bundle si installa dal file scaricato e si aggiorna installando quello della versione successiva. L’applicazione ha accesso alla cartella personale per aprire e salvare i database. La riga di comando (Interfaccia a riga di comando (CLI)) si ottiene con flatpak run io.github.kevung.blunderDB <comando>.

1.3.4. Archivio .tar.gz

Per le altre distribuzioni. L’estrazione di un archivio conserva il bit di esecuzione, quindi non è necessario chmod:

tar xzf blunderDB-linux-webkit2gtk-4.1-x.y.z.tar.gz
cd blunderDB-linux-webkit2gtk-4.1-x.y.z
./blunderDB

Nota

L’eseguibile dell’archivio si chiama blunderDB, con le maiuscole. I pacchetti .deb, .rpm, AUR e Flatpak installano inoltre il collegamento blunderdb in minuscolo, il nome usato dalla documentazione della riga di comando (Interfaccia a riga di comando (CLI)); l’archivio contiene lo stesso collegamento accanto all’eseguibile. Per averlo nel proprio PATH: ln -s "$PWD/blunderDB" ~/.local/bin/blunderdb.

1.3.5. Binario grezzo (metodo avanzato)

Il binario grezzo https://github.com/kevung/blunderDB/releases/latest/download/blunderDB-linux-0.36.0 rimane disponibile. Poiché un browser rimuove il bit di esecuzione durante il download, è necessario ripristinarlo prima della prima esecuzione:

chmod +x ./blunderDB-linux-x.y.z

Nota

Vengono pubblicate due varianti Linux a seconda della versione della libreria webkit2gtk. Se si ottiene l’errore libwebkit2gtk-4.0.so.37: cannot open shared object file, la distribuzione utilizza webkit2gtk-4.1: utilizzare il pacchetto .deb/.rpm, il pacchetto AUR oppure scaricare la versione dedicata https://github.com/kevung/blunderDB/releases/latest/download/blunderDB-linux-webkit2gtk-4.1-0.36.0. I pacchetti nativi selezionano automaticamente la dipendenza corretta.

1.4. Immagine Docker (modalità server)

La modalità server (Modalità headless (server)) non ha bisogno dell’applicazione desktop: ogni versione pubblica l’immagine ghcr.io/kevung/blunderdb-serve sul registro GitHub, per linux/amd64 e linux/arm64, con il tag della versione e con latest:

docker pull ghcr.io/kevung/blunderdb-serve:x.y.z

L’avvio, la configurazione e l’avvertenza sul proxy di autenticazione sono descritti in Immagine pubblicata.

1.5. Gestori di pacchetti Windows e Mac (in arrivo)

Su Linux, blunderDB si installa già tramite il gestore di pacchetti (AUR, .deb, .rpm). L’equivalente per Windows (winget) e per Mac (Homebrew) è in preparazione: i manifesti sono forniti con ogni release (blunderDB-winget-manifests-x.y.z.zip e blunderdb-x.y.z.rb sulla pagina delle release), ma non sono ancora stati sottoposti ai repository pubblici. Finché non sarà così, i comandi qui sotto non funzionano; descrivono l’installazione prevista:

winget install KevinUnger.blunderDB        # Windows, une fois publié

brew tap kevung/tap                        # Mac, une fois le tap créé
brew install --cask blunderdb

Né il pacchetto winget né il cask cambiano la natura dell’eseguibile: resta non firmato, e gli avvertimenti descritti qui sotto si applicano invariati. Su Mac, brew install --cask --no-quarantine blunderdb evita il blocco di Gatekeeper al primo avvio.

1.6. Avvertenze per Windows e Mac

Avvertimento

Su Windows, è possibile che quest’ultimo sia restio a eseguire blunderDB. Vedere Sezione 16 per capire il motivo e aggirare gli eventuali blocchi.

Avvertimento
