8. Domande frequenti (FAQ)

8.1. A cosa serve blunderDB?

blunderDB permette di costituire un database personalizzato di posizioni. Il suo punto di forza è non presupporre alcuna classificazione a priori. L’utente ha così la libertà di interrogare le posizioni con grande flessibilità combinando a piacimento diversi criteri (corsa, struttura, cubo, punteggio, pedine arretrate, pedine nella zona, probabilità di vittoria/gammon/backgammon, …).

Un altro utilizzo pratico di blunderDB è la creazione di cataloghi di posizioni di riferimento. Grazie alla possibilità di etichettare le posizioni, l’utente può raccogliere tutte le sue posizioni di riferimento in modo strutturato all’interno di un unico file. Spero che blunderDB faciliti la condivisione di posizioni tra i giocatori.

8.2. Cosa ha motivato la creazione di blunderDB?

Ero abituato a conservare in cartelle diverse posizioni interessanti o blunder. Tuttavia incontravo difficoltà a ritrovare posizioni secondo criteri non previsti inizialmente dalla mia scelta di categorie tematiche. Per esempio, se le posizioni erano state ordinate per tipo di gioco (corsa, holding game, blitz, backgame, …), come recuperare tutte le posizioni a un certo punteggio? o a un certo livello di cubo? Infine, alcune vecchie posizioni tendevano a cadere nell’oblio. Volevo uno strumento che aggregasse tutte le mie posizioni e che non presupponesse a priori categorie tematiche, per poi poter porre domande al database. Con questo approccio flessibile, si possono aggiungere nuovi filtri senza rompere l’organizzazione delle posizioni. Questo tipo di software è piuttosto comune negli scacchi, come ChessBase.

8.3. Come salvare lo stato del database corrente?

Il database viene aggiornato immediatamente dopo l’esecuzione delle richieste. Non è necessaria alcuna operazione di salvataggio esplicita.

8.4. Devo creare database diversi per categorie diverse di posizioni?

Salvo per ragioni ben identificate, è essenziale non ripartire le posizioni in database separati, a rischio di non poterle mettere in relazione in ricerche future. La filosofia di blunderDB è di non presupporre categorie di posizioni a priori e di permettere all’utente di interrogarle in modo flessibile. Quando le posizioni sono state incontrate in condizioni particolari o per ragioni specifiche, può essere opportuno conservarle in database distinti. Si possono per esempio costituire database di posizioni distinti per:

  • le posizioni di riferimento,

  • i blunder nei tornei dal vivo,

  • i blunder nel gioco online.

8.5. Come unire più database?

Se disponi di più database blunderDB che desideri unire, utilizza la funzionalità «Import Database»:

  1. Apri il database principale (quello che riceverà le posizioni importate)

  2. Fai clic sul pulsante «Import Database» nella barra degli strumenti

  3. Seleziona il database da importare

  4. blunderDB unirà automaticamente le posizioni

Durante l’unione, blunderDB evita i duplicati e unisce in modo intelligente analisi e commenti. Le posizioni identiche non verranno duplicate, ma le loro analisi e i loro commenti verranno combinati.

Nota

Si consiglia di eseguire una copia di backup del database principale prima di importare un altro database.

8.6. Quali formati di file di match sono supportati?

blunderDB supporta i seguenti formati di match:

  • eXtreme Gammon (XG): file .xg, con analisi completa delle mosse, decisioni di cubo, mosse giocate e supporto multi-motore. File .xgp per l’importazione di posizioni individuali con analisi.

  • GNUbg: file .sgf (Smart Game Format), con analisi.

  • Jellyfish: file .mat e .txt.

  • BGBlitz: file .bgf e posizioni testuali.

L’importazione può avvenire tramite file singolo, selezione multipla, cartella ricorsiva, incollaggio dagli appunti o trascinamento (drag and drop).

blunderDB rileva automaticamente i duplicati e impedisce l’importazione di un match già presente nel database.

8.7. Ho bisogno di eXtreme Gammon per usare blunderDB?

No. blunderDB legge anche i file di GNUbg, BGBlitz e Jellyfish, e il suo valutatore integrato (gammonNet) analizza qualsiasi posizione senza dipendere da software di terzi — vedi «Quanto vale il valutatore integrato?» più sotto. Un import da XG apporta tuttavia l’analisi più completa (mosse, decisioni di cubo, marcature, fortuna del tiro): è il formato più ampiamente sfruttato dalle statistiche.

8.8. Che cos’è una collezione?

Una collezione è un raggruppamento personalizzato di posizioni. A differenza di una ricerca per filtri che è dinamica, una collezione è un insieme fisso di posizioni scelte manualmente dall’utente. Le collezioni consentono, ad esempio, di raggruppare posizioni di riferimento per una tematica particolare.

8.9. Che cos’è l’EPC?

L’EPC (Effective Pip Count) è una misura più precisa del semplice conteggio pip per valutare le posizioni di bear-off. Il pannello Eval di blunderDB utilizza il database di bear-off a 6 punti di GNUbg e calcola in tempo reale l’EPC, il numero medio di lanci, la deviazione standard, il conteggio pip e il wastage.

Sulle posizioni di bearoff puro, il pannello mostra anche la probabilità di vittoria del giocatore al tiro e, quando la posizione è coperta da un database two-sided (database integrato fino a 6 pedine per giocatore, database scaricabile fino a 11), il verdetto di cubo money esatto. Fuori da questo dominio, la probabilità è stimata con il suo margine d’errore e il verdetto non viene volutamente mostrato. Vedere la sezione « Metodologia e ipotesi del pannello Eval » del manuale per il dettaglio delle ipotesi.

8.10. Quanto vale il valutatore integrato (gammonNet)?

gammonNet è una rete neurale addestrata da terzi (vedi Crediti), portata in Go e compilata in blunderDB: nessun software esterno, nessuna connessione di rete. Svolge il ruolo di XG o di GNUbg per le posizioni non importate — ricerca fino a 0 o 2 tiri di anticipo, decisione di cubo secondo Janowski e la tabella di equità di match di blunderDB, rispettando il punteggio. Non è né l’unico né necessariamente il miglior motore sul mercato: è quello che funziona offline, senza account né abbonamento, sulla posizione che state guardando. Nulla impedisce peraltro di importare le analisi di XG o di GNUbg quando esistono — le due fonti convivono, e una colonna indica l’origine di ciascuna analisi. Vedi la sezione «Pannello Eval» e «Metodologia e ipotesi del pannello Eval» del manuale.

8.11. Qual è la differenza tra il PR e lo Snowie Error Rate?

Il PR (Performance Rating) è la media degli errori di equità (normalizzata, in millesimi di punto) sull’insieme delle decisioni conteggiate; più è basso, meglio si gioca. Lo Snowie Error Rate riporta la stessa media al numero di mosse piuttosto che al numero di decisioni — una partita più lunga non peggiora quindi meccanicamente lo SER. blunderDB mostra entrambi nel pannello Stats, allineati alle convenzioni di eXtreme Gammon e di GNUbg (vedi Appendice: modello statistico — allineamento XG / gnuBG / blunderDB per il dettaglio delle regole di conteggio).

8.12. blunderDB dispone di un’interfaccia a riga di comando?

Sì, blunderDB dispone di un’interfaccia a riga di comando (CLI) che consente di eseguire senza interfaccia grafica operazioni quali la creazione di database, l’importazione di match, l’esportazione, la ricerca di posizioni, la visualizzazione di statistiche, ecc. Consultare la documentazione CLI per maggiori dettagli.

8.13. blunderDB propone una modalità server?

Sì, una modalità «headless» facoltativa: lo stesso binario, avviato con serve, espone il motore di blunderDB in HTTP + JSON dietro un reverse proxy che autentica (blunderDB stesso non esegue alcuna autenticazione). Può appoggiarsi su SQLite o su PostgreSQL multi-tenant, e serve per esempio a consultare o importare partite da un browser, a integrare blunderDB in un altro strumento, o a condividere un database tra più giocatori. L’uso normale resta l’applicazione desktop; vedi Modalità headless (server) per i dettagli (inclusa l’immagine Docker pronta all’uso) e il tutorial «Distribuire la modalità server dietro un proxy» della guida utente.

8.14. Posso modificare, copiare, condividere blunderDB?

Sì, assolutamente. blunderDB è rilasciato sotto licenza MIT.

8.15. Dove sono conservati i miei dati?

Sul vostro disco, nel file .db scelto creando il database: nessun account, nessun server, nessuna sincronizzazione predefinita. L’applicazione desktop apre direttamente questo file; solo la modalità server facoltativa (vedi sopra) fa girare blunderDB a distanza, e in quel caso siete voi a ospitare quel server.

8.16. Posso condividere un database con un altro giocatore?

Sì: un database blunderDB è un semplice file, basta copiarlo o inviarlo. Per diffondere un database a terzi, due meccanismi facoltativi, scelti al momento dell’esportazione, ne fanno una diffusione controllata piuttosto che una semplice copia: una filigrana d’origine firma il file con la vostra identità di emittente (infalsificabile, leggibile nel pannello Metadati o tramite blunderdb info, senza mai registrare nulla lato destinatario), e una protezione con password produce un file .dbx cifrato. Vedi Distribuire un database: origine e password nel manuale.

8.17. Quale formato di dati utilizza blunderDB?

Il database è un semplice file SQLite. In assenza di blunderDB, può quindi essere aperto con qualsiasi editor di file SQLite.

8.18. Quali sono stati i principi di progettazione di blunderDB?

Volevo un’interfaccia accessibile, ma pensata soprattutto per un utilizzo avanzato e prolungato, in cui si concatenano posizioni e ricerche. La riga di comando, aperta con la pressione della barra SPAZIO, e le scorciatoie da tastiera servono questo utilizzo, senza essere un passaggio obbligato.

Desideravo inoltre che blunderDB fosse leggero, autonomo, senza installazione e disponibile per diverse piattaforme, da cui la mia scelta del linguaggio Go e della libreria Svelte. Per la serializzazione del database, il formato dei file deve essere multipiattaforma e adatto a contenere un database. Il formato di file sqlite sembrava perfettamente indicato.

Ci tenevo anche a che un database restasse un semplice file, che si può copiare, salvare o inviare a un altro giocatore.

Infine, blunderDB non si limita più all’applicazione desktop: lo stesso binario offre un’interfaccia a riga di comando e una modalità server facoltativa, che può appoggiarsi a PostgreSQL per le installazioni multiutente. L’uso normale resta tuttavia l’applicazione desktop. Vedere Interfaccia a riga di comando (CLI) e Modalità headless (server).

8.19. Qual è l’architettura software di blunderDB?

  • Il backend è scritto in Go. È responsabile di tutte le operazioni sul database SQLite che memorizza le posizioni.

  • Il frontend è scritto in Svelte. È responsabile del rendering dell’interfaccia grafica e del board del Backgammon.

  • L’applicazione è incapsulata con Wails, che consente di produrre applicazioni desktop native per Windows, Linux e macOS.

  • Il database è gestito da SQLite.

  • La modalità server facoltativa può appoggiarsi a PostgreSQL invece di SQLite per le installazioni multiutente.

  • Il valutatore integrato (gammonNet, MIT) è una rete neurale portata in Go e compilata in blunderDB: valuta qualsiasi posizione offline, senza XG né GNUbg. Vedi «Quanto vale il valutatore integrato?» più sotto.

Per maggiori informazioni, vedere il repository GitHub di blunderDB.

8.20. Su quali piattaforme funziona blunderDB?

blunderDB funziona su Windows, Linux e Mac.

8.21. Da dove proviene l’icona di blunderDB?

L’icona di blunderDB è l’emoticon «goggling» della serie SMirC.
