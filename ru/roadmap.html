9. Дорожная карта

На этой странице перечислены идеи, рассматриваемые для blunderDB — это не обязательство по срокам или порядку. blunderDB разрабатывается одним человеком в свободное время: идея может быстро продвинуться, ждать месяцами или быть отброшена, если её заменит идея получше.

Точное отслеживание ведётся на GitHub:

  • открытые тикеты сгруппированы по этапам в вехах Étape 3 — Étendre (то, что описано на этой странице) и Étape 4 — Fond (более тяжёлые проекты);

  • чтобы предложить или обсудить идею — раздел Discussions – категория Ideas;

  • каждая опубликованная версия анонсируется в Discussions – категория Announcements.

10. Этап 3 — Расширение

10.1. Импорт и рабочий процесс

  • Панель по завершении импорта: число импортированных матчей, отмеченные позиции, позиции без анализа, пять худших ошибок (#257).

  • Наблюдение за папкой (например, папкой eXtreme Gammon) и автоматический импорт каждого нового файла (#258).

  • После импорта — прохождение очереди изучения, показывающей только блендеры, отмеченные позиции и спорные решения партии (#259).

  • Импорт матчей, сыгранных на bgammon.org, и распознавание идентификатора позиции OGID, вставленного в приложение (#262).

  • Отслеживание происхождения каждого комментария (пользователь, eXtreme Gammon, GNUbg…) и отображение всех, а не одного, выбранного случайно (#263).

10.2. Категоризация без навязывания классификации

  • Автоматическая маркировка каждой позиции по фазе партии (дебют, миттельшпиль, гонка, беароф) для фильтрации и поиска в статистике (#264).

  • Словарь предлагаемых тегов (#blitz, #backgame, #containment…) с автодополнением и панель, перечисляющая их по частоте (#265).

  • Пятая вкладка статистики, разбивающая PR и частоту ошибок по фазе, тегу и счёту away, в виде матрицы (#266).

10.3. Анализ и оценка

  • Для текущей позиции — вердикт по кубу при любом счёте матча до 5, 7 или 9 очков, в единой сетке (#267).

  • PR, вычисляемый по матчам без импортированного анализа, путём сравнения сыгранного хода с рекомендацией встроенного оценщика (#268).

  • Сравнение бок о бок, на одной и той же позиции, того, что говорят разные движки, уже присутствующие в базе (#269).

  • Публикация реальной силы встроенного оценщика по сравнению с точной эталонной таблицей и её непрерывное измерение против импортов eXtreme Gammon (#270).

  • Отображение действующих правил (лимит куба, Джакоби, бивер) рядом с вердиктом и возможность выбора таблицы матчевых эквити для каждой базы (#271).

  • Публикация измерения 3-ply (время, прирост точности) и предложение его в качестве настройки, если компромисс это оправдывает (#272).

10.4. Обучение

  • Первый хронометрируемый тренировочный модуль: подсчёт пипсов, EPC, точка тейка (#273).

  • Постановка цели прогресса («PR ниже 5 за три месяца») и отслеживание отклонения на кривой (#274).

  • Связь статистики обучения (Anki) со статистикой реальной игры: действительно ли повторённая категория улучшается (#275)?

  • Связанные карточки куба: сначала удвоение, затем принятие, как два отдельных вопроса вместо одной двухэтапной карточки (#276).

  • Обучающие маршруты: упорядоченная последовательность прокомментированных позиций, распространяемая как база с водяным знаком, предназначенная для тренера (#277).

10.5. Обмен анализом

  • Единое отображение доски, экспортируемое в SVG или PNG, точно соответствующее тому, что показывает экран (#278).

  • Автономный HTML-отчёт по сессии, матчу или турниру, распечатываемый в PDF из браузера (#279).

  • Экспорт в CSV или Parquet с примером блокнота Jupyter, поддерживаемым в актуальном состоянии (#280).

  • Указатель на этом сайте баз с водяными знаками, которыми другие игроки делятся с проверяемой личностью (#281).

10.6. Поиск и библиотека

  • Коллекции, которые переоцениваются при открытии (именованный фильтр, никогда не замороженный), и сравнение двух игроков бок о бок на вкладке Игроки (#282).

  • Запись поискового запроса на обычном языке («мои ошибки по кубу при этом счёте») вместо токенов, детерминированно и офлайн (#283).

10.7. Интерфейс и платформа

  • Экран приветствия, предлагающий, когда не открыта ни одна недавняя база: обучающий тур, пример базы, импорт моих матчей, открытие базы (#284).

  • Корзина для удалённых позиций и «отмена» для самых частых удалений (#285).

  • Именованные темы — светлая, тёмная, высококонтрастная, для печати (#286).

  • Ряд мелких повседневных удобств: доступный для просмотра журнал активности, палитра команд, более читаемые значки поиска (#287).

  • Чёткое разъяснение того, что работает для синхронизации базы между несколькими компьютерами (и что нет), и кнопка для объединения двух баз (#288).

  • Минимальный клиент и политика версионирования для API серверного режима (#289).

  • Перенос в приложение возможностей, которые сегодня существуют только на стороне сервера: приостановка карточки, журнал повторений, оптимизация FSRS (#290).

11. Этап 4 — Фундаментальные проекты

Эти идеи меняют природу части программного обеспечения; каждая ждёт явного решения перед началом работы.

  • Автоматическая классификация типа игры позиции (гонка, holding, backgame, blitz…), именование повторяющихся тем ошибок (слишком пассивно, тайминг, недооценённый гаммон…) и группировка повторяющихся ошибок по накопленной стоимости — обещание, которое даёт название продукта (#291).

  • Усечённые роллауты для разрешения спора между двумя очень близкими ходами с отображаемым доверительным интервалом (#292).

  • «Позиции, похожие на эту»: поиск позиций, наиболее близких к той, что на экране (#293).

  • Режим викторины, который проверяет, а не заучивает, с тренировочным PR, сопоставимым с реальным PR (#294).

  • Веб-интерфейс только для чтения поверх серверного режима, для планшета и мобильного (#295).

  • Режим клуба или тренера на сервере: предоставление библиотеки только для чтения, получение матчей учеников (#296).

  • Дистиллированная, гораздо более быстрая оценочная сеть и кэш оценок, переживающий закрытие приложения (#297).

  • Объяснение ошибки одной фразой, без обращения к языковой модели (#298).

  • Необязательный ассистент, строго локальный и никогда не включённый по умолчанию, через Ollama (#299).

12. Что не планируется

Игра против встроенного оценщика изменила бы природу продукта (полноценный игровой движок: правила, ввод ходов, история партии); это не входит в планы blunderDB (#300).
