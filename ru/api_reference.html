Контракт API

Это приложение генерируется из исходного кода (go run ./cmd/openapi-gen; полный контракт со схемами см. в openapi.yaml в корне репозитория): не редактируйте его напрямую, следующая генерация перезапишет любые изменения. Каждое семейство группирует методы POST /v1/<семейство>.<метод>, предоставляемые демоном (см. Безголовый режим (сервер)), с их формой ответа (JSON или NDJSON для потокового списка) и, если применимо, упоминанием необязательного заголовка Idempotency-Key.

Идемпотентность

Большинству методов не нужен никакой особый механизм: чтения не имеют побочных эффектов, а записи positions.* идемпотентны по своему действию благодаря хешу Зобриста содержимого — повторное сохранение той же позиции возвращает ту же строку, а не дубликат. 48 методов принимают необязательный заголовок Idempotency-Key: те, у которых два вызова — это два разных действия, и positions.save, ответ которого сообщает, создал ли вызов позицию (created), и сообщил бы это неверно при повторе после потерянного ответа. Вызов, повторённый с тем же ключом, возвращает результат первой попытки вместо повторения её действия — см. пометку «(Idempotency-Key)» в таблице выше. Ни одному другому методу этот заголовок не нужен, и они его не принимают.

Условные чтения

Методы, помеченные «(ETag)», возвращают заголовок ETag. Если отправить его обратно в If-None-Match, будет получен ответ 304 без тела, пока не изменилось ничто из того, что читает метод — см. Проведение турниров и мероприятия.

Таймкоды транскрипции

Жест transcriptions.apply может нести момент видео, в который он совершается, в миллисекундах от начала медиа: TickMS, который читается, только когда HasTick равен true (0 тоже момент). enter_die делает его таймкодом броска (считается первая клавиша кости); enter_play, validate, dance, double, take, pass и resign делают его таймкодом действия, только для нового действия: исправление на месте сохраняет прежние таймкоды. Жест set_timecode задаёт TickMS (вместе с HasTick) и RollTickMS (вместе с HasRollTick) для действия под курсором; отрицательное значение стирает таймкод. Жест set_video привязывает источник видео, названный в VideoSource (URL http(s) или локальный путь), пустая строка отвязывает его; set_header тоже задаёт его, когда его заголовок называет источник, но никогда не стирает.

Жест seek_cursor ставит курсор на действие с номером At, а за последним — в конец документа, ничего не записывая и не попадая в стек отмены: так курсор следует за воспроизводимым видео. decision_ms вместе с decision_estimated — это оценка: ход без метки действия, измеренный от броска до первого момента следующего действия.

Отрисованное состояние несёт источник в header.video_source, таймкоды каждого действия в roll_tick_ms и tick_ms и, у каждого аннотированного действия, длительности decision_ms и cube_decision_ms: измеренные Арбитром (Arbiter), когда они измерены, иначе выводимые из таймкодов. Таймкод, предшествующий предыдущему, помечается несогласованностью timecode_backwards и оставляет неизвестными зависящие от него длительности.
