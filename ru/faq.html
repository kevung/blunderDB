8. Часто задаваемые вопросы

8.1. Для чего нужен blunderDB?

blunderDB позволяет создать персонализированную базу данных позиций. Его сила в том, что он не предполагает никакой классификации a priori. Таким образом, пользователь свободен запрашивать позиции с большой гибкостью, комбинируя по своему усмотрению различные критерии (гонка, структура, куб, счёт, отставшие шашки, шашки в зоне, шансы на выигрыш/гаммон/бэкгаммон, …).

Ещё одно удобное применение blunderDB — это составление каталогов эталонных позиций. Благодаря возможности помечать позиции пользователь может структурированно собрать все свои эталонные позиции в одном файле. Я хочу, чтобы blunderDB упрощал обмен позициями между игроками.

8.2. Что побудило создать blunderDB?

Раньше я хранил интересные позиции или ошибки (blunders) в разных папках. Однако мне было трудно находить позиции по критериям, изначально не предусмотренным моим выбором тематических категорий. Например, если позиции были отсортированы по типу игры (гонка, holding game, блиц, backgame, …), как найти все позиции при определённом счёте? или при определённом уровне куба? Наконец, некоторые старые позиции имели тенденцию забываться. Я хотел инструмент, который объединяет все мои позиции и не предполагает a priori тематических категорий, а затем позволяет задавать вопросы базе данных. При таком гибком подходе новые фильтры можно добавлять, не нарушая организацию позиций. Такое программное обеспечение довольно распространено в шахматах, например ChessBase.

8.3. Как сохранить текущую базу данных?

База данных изменяется немедленно после выполнения запросов. Явного сохранения не требуется.

8.4. Нужно ли создавать разные базы данных для разных категорий позиций?

За исключением хорошо обоснованных причин, важно не распределять позиции по отдельным базам данных, рискуя не суметь связать их в будущих поисках. Философия blunderDB состоит в том, чтобы не предполагать категории позиций a priori и позволять пользователю запрашивать их гибко. Когда позиции встречались в особых условиях или по конкретным причинам, может быть разумно хранить их в отдельных базах данных. Можно, например, создать отдельные базы данных позиций для:

  • эталонных позиций,

  • бландеров на реальных турнирах,

  • бландеров в онлайн-игре.

8.5. Как объединить несколько баз данных?

Если у вас несколько баз данных blunderDB, которые вы хотите объединить, используйте функцию «Import Database»:

  1. Откройте основную базу данных (ту, в которую будут импортированы позиции)

  2. Нажмите кнопку «Import Database» на панели инструментов

  3. Выберите базу данных для импорта

  4. blunderDB автоматически объединит позиции

В ходе слияния blunderDB избегает дублирования и разумно объединяет анализы и комментарии. Одинаковые позиции не будут дублированы, но их анализы и комментарии будут объединены.

Примечание

Рекомендуется сделать резервную копию основной базы данных перед импортом другой базы данных.

8.6. Какие форматы файлов матчей поддерживаются?

blunderDB поддерживает следующие форматы матчей:

  • eXtreme Gammon (XG): файлы .xg с полным анализом ходов, решениями по кубу, сыгранными ходами и поддержкой нескольких движков. Файлы .xgp для импорта отдельных позиций с анализом.

  • GNUbg: файлы .sgf (Smart Game Format) с анализом.

  • Jellyfish: файлы .mat и .txt.

  • BGBlitz: файлы .bgf и текстовые позиции.

Импорт можно выполнять по одному файлу, множественным выбором, рекурсивно из папки, вставкой из буфера обмена или перетаскиванием.

blunderDB автоматически обнаруживает дубликаты и предотвращает импорт матча, уже присутствующего в базе данных.

8.7. Нужен ли мне eXtreme Gammon для использования blunderDB?

Нет. blunderDB также читает файлы GNUbg, BGBlitz и Jellyfish, а его встроенный оценщик (gammonNet) анализирует любую позицию без зависимости от стороннего программного обеспечения — см. «Чего стоит встроенный оценщик?» ниже. Однако импорт из XG даёт наиболее полный анализ (ходы, решения по кубу, отметки, удача броска): это формат, наиболее полно используемый статистикой.

8.8. Что такое коллекция?

Коллекция — это пользовательская группировка позиций. В отличие от динамического поиска по фильтрам, коллекция представляет собой фиксированный набор позиций, выбранных пользователем вручную. Коллекции позволяют, например, группировать эталонные позиции по конкретной теме.

8.9. Что такое EPC?

EPC (Effective Pip Count) — более точная мера, чем простой пипкаунт, для оценки позиций снятия шашек. Панель Eval в blunderDB использует базу данных снятия шашек с 6 пунктов GNUbg и в реальном времени вычисляет EPC, среднее число бросков, стандартное отклонение, пипкаунт и wastage.

На позициях чистого bearoff панель также отображает вероятность выигрыша игрока на ходу и, когда позиция покрыта two-sided базой (встроенная база — до 6 шашек у каждого игрока, загружаемая — до 11), точный money-вердикт по кубу. Вне этой области вероятность оценивается с указанием погрешности, а вердикт намеренно не отображается. Подробности допущений см. в разделе «Методология и допущения панели Eval» руководства.

8.10. Чего стоит встроенный оценщик (gammonNet)?

gammonNet — это нейронная сеть, обученная третьей стороной (см. Благодарности), портированная на Go и скомпилированная в blunderDB: никакого внешнего ПО, никакого сетевого подключения. Она играет роль XG или GNUbg для неимпортированных позиций — поиск на глубину 0 или 2 бросков вперёд, решение по кубу по Яновскому и таблице эквити матча blunderDB, с учётом счёта. Это не единственный и не обязательно лучший движок на рынке: это тот, который работает офлайн, без учётной записи и подписки, для позиции, на которую вы смотрите. При этом ничто не мешает также импортировать анализы XG или GNUbg, когда они существуют — оба источника сосуществуют, и колонка указывает происхождение каждого анализа. См. раздел «Панель Eval» и «Методология и допущения панели Eval» в руководстве.

8.11. В чём разница между PR и Snowie Error Rate?

PR (Performance Rating) — это среднее значение ошибок эквити (нормализованное, в тысячных долях очка) по всем засчитанным решениям; чем оно ниже, тем лучше игра. Snowie Error Rate относит то же среднее к числу ходов, а не решений — поэтому более длинный матч механически не ухудшает SER. blunderDB показывает оба показателя на панели Stats, согласованных с соглашениями eXtreme Gammon и GNUbg (см. Приложение: Модель статистики — выравнивание XG / gnuBG / blunderDB для подробностей правил подсчёта).

8.12. Есть ли у blunderDB интерфейс командной строки?

Да, blunderDB имеет интерфейс командной строки (CLI), позволяющий выполнять без графического интерфейса такие операции, как создание баз данных, импорт матчей, экспорт, поиск позиций, отображение статистики и т.д. Смотрите документацию CLI для получения подробной информации.

8.13. Предлагает ли blunderDB серверный режим?

Да, опциональный «headless»-режим: тот же самый бинарный файл, запущенный с serve, предоставляет движок blunderDB по HTTP + JSON за аутентифицирующим обратным прокси (сам blunderDB не выполняет никакой аутентификации). Он может работать на SQLite или на многопользовательском (multi-tenant) PostgreSQL и служит, например, для просмотра или импорта матчей из браузера, интеграции blunderDB в другой инструмент или совместного использования базы данных несколькими игроками. Обычным способом использования остаётся настольное приложение; см. Безголовый режим (сервер) для подробностей (включая готовый образ Docker) и руководство «Развёртывание серверного режима за прокси» в руководстве пользователя.

8.14. Можно ли изменять, копировать, распространять blunderDB?

Да, конечно (и это даже приветствуется!). blunderDB распространяется по лицензии MIT.

8.15. Где хранятся мои данные?

На вашем диске, в файле .db, который вы выбрали при создании базы данных: никакой учётной записи, никакого сервера, никакой синхронизации по умолчанию. Настольное приложение открывает этот файл напрямую; только опциональный серверный режим (см. выше) запускает blunderDB удалённо, и в этом случае именно вы размещаете этот сервер.

8.16. Могу ли я поделиться базой данных с другим игроком?

Да: база данных blunderDB — это обычный файл, достаточно скопировать его или отправить. Для распространения базы данных третьей стороне два опциональных механизма, выбираемых при экспорте, превращают это в контролируемое распространение, а не простое копирование: водяной знак происхождения подписывает файл вашей идентичностью издателя (неподделываемый, читаемый на панели Метаданные или через blunderdb info, никогда ничего не фиксируя на стороне получателя), а защита паролем создаёт зашифрованный файл .dbx. См. Распространение базы: происхождение и пароль в руководстве.

8.17. Какой формат данных использует blunderDB?

База данных — это простой файл SQLite. В отсутствие blunderDB его можно открыть любым редактором файлов SQLite.

8.18. Каковы были принципы проектирования blunderDB?

Я хотел, чтобы интерфейс оставался доступным, но прежде всего продумывал его для продвинутой и интенсивной работы, когда позиции и запросы идут одна за другой. Командная строка, открываемая нажатием клавиши ПРОБЕЛ, и сочетания клавиш служат такой работе, но не являются обязательными.

Кроме того, я хотел, чтобы blunderDB был лёгким, автономным, не требующим установки и доступным для разных платформ, отсюда мой выбор языка Go и библиотеки Svelte. Для сериализации базы данных формат файлов должен быть кроссплатформенным и подходящим для хранения базы данных. Формат файлов SQLite оказался как нельзя кстати.

Мне также было важно, чтобы база оставалась обычным файлом, который можно скопировать, сохранить или отправить другому игроку.

Наконец, blunderDB больше не ограничивается настольным приложением: тот же исполняемый файл предоставляет интерфейс командной строки и необязательный серверный режим, который может опираться на PostgreSQL для многопользовательских развёртываний. Тем не менее обычным способом использования остаётся настольное приложение. См. Интерфейс командной строки (CLI) и Безголовый режим (сервер).

8.19. Какова программная архитектура blunderDB?

  • Бэкенд написан на Go. Он отвечает за все операции с базой данных SQLite, в которой хранятся позиции.

  • Фронтенд написан на Svelte. Он отвечает за отображение графического интерфейса и доски для нард.

  • Приложение упаковано с помощью Wails, что позволяет создавать нативные настольные приложения для Windows, Linux и macOS.

  • База данных управляется SQLite.

  • Необязательный серверный режим может опираться на PostgreSQL вместо SQLite для многопользовательских развёртываний.

  • Встроенный оценщик (gammonNet, MIT) — это нейронная сеть, портированная на Go и скомпилированная в blunderDB: она оценивает любую позицию офлайн, без XG или GNUbg. См. «Чего стоит встроенный оценщик?» ниже.

Для получения дополнительной информации см. репозиторий blunderDB на GitHub.

8.20. На каких платформах работает blunderDB?

blunderDB работает на Windows, Linux и Mac.

8.21. Откуда взята иконка blunderDB?

Иконка blunderDB — это смайлик «goggling» из серии SMirC.
