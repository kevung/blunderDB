Матчи, турниры и партии

match — Отобразить матч

Показывает позиции и анализы импортированного матча. В выводе text и summary заголовок повторяет то, что исходный файл говорит о матче, если говорит: рейтинг Эло и опыт каждого игрока, транскрибировавший, правила Джекоби и Бобра денежной игры, программа, записавшая файл; вывод json содержит их в объекте match.

Если в матче сохранена длительность решений (матч, сыгранный против бота, см. Дуэль), вывод text показывает длительность каждого решения, решение по кубу отдельно, а вывод summary — итог и среднее каждого игрока, с отметкой игрока, у которого запас закончился первым; вывод json содержит decision_ms и cube_decision_ms. Неизвестная длительность не записывается. list --type timeerrors выдаёт по игроку и полосе длительности (меньше 5 с, от 5 до 15 с, от 15 до 30 с, больше 30 с) число решений, среднюю ошибку и долю блундеров; --format json отдаёт строки. --ids (идентификаторы матчей через запятую) ограничивает таблицу этими матчами: разбор турнира или сессии.

Для матча, сыгранного здесь в Дуэли, выводы text и summary добавляют его происхождение: начало, раскрытый сид костей и его SHA-256 для сравнения с отпечатком, опубликованным при создании Дуэли, завершение матча (сыгран до конца, остановлен до конца или проигран по времени и кем), контроль времени, игрока, чей резерв исчерпался первым, и бота (уровень, версия gammonNet). Для матча, сыгранного не здесь, они пишут Origin: not played here. Вывод json содержит происхождение в origin (включая lost_on_time), null для матча, сыгранного не здесь. Сервер отдаёт его через /v1/matches.origin: null для матча без происхождения, 404 для несуществующего матча.

Для проанализированного матча потеря шансов выиграть матч на каждом ходу (mwc_loss, дробь: 0,0123 означает 1,23 %, null для неоценённого хода) идёт тем же путём: вывод json содержит список под decision_losses, text добавляет строку MWC loss к оценённым ходам, а summary даёт итог по игрокам, равный потере MWC в списке матчей. Каждая запись содержит также свою сложность (difficulty, ожидаемая потеря эталонного игрока в той же позиции, та же единица, null для неоценённого хода) и avoidable для избегаемой ошибки; вывод json добавляет difficulty_summary (по игрокам: difficulty, excess, ratio, avoidable), text — строки Difficulty и Avoidable error, summary — раздел Difficulty. Сервер отдаёт её через /v1/stats.matchDecisionLosses.

summary заканчивается разделом Review, итогами матча (итоги матча): по игроку PR и его 95-процентный интервал по партиям, потеря MWC, приведённая к 7 очкам, и её интервал по партиям, результат с поправкой на удачу (с результатом, чистой удачей, разрывом ошибок и охватом бросков), три ошибки для разбора (партия, ход, потеря и устранимая доля) и распределение ошибок на поспешные и обдуманные. Сервер отдаёт их через /v1/stats.matchReview. В stats общий PR и строки по фазе, по метке и по счёту несут свой 95-процентный интервал по матчам (столбец 95 % CI), а list --type players — столбец L7.

./blunderdb match --db <path> --id <id> [--format <format>] [--output <file>]

Параметры:

  • --db — База данных (обязательно).

  • --id — Идентификатор матча для отображения (обязательно).

  • --format — Формат вывода: json, text или summary (по умолчанию: json).

  • --output — Выходной файл (по умолчанию: стандартный вывод).

Примеры:

./blunderdb match --db base.db --id 1 --format summary
./blunderdb match --db base.db --id 1 --format text
./blunderdb match --db base.db --id 1 --output match1.json

match repair — Переписывает позиции, анализ и ошибки матча по его исходному файлу, тому, который называет вкладка Сведения его карточки. Матч сохраняет свой идентификатор, турнир, имена игроков в сохранённом виде (псевдонимы, исправления, перестановка), дату, комментарий, видео и метки, транскрипцию и комментарии, написанные к его позициям: комментарий к позиции, которую восстановление покидает, переходит на позицию, которую файл называет для того же хода, если только коллекция, карточка Anki или урок ещё не держит эту позицию; тогда комментарий остаётся там, и отчёт его учитывает. Анализ глубже файлового (ролаут, запущенный после импорта) или исправленный вручную сохраняется. Матч, уже соответствующий своему файлу, не переписывается. --dry-run сообщает, что изменилось бы, ничего не записывая. --list просматривает все матчи, у которых есть исходный файл, и выводит те, что от него отличаются, с числом ходов, позиция которых меняется, и долей проанализированных ходов до и после, а также те, чей файл не найден; ничего не записывает. Относительный путь ищется от папки базы, затем от текущей папки. Восстановление отклоняется, если файл не найден, больше не содержит матч (его отпечаток уже не совпадает с отпечатком сохранённого матча) или если по сохранённым ходам нельзя понять, какой игрок файла какой. Сервер предоставляет его через /v1/matches.repair, исходный файл передаётся в запросе.

./blunderdb match repair --db <chemin> (--id <ID> [--dry-run] | --list) [--format text|json]

./blunderdb match repair --db base.db --list
./blunderdb match repair --db base.db --id 42 --dry-run
./blunderdb match repair --db base.db --id 42

tournament — Чтение проведённого турнира

Читает руководимый турнир без графического интерфейса. Интерактивное руководство турниром — дело консоли движка Nicomaque; эти подкоманды читают, ни одна не ждёт ввода, и только move и confirm пишут.

./blunderdb tournament <sous-commande> --db <chemin> [options]

Подкоманды:

  • list [--format text|json] — Проведённые турниры базы, с их состоянием, версией движка, мероприятием, к которому принадлежит каждый (пусто, если ни к какому), и датой последнего решения.

  • verify --id N [--format text|json] — Переигрывает проведение и сообщает о каждом оставшемся предупреждении. Завершается с ошибкой, если хоть одно осталось: это проверка после турнира, и скрипту, который прогоняет её по базам сезона, нужен код возврата, а не строка для фильтрации.

  • standings --id N — Итоговая таблица в CSV, с призовыми, на языке интерфейса.

  • ranking --season [--rencontre N] [--from AAAA-MM-JJ] [--to AAAA-MM-JJ] [--points 25,18,15] [--participation P] [--elo] [--format csv|json] — Сезонный рейтинг: завершённые турниры мероприятия или периода (границы включены, по дате турнира; без фильтра — все проведённые турниры), где каждое место переводится в очки по шкале (победитель первым; по умолчанию 25, 18, 15, 12, 10, 8, 6, 4, 2, 1), плюс --participation за каждый сыгранный турнир. Разделившие место делят среднее из занимаемых ими мест. Человек узнаётся от турнира к турниру по имени. --elo добавляет клубный Elo, пересчитанный по матчам сезона (формула FIBS, старт с 1500). CSV содержит одну строку на человека и один столбец очков на турнир; незавершённый турнир указывается в списке, но ничего не приносит.

  • page --id N|--rencontre N [--out <папка>] — HTML-страница для экрана одного состязания (--id), либо настенная страница мероприятия (--rencontre: одна строка на стол, независимо от того, какое состязание его занимает). Требуется ровно один из двух. Без --out она идёт в стандартный вывод; с ним записывается в папку, которая становится папкой проведения или мероприятия.

  • export --id N — Сырой журнал событий, воспроизводимый инструментами движка. Журнал — вся правда о проведении: таблица, сетки и предупреждения воспроизводятся из него. Инструменту, читающему этот вывод, blunderDB не нужен вовсе.

  • move --id N --match M --table T [--format text|json] — Меняет стол идущего матча, как перетаскивание одной ячейки на другую в сетке. Если целевой стол занят, два матча меняются столами; стол, выведенный из эксплуатации, отклоняется. В мероприятии, если стол занят другим состязанием, обмен происходит между двумя состязаниями: смена стола записывается в журнал каждого. Выводит стол каждого идущего матча.

  • hall --rencontre N [--format text|json] — Все столы мероприятия: одна строка на стол, какой бы турнир его ни занимал (турнир, матч, игроки), затем предложения всех турниров одной очередью (proposal), сначала игроки, ждущие дольше всех, и в конце матчи, задержанные из-за отсутствия стола или свободного игрока (held, с причиной). Это сетка, которую показывает вид Все столы Дирекции. Столы группируются по залам, если у мероприятия есть залы, и называются по имени, если оно есть.

  • proposals --id N [--format text|json] — Пронумерованная очередь предложений движка: матчи, жеребьёвки, переход к следующей фазе, замена выбывшего участника, прошедшего из группы.

  • confirm --id N --n K [--format text|json] — Подтверждает предложение номер K из proposals, как Запустить в панели, затем показывает следующую очередь.

  • tables --rencontre N|--tournament N [--format text|json] — Свойства столов (название, зал, зарезервирован, закреплён за) и залы, где играет каждое состязание мероприятия (--rencontre), либо свойства состязания, которое играет отдельно (--tournament). Только чтение: запись идёт через call (rencontres.setTables, rencontres.setEventRooms, directions.setTables).

Общие параметры: --db (обязательно), --id (обязательно, кроме list, ranking, page --rencontre, hall и tables), --format.

Примеры:

./blunderdb tournament list --db base.db
./blunderdb tournament verify --db base.db --id 3
./blunderdb tournament standings --db base.db --id 3 > classement.csv
./blunderdb tournament ranking --db base.db --season --from 2026-01-01 --to 2026-12-31 --elo > saison.csv
./blunderdb tournament page --db base.db --id 3 --out /tmp/affichage
./blunderdb tournament page --db base.db --rencontre 1 --out /tmp/evenement
./blunderdb tournament export --db base.db --id 3 > journal.json
./blunderdb tournament move --db base.db --id 3 --match m4 --table 7
./blunderdb tournament hall --db base.db --rencontre 1
./blunderdb tournament tables --db base.db --rencontre 1
./blunderdb tournament proposals --db base.db --id 3
./blunderdb tournament confirm --db base.db --id 3 --n 1

transcribe — Воспроизвести запись

Воспроизводит запись и сообщает, что в ней обнаруживает повторное проигрывание. Источник — файл .mat, матч библиотеки или черновик записи, ровно один из трёх. Матч читается через тот .mat, который он дал бы при экспорте: воспроизводится, стало быть, то, что содержал бы экспорт.

./blunderdb transcribe --mat <fichier> [--check] [--render <sortie>]
./blunderdb transcribe --db <path> --match <id> --check
./blunderdb transcribe --db <path> --draft <id> --check
./blunderdb transcribe --db <path> --match <id> --edit [--accept-losses]
./blunderdb transcribe --db <path> --draft <id> --finish|--abandon
./blunderdb transcribe --db <path> --materialize <document.json>
./blunderdb transcribe --db <path> --import <fichier.mat|document.json>

Параметры:

  • --mat — Воспроизводимый файл .mat.

  • --db — База данных, для --match и --draft.

  • --match — Идентификатор воспроизводимого матча библиотеки.

  • --draft — Идентификатор воспроизводимого черновика записи.

  • --check — Перечисляет найденные несоответствия (поведение по умолчанию).

  • --render — Записывает запись обратно в .mat по этому пути.

  • --format — Формат вывода: text (по умолчанию) или json.

  • --edit — Открывает черновик для --match (или возвращает уже открытый для него).

  • --accept-losses — С --edit для импортированного матча: соглашается, что его анализы и комментарии могут быть потеряны.

  • --finish — Завершает --draft: записывает его матч или заменяет тот, из которого он был открыт, и освобождает черновик.

  • --abandon — Отказывается от --draft: удаляет его без матча; матч, из которого он был открыт, остаётся как есть.

  • --yes — С --abandon для черновика, который так и не породил матч: подтверждает, что всё записанное в нём будет потеряно.

  • --materialize — JSON-документ (header и actions, включая кости), который записывается как матч за один раз или не записывается вовсе.

  • --import — Файл .mat или JSON-документ транскрипции, на котором открывается новый черновик.

--check называет каждое несоответствие с номером действия и партией, в которой оно находится: недопустимый ход, два хода подряд одного игрока, невозможное действие с кубом, действие после конца матча, ход, шаги которого не используют собственные кости, первый ход партии с дублем, которым стартовый бросок быть не может, незаписанный ход — ячейка ???, которую gnubg пишет, когда не сохранил сыгранный ход, и которая не означает, что игрок не смог сходить, несогласованный заявленный счёт — партия, строка счёта которой не та, что дают предыдущие партии, и которая переигрывается с записанным счётом.

Несоответствие сообщается, но никогда не ставится в упрёк: из-за него ничего не отвергается, и код возврата остаётся нулевым, что бы ни нашло проигрывание. Ненулевой код означает настоящий сбой — нечитаемый файл, база, которая не открывается, вывод, который невозможно записать. Скрипт, желающий действовать по этим наблюдениям, читает их в --format json, где испорченный файл и партия с недопустимым ходом не смешиваются.

--render записывает запись обратно в .mat, что позволяет проверить обратимость преобразования на настоящем файле вне тестов.

--materialize записывает без черновика матч, который разыгрывает документ действий, пришедший откуда-то ещё. Правила применяются строго: первое отклонённое действие приводит к сбою команды с указанием его порядкового номера (начиная с 0) и причины, и ничего не записывается. Длительности решений документа (decision_ms, cube_decision_ms) переносятся на ходы.

--import открывает новый черновик на файле .mat или на JSON-документе транскрипции (header, actions и, необязательно, format_version и next_score — форма, в которой хранится черновик). Несоответствия файла сохраняются и отмечаются, как в любом черновике: их исправляют до того, как --finish запишет матч. Файл, который не может прочитать никакое воспроизведение, — нечитаемый JSON, неизвестный вид действия, игрок, кубик или пункт вне доски, .mat без партии — приводит к ошибке команды, и черновик не открывается.

Записывают только три других параметра, теми же методами, что и панель «Запись»: --edit открывает черновик для существующего матча, --finish завершает его — матч заменяется под тем же идентификатором — а --abandon удаляет черновик без матча и требует --yes для черновика, который так и не был завершён и уносит с собой всё записанное в нём. Импортированный матч несёт анализы и комментарии, которых нет в .mat: --edit сообщает самое большее их число и отказывает без --accept-losses.

Пример:

./blunderdb transcribe --mat match.mat --check

# match.mat: 7 point match, 4 game(s), 203 action(s)
#   Final score: 9-2
# Inconsistencies: none

duel — Сыграть Дуэль

Играет Дуэль без интерфейса, по одному Действию за вызов. Каждый вызов — отдельный процесс: он возобновляет Дуэль из базы, играет одно Действие и записывает его обратно. Длительности ходов Дуэли, сыгранной так, неизвестны, но не равны нулю.

./blunderdb duel create --db <path> (--length <n> | --money [--jacoby]) [--side1 <côté>] [--side2 <côté>]
./blunderdb duel create --db <path> --length <n> [--start <XGID>] [--away <j1>,<j2>] [--reroll] [--after-cube] [--single-game] [--minutes-per-point <min> --delay <s>]
./blunderdb duel show --db <path> --id <id>
./blunderdb duel list --db <path>
./blunderdb duel move --db <path> --id <id> --play "24/18 13/11"
./blunderdb duel roll|double|take|pass|resign --db <path> --id <id>
./blunderdb duel forfeit --db <path> --id <id> --side 1|2
./blunderdb duel contribute --db <path> --id <id> --side 1|2 --value <texte>
./blunderdb duel stop|discard --db <path> --id <id>

Подкоманды:

  • create — Начинает Дуэль и играет до первого решения внешней Стороны. --length (от 1 до 25 очков) или --money; --start (XGID Старта); --name1 и --name2; --side1 и --side2 (external или bot:<уровень>, где уровень — instant, normal или thorough, или external:<конфигурация>@<движок> — внешняя Сторона, объявляющая Бота, который играет за ней: происхождение Матча записывает его как объявленного, а не удостоверенного); --discard-at-end отбрасывает черновик в конце вместо записи Матча; --combined-seed не бросает кости, пока каждая внешняя Сторона не внесёт свой вклад в зерно. --away задаёт счёт первой партии в недостающих очках, игрок1,игрок2 (1: партия Кроуфорда, 0: одно очко после неё), и заменяет счёт из --start; без --start партия начинается с начальной позиции при этом счёте. --reroll заставляет бросить заново бросок, который несёт --start; --after-cube начинает после решения о кубе в Старте (игрок, чей ход, сразу бросает, предложенное удвоение принимается) — по умолчанию Дуэль начинается до него, и предложенное удвоение ждёт ответа соперника. --single-game останавливает Дуэль в конце её первой партии, которая записывается одна как Матч. --minutes-per-point и --delay задают контроль времени: резерв каждого игрока в минутах на очко матча (Standard 2, Speed 0,4) и задержку на ход в секундах (12, 10); --time-out (continue или lose_match) — что делает исчерпанный резерв. Старт, который правила не допускают (фишки, счёт за пределами длины, оба игрока в партии Кроуфорда, куб), отклоняется с указанием причины. С двумя Ботами весь матч играется в этом вызове (--side1 bot:instant --side2 bot:instant); сессия на деньги между двумя Ботами отклоняется, так как она никогда не закончилась бы, кроме как в одной партии.

  • show — Счёт, чего ждёт Дуэль и, для хода, допустимые варианты. Начальное значение генератора костей никогда не показывается до конца: его заменяет отпечаток.

  • list — Приостановленные Дуэли.

  • roll, move, double, take, pass, resign — Одно Действие Стороны, которую ждёт Дуэль (--side 1|2, чтобы указать её); --play задаёт ход в нотации, в любом порядке; --level (от 1 до 3) — ценность сдачи; --revision отклоняет Действие, если Дуэль продвинулась.

  • contribute — Вклад внешней Стороны в комбинированное зерно (--side 1|2, --value, от 1 до 64 байт), только один раз, до первого броска; последний вклад запускает кости. Броски тогда выводятся из HMAC-SHA256 запечатанного зерна над вкладом каждой Стороны, которому предшествует его длина, а происхождение Матча хранит вклады.

  • forfeit — Сторона --side (обязательно) сдаёт матч: текущая партия достаётся другой Стороне с очками, доводящими её до длины матча (в игре на деньги — простая по стоимости куба), и Матч записывается как выигранный ею.

  • stop — Останавливает сессию на деньги и записывает её Матч как есть, текущую партию без победителя. Матч на очки отклоняется: он записывается только целиком (forfeit, discard). Остановить — не значит сдать.

  • discard — Отбрасывает Дуэль: ничего не записывается.

Все принимают --db и --format (text или json).
