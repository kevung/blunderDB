マッチ、トーナメント、ゲーム

match — マッチを表示する

インポートしたマッチのポジションと解析を表示します。textとsummaryの出力では、元ファイルがマッチについて記していれば、ヘッダーにそれが示されます：各プレイヤーの Elo レーティングと経験、記録者、マネーゲームの Jacoby と Beaver のルール、ファイルを書いたプログラム。jsonの出力ではmatchオブジェクトに含まれます。

マッチが判断の所要時間を保持している場合(ボット相手に指したマッチ、デュエルを参照)、text 出力は各判断の所要時間をキューブ判断を分けて示し、summary 出力は各プレイヤーの合計と平均を、持ち時間が先に尽きたプレイヤーの印付きで示します。json 出力には decision_ms と cube_decision_ms が含まれます。不明な所要時間は書き出されません。list --type timeerrorsは、プレイヤーと所要時間の帯(5秒未満、5〜15秒、15〜30秒、30秒超)ごとに、判断数、平均誤り、ブランダーの割合を示します。--format jsonはその行を返します。 --ids（カンマ区切りのマッチ ID）はこの表をそれらのマッチに限定します。トーナメントやセッションの振り返りに使います。

ここでデュエルとして対局したマッチについて、text と summary の出力はその出自を追加します。開始局面、公開されたダイスのシードとその SHA-256（デュエル作成時に公開されたフィンガープリントと照合するもの）、マッチの終わり方（最後まで対局、終了前に中断、または時間切れ負けとその当事者）、持ち時間、先に持ち時間が尽きたプレイヤー、ボット（レベル、gammonNet のバージョン）です。ここで対局していないマッチについては Origin: not played here と書きます。json の出力では出自が origin（lost_on_time を含む）に入り、ここで対局していないマッチでは null です。サーバーは /v1/matches.origin で提供し、出自のないマッチには null、存在しないマッチには 404 を返します。

分析済みのマッチでは、各手で失われたマッチの勝率(mwc_loss、小数で、0,0123 は 1,23 % に当たり、採点されない手では null)も同じ経路をたどります。json 出力は一覧を decision_losses の下に持ち、text は採点された手に MWC loss の行を加え、summary はプレイヤーごとの合計を示します。これはマッチ一覧の MWC 損失に等しい値です。各エントリは難度(difficulty、同じ局面での基準プレイヤーの期待損失で、単位は同じ、採点されない手では null)と、避けられたミスを示す avoidable も持ちます。json 出力は difficulty_summary (プレイヤーごと: difficulty、excess、ratio、avoidable)を、text は Difficulty と Avoidable error の行を、summary は Difficulty セクションを加えます。サーバーはこれを /v1/stats.matchDecisionLosses で提供します。

summary は Review セクション、すなわちマッチの総括(マッチの総括)で終わります。プレイヤーごとに、PR とそのゲームにわたる 95 % 区間、7 ポイントに換算した MWC 損失とそのゲームにわたる区間、運で補正した結果(結果、ネットの運、ミスの差、ダイスのカバー率を含む)、見直すべき 3 つのミス(ゲーム、手、損失、回避可能な割合)、そしてミスの急いだものと熟考したものへの内訳を示します。サーバーは /v1/stats.matchReview で提供します。stats では、全体の PR と、フェーズ別、ラベル別、スコア別の行が、マッチにわたる 95 % 区間(列 95 % CI)を持ち、list --type players には L7 列があります。

./blunderdb match --db <path> --id <id> [--format <format>] [--output <file>]

オプション：

  • --db — データベース（必須）。

  • --id — 表示するマッチのID（必須）。

  • --format — 出力フォーマット：json、text、または summary（デフォルト：json）。

  • --output — 出力ファイル（デフォルト：標準出力）。

例：

./blunderdb match --db base.db --id 1 --format summary
./blunderdb match --db base.db --id 1 --format text
./blunderdb match --db base.db --id 1 --output match1.json

match repair — マッチのカードの 情報 タブが示すソースファイルから、そのマッチの局面・解析・エラーを書き直します。マッチは ID、トーナメント、保存されたとおりのプレイヤー名（エイリアス、修正、入れ替え）、日付、コメント、動画とマーク、トランスクリプション、局面に書かれたコメントを保持します。修復によって離れる局面に残されたコメントは、同じ手についてファイルが示す局面に移ります。ただし、コレクション、Anki カード、レッスンがその局面をまだ保持している場合、コメントはそこに残り、レポートがその数を示します。ファイルより深い解析（インポート後に実行したロールアウト）や手で修正した解析は残ります。ファイルとすでに一致するマッチは書き直されません。--dry-run は何も書かずに変更内容を示します。--list はソースファイルを持つすべてのマッチを調べ、それと異なるものを、局面が変わる手の数と前後の解析済みの手の割合とともに示し、ファイルが見つからないものも示します。何も書き込みません。相対パスはデータベースのフォルダー、次に現在のフォルダーから探します。ファイルが見つからない場合、ファイルがもうそのマッチを含まない場合（その指紋が保存されたマッチのものでない場合）、保存された手からファイルのどちらのプレイヤーかを判別できない場合、修復は拒否されます。サーバーは /v1/matches.repairで提供し、ソースファイルはリクエストで送信されます。

./blunderdb match repair --db <chemin> (--id <ID> [--dry-run] | --list) [--format text|json]

./blunderdb match repair --db base.db --list
./blunderdb match repair --db base.db --id 42 --dry-run
./blunderdb match repair --db base.db --id 42

tournament — 運営した大会を読む

グラフィカルインターフェースなしで、運営中のトーナメントを読み取ります。トーナメントを対話的に運営するのは Nicomaque エンジンのコンソールの役目です。これらのサブコマンドは読み取りのみで、入力を待つものはなく、書き込むのはmoveとconfirmだけです。

./blunderdb tournament <sous-commande> --db <chemin> [options]

サブコマンド：

  • list [--format text|json] — データベース内の運営済み大会と、その状態、エンジンのバージョン、それぞれが属するイベント（なければ空欄）、最後の決定の日付。

  • verify --id N [--format text|json] — 運営を再生し、残っている警告をすべて報告します。警告が残っていればエラー終了します。これは大会後の点検であり、シーズン分のデータベースにこれを流すスクリプトが欲しいのは終了コードであって、絞り込むための一行ではありません。

  • standings --id N — 賞金を含む順位表を CSV で、インターフェイスの言語で出力します。

  • ranking --season [--rencontre N] [--from AAAA-MM-JJ] [--to AAAA-MM-JJ] [--points 25,18,15] [--participation P] [--elo] [--format csv|json] — シーズンランキング。イベントまたは期間の終了済みの大会を対象とします（両端を含み、大会の日付で判定。フィルターがなければ運営したすべての大会）。各順位は配点表によってポイントに換算され（優勝者が先頭。既定は 25、18、15、12、10、8、6、4、2、1）、さらに参加した大会ごとに --participation が加わります。同順位は、占める順位の平均を分け合います。大会をまたいで、人物は名前で識別されます。--elo は、シーズンの対戦をやり直して算出したクラブ Elo（FIBS の式、初期値 1500）を加えます。CSV は 1 人 1 行、大会ごとに 1 列のポイント列を出力します。終了していない大会は一覧に載りますが、ポイントにはなりません。

  • page --id N|--rencontre N [--out <フォルダー>] — 種目の HTML 表示ページ（--id）、またはイベントの壁面ページ（--rencontre：どの種目が使っていてもテーブルごとに1行）。どちらか一方が必須です。--out なしなら標準出力へ、指定するとそのフォルダーに書き出され、以後そこが運営またはイベントのフォルダーになります。

  • export --id N — 生のイベントジャーナル。エンジンのツールで再生できます。ジャーナルは運営のすべての真実であり、順位表もトーナメント表も警告もそこから再生されます。この出力を読むツールに blunderDB は一切不要です。

  • move --id N --match M --table T [--format text|json] — 進行中のマッチのテーブルを変更します。グリッドでセルを別のセルへドラッグするのと同じ操作です。移動先のテーブルが使用中なら、2 つのマッチがテーブルを入れ替えます。使用停止中のテーブルは拒否されます。イベント内で、テーブルが別の種目に使われている場合は、2 つの種目の間で入れ替えます。テーブルの変更はそれぞれのログに記録されます。進行中の各マッチのテーブルを表示します。

  • hall --rencontre N [--format text|json] — イベントのすべてのテーブルです。どの種目が使っているかにかかわらずテーブルごとに 1 行（種目、マッチ、プレイヤー）を示し、続けてすべての種目の提案を一つの列で示し（proposal）、最も長く待っているプレイヤーが先になります。最後に、テーブルまたは空いているプレイヤーがないために保留されている試合を理由とともに示します（held）。Direction のすべてのテーブルビューが表示するグリッドです。イベントに会場がある場合、テーブルは会場ごとにまとめられ、名前を持つテーブルには名前が表示されます。

  • proposals --id N [--format text|json] — エンジンの番号付き提案リスト：試合、抽選、フェーズの移行、棄権したグループ進出者の繰り上げ。

  • confirm --id N --n K [--format text|json] — proposals の番号 K の提案を、パネルの 開始 と同じように確定し、続くリストを表示します。

  • tables --rencontre N|--tournament N [--format text|json] — テーブルのプロパティ（名前、会場、予約済み、割り当て先）と、イベントの各種目が行われる会場（--rencontre）、または単独で行われる種目のプロパティ（--tournament）を表示します。読み取り専用で、書き込みは call を通じて行います（rencontres.setTables、rencontres.setEventRooms、directions.setTables）。

共通オプション: --db（必須）、--id（list、ranking、page --rencontre、hall、tables 以外で必須）、--format。

例：

./blunderdb tournament list --db base.db
./blunderdb tournament verify --db base.db --id 3
./blunderdb tournament standings --db base.db --id 3 > classement.csv
./blunderdb tournament ranking --db base.db --season --from 2026-01-01 --to 2026-12-31 --elo > saison.csv
./blunderdb tournament page --db base.db --id 3 --out /tmp/affichage
./blunderdb tournament page --db base.db --rencontre 1 --out /tmp/evenement
./blunderdb tournament export --db base.db --id 3 > journal.json
./blunderdb tournament move --db base.db --id 3 --match m4 --table 7
./blunderdb tournament hall --db base.db --rencontre 1
./blunderdb tournament tables --db base.db --rencontre 1
./blunderdb tournament proposals --db base.db --id 3
./blunderdb tournament confirm --db base.db --id 3 --n 1

transcribe — 記譜を再生する

記譜を再生し、再生が見つけたものを報告します。ソースは.matファイル、ライブラリのマッチ、記譜の下書きのいずれか一つだけです。マッチはエクスポート時に生成される.matを通して読まれるため、再生されるのはエクスポートが含むはずのものです。

./blunderdb transcribe --mat <fichier> [--check] [--render <sortie>]
./blunderdb transcribe --db <path> --match <id> --check
./blunderdb transcribe --db <path> --draft <id> --check
./blunderdb transcribe --db <path> --match <id> --edit [--accept-losses]
./blunderdb transcribe --db <path> --draft <id> --finish|--abandon
./blunderdb transcribe --db <path> --materialize <document.json>
./blunderdb transcribe --db <path> --import <fichier.mat|document.json>

オプション：

  • --mat — 再生する.matファイル。

  • --db — データベース。--match および --draft 用。

  • --match — 再生するライブラリのマッチの識別子。

  • --draft — 再生する記譜の下書きの識別子。

  • --check — 見つかった不整合を列挙する（既定の動作）。

  • --render — 記譜をこのパスに.matとして書き戻す。

  • --format — 出力フォーマット：text（デフォルト）またはjson。

  • --edit — --match に対して下書きを開きます(すでに開かれている下書きがあればそれを返します)。

  • --accept-losses — 取り込み済みのマッチに対する --edit と併用:その分析とコメントが失われうることを受け入れます。

  • --finish — --draft を完了します:そのマッチを書き込むか、開いた元のマッチを置き換え、下書きを解放します。

  • --abandon — --draft を破棄します:マッチを作らずに削除します。開いた元のマッチはそのまま残ります。

  • --yes — マッチを一度も生み出していない下書きに --abandon を使うとき、その中に書かれたすべてが失われることを確認します。

  • --materialize — サイコロを含む JSON ドキュメント(header と actions)を、一度にマッチとして書き込むか、まったく書き込まないか。

  • --import — 新しい下書きを開く元となる .mat ファイルまたは JSON の転記ドキュメント。

--check は各不整合を、アクション番号とそれが属するゲームとともに示します。不正な手、同じプレイヤーが続けて二手、不可能なキューブ操作、マッチ終了後のアクション、自身のダイスを使っていない手、ゾロ目で指されたゲームの最初の手(オープニングロールはゾロ目になりえません)、記録されていない手、そして申告スコアの不一致です。記録されていない手とは、gnubg が実際に指された手を残さなかったときに書く ??? のセルであり、ダンスではありません。申告スコアの不一致とは、スコア行が前のゲームから導かれるものと異なるゲームであり、書かれたスコアで再生されます。

不整合は報告されるだけで、けっして拒否の理由になりません。不整合を理由に何かが拒まれることはなく、再生が何を見つけても終了コードは 0 のままです。ゼロ以外の終了コードは本当の失敗を示します — 読めないファイル、開けないデータベース、書き込めない出力です。所見に基づいて動作させたいスクリプトは--format jsonで読み取ります。そこでは壊れたファイルと不正な手を含むゲームが混同されません。

--render は記譜を.matとして書き戻します。これにより、テストの外で実際のファイルについて往復変換を確認できます。

--materialize は、よそから届いたアクションのドキュメントが表すマッチを、下書きを経ずに書き込みます。ルールは厳密に適用されます。最初に拒否されたアクションがあると、コマンドはその順位(0 から数えます)と理由を示して失敗し、何も書き込まれません。ドキュメントの判断時間(decision_ms、cube_decision_ms)は各手に引き継がれます。

--import は .mat ファイルまたは JSON の転記ドキュメント（header、actions、任意で format_version と next_score。下書きが保存される形式）から新しい下書きを開きます。ファイルの不整合は、どの下書きとも同じく保持され、マークされます。--finish がマッチを書き込む前に修正します。どの再生でも読めないファイル（読めない JSON、未知のアクション種別、盤外のプレイヤー・ダイス・ポイント、ゲームのない .mat）はコマンドを失敗させ、下書きを開きません。

書き込みを行う他のオプションは三つだけで、記譜パネルと同じメソッドを通します。--edit は既存のマッチに対して下書きを開き、--finish はそれを完了し(マッチは同じ識別子のまま置き換えられます)、--abandon はマッチを作らずに下書きを削除します。一度も完了していない下書きには --yes が必要で、書かれた内容はすべて失われます。取り込み済みのマッチは .mat に含まれない分析とコメントを持っています。--edit は最大でその件数を示し、--accept-losses がなければ拒否します。

例：

./blunderdb transcribe --mat match.mat --check

# match.mat: 7 point match, 4 game(s), 203 action(s)
#   Final score: 9-2
# Inconsistencies: none

duel — デュエルをプレイする

インターフェースなしで、1 回の呼び出しにつき 1 アクションずつデュエルを進めます。呼び出しごとに別プロセスとなり、データベースからデュエルを再開し、1 アクションを進めて書き戻します。この方法で進めたデュエルのムーブの所要時間は不明であり、ゼロではありません。

./blunderdb duel create --db <path> (--length <n> | --money [--jacoby]) [--side1 <côté>] [--side2 <côté>]
./blunderdb duel create --db <path> --length <n> [--start <XGID>] [--away <j1>,<j2>] [--reroll] [--after-cube] [--single-game] [--minutes-per-point <min> --delay <s>]
./blunderdb duel show --db <path> --id <id>
./blunderdb duel list --db <path>
./blunderdb duel move --db <path> --id <id> --play "24/18 13/11"
./blunderdb duel roll|double|take|pass|resign --db <path> --id <id>
./blunderdb duel forfeit --db <path> --id <id> --side 1|2
./blunderdb duel contribute --db <path> --id <id> --side 1|2 --value <texte>
./blunderdb duel stop|discard --db <path> --id <id>

サブコマンド：

  • create— デュエルを開始し、外部サイドの最初の判断まで進めます。--length(1~25 ポイント)または--money、--start(スタートの XGID)、--name1と--name2、--side1と--side2(external、またはinstant、normal、thoroughを伴うbot:<レベル>、または背後でプレイするボットを申告する外部サイドを表すexternal:<構成>@<エンジン>。マッチの由来はそれを、証明されたものではなく申告されたものとして記録します)を指定できます。--discard-at-endは、マッチを書き込まずに終了時に下書きを破棄します。--combined-seedは、各外部サイドがシードへの寄与を行うまでダイスを振りません。--awayは、最初のゲームのスコアを足りないポイントでプレイヤー1,プレイヤー2の形で指定し(1:クロフォードゲーム、0:その後の 1 ポイント)、--startのスコアを置き換えます。--startがなければ、ゲームはこのスコアで初期局面から始まります。--rerollは、--startが持つ出目を振り直します。--after-cubeは、スタートのキューブの判断の後から始めます(手番のプレイヤーはすぐに振り、提示されたダブルはテイクされます)。既定ではデュエルはその前から始まり、提示されたダブルは相手の答えを待ちます。--single-gameは、最初のゲームの終わりでデュエルを止め、そのゲームだけをマッチとして書き込みます。--minutes-per-pointと--delayは持ち時間を定めます。各プレイヤーの持ち時間をマッチの 1 ポイントあたりの分(Standard は 2、Speed は 0.4)で、手ごとのディレイを秒(12、10)で指定します。--time-out(continueまたはlose_match)は、持ち時間を使い切ったときの扱いです。ルール上認められないスタート(チェッカー、マッチ長を超えるスコア、両プレイヤーがクロフォードゲーム、キューブ)は、理由とともに拒否されます。2 つのボットの場合、マッチ全体がこの呼び出しの中で行われます(--side1 bot:instant --side2 bot:instant)。2 つのボットの間のマネーゲームのセッションは、1 ゲームのみの場合を除き、終わらないため拒否されます。

  • show— スコア、デュエルが待っているもの、ムーブの場合は合法的なプレイを表示します。サイコロのシードは終了前には表示されず、フィンガープリントがその代わりとなります。

  • list— 保留中のデュエル。

  • roll、move、double、take、pass、resign— デュエルが待っているサイドの 1 アクション(--side 1|2 で指定)。--playはムーブを記法で、任意の順序で渡します。--level(1~3)はリザインの価値を、--revisionはデュエルが進んでいる場合にアクションを拒否します。

  • contribute— 結合シードへの外部サイドの寄与(--side 1|2、--value、1~64 バイト)。最初のロールの前に一度だけ行えます。最後の寄与でダイスが始まります。ロールは、封印されたシードを鍵とし、各サイドの寄与をその長さを前置して並べたものに対する HMAC-SHA256 から得られ、マッチの由来は寄与を持ちます。

  • forfeit — --side のサイド（必須）がマッチを放棄します。進行中のゲームは、相手サイドをマッチの長さに届かせるポイントで相手のものとなり（マネーゲームではキューブの値でのシングル）、マッチは相手の勝ちとして保存されます。

  • stop — マネーゲームのセッションを終了し、そのマッチを現状のまま保存します。進行中のゲームは勝者なしです。ポイントマッチは拒否されます。最後まで終えたものだけが保存されます（forfeit、discard）。終了は放棄ではありません。

  • discard— デュエルを破棄します。何も書き込まれません。

すべてのサブコマンドが --db と --format(text または json)を受け付けます。
