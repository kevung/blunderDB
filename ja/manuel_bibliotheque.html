分析、コメント、検索

分析パネル

分析 パネル（CTRL-L）は、eXtreme Gammon（XG）、GNUbg、BGBlitz、または gammonNet からインポートした現在のポジションの分析データを表示します。最良の選択肢（チェッカーの手またはキューブの判断）を、そのエクイティ値と対応するエラーと共に提示します。d キーでチェッカーの手の分析とキューブの分析を切り替えられます。マッチを辿っているときは、実際にプレイされた手が選択肢のリストで強調表示されます。パネルを表示または非表示にするには、CTRL-L を押すか list コマンドを実行します。

解析のない局面はそのことを示し、評価ボタンで Eval パネルに開けます。

ツールバーのチャレンジボタン（pip カウントのボタンの後、キーm）は、局面を閲覧しながら解析を見る前に自分の答えを決めるためのものです：検索結果、マッチのレビュー、自分のミスの復習。有効にすると、パネルの解析全体（チェッカーとキューブ）を灰色の領域で覆い、領域をクリックすると表示されます。局面が変わるたびに覆いが戻ります。チャレンジは表示上のマスクであり、表示してもデータベースには何も記録されません。設定は pip カウントと同様に、blunderDB を閉じるまで保持されます。マッチのレビューでは、チャレンジは手の一覧の記号、損失、難度も隠します。表示中の手のものは、その解析とともに表示されます。

表の下に、打った判断が何を損したのか、なぜかを述べる 一文 が出ることがあります。「120 mp の損：着手はブロットを三個残しますが、13/7 8/7 なら一個です。」六つの測定可能な規則から作られます — 露出、作った／逃した自陣のポイント、手放したギャモン率、得より高くつく安全、そしてキューブの誤りの二つの向き（ダブルが遅すぎる／早すぎる、テイクが甘すぎる／パスが固すぎる）です。

肝心なのは 黙る という規則です。文が出るのは、規則が確信をもって当てはまり、しかも各エンジンが誤りだと一致する閾値を超えた損失のときだけです。それ以外のときは文が出ません。空の枠も「わかりません」もありません。誤った説明は説明がないより高くつきます。不正確なことを教えてしまうからです。

同じ文は、誤りを犯したその場にも添えられます。Anki カードの裏面では公開された分析の下に、決定の練習のクイズの判定ではmp単位のコストの下に表示されます。ここでも沈黙の規則は同じです。正しい手や、どの規則でも説明できない誤りには、何も追加されません。

ある局面を複数のエンジンが判断している場合、パネル上部の帯がそれらを並べます。エンジンごとに 1 行で、深さとその答え——キューブの判断、あるいはそのエンジン自身の最善手——を示します。まず一致しているかどうかを述べますが、この帯を正当化するのは不一致のほうです。「XG はダブル・テイク、gammonNet はダブルしない」が一目で読めます。以前は二つの表を斜めに見比べる必要がありました。

あるエンジンの最善手とは、そのエンジンにとっての最善手です。候補手の一覧はエンジンを問わずエクイティ順に並んでいるので、その先頭はどのエンジンの最善手でもありません。

この帯は、実際に複数のエンジンがある場合にだけ現れ、このパネルにしか存在しません。Eval パネルが示すのはひとつの判断、すなわち内蔵エンジンの判断です（ADR-0017）。比較の居場所はそこにはありません。

手はボード上で読むとおりに書かれます。ここでも Eval パネルと同じです：最も進んでいないチェッカーが先に動き、1 つのチェッカーが複数のダイスを続けて使う場合は一度だけ書かれます——同じチェッカーで打った 64 は 24/14 と読み、到着時にヒットすれば 24/14* です。経路の詳細が再び現れるのは、それが何かを付け加えるときだけです：途中でのヒットはその経由点を保ち、24/18* 18/14 と書きます。そうしなければ 18 でのヒットが表記から消えてしまうからです。

インポートされた解析のエクイティは Eval パネルと同じ規則に従います：列は自身の参照系を明示します——解析対象のポジションのスコアに応じて「Equity (money)」または「Equity (match)」であり、スケールを示さない単なる「Equity」にはなりません。マネーゲームのポジションで有効なJacobyルールとBeaverルールも、キューブ判断テーブルの下にバッジとして表示されます。

ロールアウト

解析パネルは局面をロールアウトできます。選んだ各ムーブ、またはキューブの各アクションから数百ゲームをプレイし、直接評価ではほとんど差が出ない二つの選択肢を区別します。候補ムーブの表で、Ctrl+クリックはムーブを選択に追加または除外し、Shift+クリックはクリックしたムーブまで選択を広げます。通常のクリックはこれまでどおり一つのムーブだけを選択します。選択範囲、または別のムーブ(そのムーブが選択になります)の上での右クリックでメニューが開き、ロールアウト(標準)を選ぶと、選択したムーブのロールアウトを選んだ設定ですぐに開始します。キューブの判断では、右クリックで判断全体をロールアウトします。パネルのShift+Rキーも同じ動作で(選択がなければ局面の上位候補をロールアウトします)、rolloutコマンド(別名 ro)も同様です。ロールアウト中は、表の下の細いバーがプレイ済みのゲーム数を示します。キャンセル、メニューのロールアウトをキャンセル、Esc、または再度Shift+Rで、何も書き込まずに停止します。設定(高速、標準、自由)は、設定のgammonNetタブで選びます(設定 を参照)。

同じメニューには局面と解析をコピーがあり、CTRL-X CTRL-Xがコピーする画像（盤面と候補手リストの上位、またはキューブ解析全体）をコピーします。手が選択されると、二つ目の項目局面と選択した手をコピーが追加されます。画像には選択した手だけが順位順に残り、各手には全候補の中での順位と、選択内の最善手ではなく局面の最善手からの差が付きます。キューブの判断では最初の項目だけが表示されます。解析表のセルはテキストとして選択されないため、選択のクリックで反転表示が残りません。

結果は解析の隣に保存され、解析を置き換えることはありません。インポートした解析は変更されません。ロールアウトした各ムーブは、表の自身の行に結果を持ちます。局面にロールアウトがある場合だけ表示されるRollout列に、エクイティと 95 % 信頼区間の半幅がエクイティ列の尺度で示されます。セルにカーソルを重ねると詳細が表示されます。標準偏差、JSD(最善手との差を差の標準偏差で表したもの。上限に達するとそのムーブは決着し、それ以上プレイされません)、ゲーム数、そして設定(エンジンとパラメータの完全なシグネチャ。シグネチャが同じ二つのロールアウトは同じ数値です)です。ロールアウトは、ムーブの優劣がついた時点で停止します。ムーブ行を持たないキューブ判断のロールアウトは、判断の下に表として表示されます。ロールアウトはゲームの中でキューブをプレイします。順位は信頼できますが、絶対的なエクイティはやや劣り、ブロックがそのことを注記します。ビーバーはプレイしません。ダブル/テイクの行は単純なテイクのもので、ビーバールールのマネーゲームの局面でも同様です(直接解析ではビーバーを数えます)。データベースにない局面はロールアウトできますが、保存されません。

ro search コマンドは、表示中の一覧(検索結果、マッチ、またはコレクション)のうち、このロールアウトをまだ持たない局面を一つずつロールアウトします。開始前に、確認ダイアログで総数が示されます。各局面は完了するたびに書き込まれます。キャンセルしても完了分は保持され、再実行すると中断した箇所から再開します。進行状況は、パネルを閉じても残ります。

別のインスタンスの blunderDB が保持しているために読み取り専用で開かれたデータベースは、保存されることになるロールアウトを最初から拒否します。最初のゲームをプレイする前に、メッセージでそのことが示されます。

コメントパネル

コメントパネル(CTRL-P)は、現在のポジションに関連付けられたコメントを表示、追加、編集します。ポジションには、異なる人が書いた複数のコメントを付けられます。すべてがスレッドとして新しい順に表示され、それぞれに著者名が付き、自分のコメントが先頭に来ます。XG ファイルからインポートされたコメントは、対応するポジションに自動的に関連付けられます。CTRL-P を押すか、comment コマンドを実行すると、パネルの表示と非表示が切り替わります。

コメントに帰属する名前は、環境設定の インターフェース タブにあるあなたの名前欄で設定します。空の場合、コメントには作者が付きません。XG インポートのコメントは XG に、マッチファイルのコメントはその書き起こし者に帰属します。コメントを書き直すと、あなたに帰属します。検索 au"Alice" は、Alice がコメントしたポジションを残します。インターフェース以外では、blunderdb comment add --author がその作者に帰属するコメントを書き込み、blunderdb comment list がそれを読み出します（コマンドラインインターフェース（CLI） を参照）。この名前は自由テキストであり、後述の署名と違って何も証明しません。

ファイルから来たコメントには出所ラベルが付く（XG、GNU BG、BGF、出所が記録されていない場合はインポート）。自分で書いたコメントには付かない。それが通常の場合であり、すべての行に印を付けても雑音にしかならないからである。インポートされたコメントを編集すると、それは自分のものになる：編集後、その文はあなたのものである。

この区別は別の場所にも現れる：マッチを削除しても、自分が書き込んだ局面はもう消えない。逆に、元ファイルから取り込まれたメモは、それを持ち込んだマッチとともに消える。

透かし付きでエクスポートされたデータベースで受け取ったコメントには、発行者の署名が付きます。スレッドには「発行者 のコメント」と表示され、続けてその鍵のフィンガープリントが、先頭に ✓ を付けて表示されます。同じ名前の人は二人いても、同じフィンガープリントの人はいません。発行者から伝えられたものと比べてください。

署名された内容と一致しなくなったコメントは保持されますが、⚠ 未検証 と表示されます。ファイル内でテキストまたは作者が変更された場合、コメントが別のポジションに移された場合、またはポジションの識別情報がその後修正された場合です。署名はポジションの識別情報を対象とするためです。 blunderdb repair があるポジションの Crawford 標識を調整して（必要なら対になるポジションと統合して）、またはマッチの修復があなたのメモを修正後のポジションへ移したとき、そのポジションが持つ署名付きコメントは、テキストが変わっていなくても検証できなくなります。 blunderdb repair はその件数を表示します。blunderDB が読み取れない署名は ⚠ 署名を読み取れません と表示されます。署名付きコメントを編集すると署名が外れ、その文はあなたのものになります。

別のデータベースから受け取ったコメントは出所を保ちます。作者が書いたメモは、あなたのメモと同様、マッチを削除してもそのポジションを保持します。XG ファイル由来の注記は XG のラベルを保ち、マッチとともに消えます。これは、すでにコメントに署名する版の blunderDB でエクスポートされたデータベースに当てはまります。より古いファイル由来のコメントには インポート済み のラベルが付き、マッチとともに消えます。 blunderdb comment list は、出所を Origin 列に、署名を Signed by 列に表示します。

タグ

タグとは、コメントに書いた #語 のことです。何も宣言しませんし、どのテーブルにも保持されません。これは意図したものです。語彙はあなた自身の文章であり、タグを付ける前に宣言を求めれば、習慣が事務手続きに変わってしまいます。

足りなかったのはもう半分でした。すなわち、自分が築いた語彙を見ることと、綴りを思い出す代わりにタグをクリックすることです。tags コマンド、またはパネルの見出し帯の # ボタンが語彙のウィンドウを開きます。このデータベースのタグが、それぞれそれを持つ局面の数とともに並び、クリックすれば対応する検索が走ります。リストの下には、このデータベースがまだ使っていない推奨タグが並びます。バックギャモンの文献から取った語彙（#blitz、#prime、#holding、#backgame、#containment、#crunch、#ace-point、#timing など）で、提案であって強制ではありません。この一覧にないタグも、あるタグとまったく同じだけの価値があります。

入力中に # を打つと、このデータベースがすでに使っているタグが、続いて推奨タグが提示されます。ある日は #back-game、翌日は #backgame と書いてしまうのを防ぐのはこれだけです。

タグ検索はコマンドラインで #prime と書きます。これは区切りを見る検索です。#prime は #priming を拾いません。部分文字列を探す通常のテキスト検索には、この二つを見分けられません。タグを複数書くと重なります。s #prime #backgame は両方を持つ局面を求めます。局面は複数のタグを持てるので、二つ挙げれば「両方」以外の意味になりません。局面がひとつの値しか持たないフェーズや出所のフィルタとは逆で、そちらでは二つ挙げれば「どちらか」の意味にしかなりません。

同じ一覧は、インターフェースの外からも blunderdb list --type tags で得られます（コマンドラインインターフェース（CLI） を参照）。

コンテキストメニュー

右クリック、または MENU キー、またはフォーカスのある行での SHIFT-F10 は、盤面で狙った局面でもコレクション内のその行でも同じメニューを開き、マッチ、トーナメント、コレクションの一覧の行では同じ形のメニューを開きます。局面に対する最も一般的な 2 つの操作、この局面を評価と画像をコピーは第 1 階層にあり、その他は ▸ の付いたサブメニューにまとめられています。

  • コピー / 共有: 画像 (CTRL-X)、XGID のみ、GNUbg ID (GNU Backgammon が set gnubgid で受け付ける局面 ID とマッチ ID。gnubgid コマンドでも得られます)、局面とその解析のテキスト (CTRL-C)、解析付きの画像、SVG または PNG で保存した画像。マッチでは .mat エクスポート。

  • 注釈: コメントは局面に対するコメントパネルを開きます。#タグを追加…は # を入力した状態でコマンドラインを開き、ENTER で # コマンドと同じようにタグを追加します (タグ を参照)。確認済みにすると確認済みを外すは学習キューの印を付けたり外したりします。

  • 移動: 近い局面、同じ構造の局面(盤面全体での構造検索)、この手でマッチを開く(その局面を指した最初のマッチを該当の手で開きます。どのマッチも通っていなければステータスバーが知らせます)、新しいビュー。

  • 解析: 局面、その鏡像、または新しいタブでの評価。高速ロールアウトと標準ロールアウトは ro fast および ro standard と同じです (ロールアウト を参照)。

  • 練習: 局面を Anki のデッキに追加します。この局面でチャレンジはチャレンジ (m) を有効にし、解析を隠します。

  • 管理: 検索盤面または Eval の下書きの保存(CTRL-S)、データベースの局面のゴミ箱へ移動(Del)。マッチでは、トランスクリプトの編集、プレイヤーの入れ替え、変更、ゴミ箱への移動。トーナメントでは、変更または削除。コレクションでは、変更またはゴミ箱への移動。

  • 送る：ポジションを … へコピー、マッチを … へコピー、トーナメントを … へコピー。開いている他のデータベースごとに一項目あり、「他のデータベース」パネルと同じコピーで、元に戻すで取り消せます。ロットに追加。ポジションには、コレクションに追加 …もあり、データベースのコレクションごとに一項目あります（比較と交換：「他のデータベース」パネル を参照）。

適用できる操作だけが表示されます。下書きは注釈もゴミ箱への移動もできず、検索盤面は評価できず、データベースにない局面はどの Anki デッキにも入らず、操作のないサブメニューは消えます。操作にショートカットがある場合は、その右側に表示されます。キーボードでは、↑ と ↓ で階層内を移動し、→ でサブメニューを最初の操作で開き、← で戻り、ESC でサブメニュー、次にメニューを閉じます。

ごみ箱

ポジション、コレクション、コメント、Anki カード、マッチの削除はごみ箱を経由します。削除は実際に行われますが、消えるもののコピーが三十日間保たれます。trash コマンドがそれらを一覧するウィンドウを開き、各項目に復元と削除、そしてごみ箱を空にするボタンが付きます。

復元されたポジションは解析とコメントとともに戻ります — 何もない状態で戻すのは名ばかりの復元です —。「学習済み」マークと、そのポジションで答えたトレーニングの回答も戻ります。元の番号に戻りますが、その間に同じポジションが保存されていれば、そちらが保持されます。ポジションは一つしか存在しないからです。そのポジションは、足りないマーク、回答、コメントを受け取り、解析があればそれを保ちます。番号が別のポジションに使われていれば、新しい番号を受け取ります。コレクションはそのリストとともに戻ります。含まれていたポジションは削除されていません — コレクションはそれらへのビューです。

削除されたマッチは、ゲーム、手、その解析、他に何も保持していないポジションを、ソースファイルのメモとともに持ち去ります。ゴミ箱はそれらすべてを保持します。復元すると、元の番号と元のインポート日で、ゲーム、手、統計とともに戻り、インポートのジャーナルが再びそのマッチを指します。削除で消えたポジションは復元されたポジションと同じように戻り、ライブラリに残ったポジションは現在の状態のままです。トーナメントの中の位置に戻ります。トーナメントが削除されていれば、トーナメントなしで戻ります。ディレクションの枠がまだ存在し、同じ対戦相手どうしで、空いていれば、その枠にも戻ります。そうでなければ枠はディレクターのものであり、マッチは枠なしで戻ります。これらの場合、ステータスバーがそれを知らせます。別のマッチがその番号を使っている場合、またはその間に同じファイル指紋のマッチがインポートされた場合、復元は拒否され、エントリはゴミ箱に残ります。指紋のないマッチ(手入力したもの、blunderDB で対局したもの)はこの方法で比較されません。

三十日より古いものは vacuum コマンドが削除するのであって、データベースを開くことではない：vacuum をしないことは、すべてを取っておくことである。

検索パネル

検索 パネル（CTRL-F または TAB）では、自由に組み合わせ可能な条件に従ってポジションをフィルターできます。チェッカーの構造、キューブの判断の種類、エラーの大きさ、日付、タグなどです。TAB キーは検索パネルとポジションエディターを同時に開き、ボード上で検索するチェッカーの構造を定義できます。

フィルターは 条件 サブタブで設定します。検索で何も見つからないときは、ステータスバーだけでなくパネルにも「一致する局面がありません」と表示され、フィルターを消去 ボタンが現れます。

表示中のポジションの中から検索するには、フィルターを続けた ss コマンドを使用します（例：ss nc、ss E>40）。ss は画面上のリストの中を検索します。直前の検索結果、開いているコレクション、またはレビュー中のマッチのポジションが対象で、コマンドを直接入力しても検索パネル（TAB）から入力しても同じです。パネルの 現在の結果内を検索 チェックボックスも同じ規則に従います。新しいタブで開く チェックボックスは、現在のビューではなく新しいビューに結果を表示します（ビュータブ を参照）。コレクションとマッチでは s は拒否されます。ライブラリ全体を検索して、表示中のリストを置き換えてしまうからです。

コレクションまたはマッチから実行した ss 検索の結果は、入力欄にもフォーカスのあるパネルにも閉じるもの（たとえば分析で選択した手）がなければ、 Esc を一度押すだけで抜けられます。blunderDB はコレクション全体、またはマッチの検討中の手に戻り、離れたポジションに戻ります。この戻り方は ss のあとだけです。コレクションやマッチから開いた検索パネルで実行した s はライブラリ全体を検索し、 Esc で元のリストには戻りません。

大規模なデータベースでの検索は、件数を数える前に表示されます。最初の結果ページがすぐに表示され、総数が分かるまでステータスバーに経過時間とともに「検索中…」が表示されます。総数が分かると、一覧の暫定的な長さが置き換えられます。同時に実行される検索は 1 つだけで、別の検索を始めると前の検索は破棄されます。Esc は実行中の検索を中断し、データベースの走査を止めます。最初のページがすでに表示されていた場合は、そのページだけが残り、ステータスバーがその旨を伝えます。

このパネルでは、検索する 判断タイプ を明示的に制御できます。 指定なし （フィルタなし）、 チェッカー （チェッカーの判断）、または キューブ （キューブの判断）です。 キューブ を選択すると、2つ目のリストでサブタイプを指定できます。 すべて 、 ダブル / ノーダブル （手番のプレイヤーがダブルするかを判断する）、または テイク / パス （相手のダブルへの応答）です。この制御は盤面と同期しています。盤面上でダイスやキューブを変更すると判断タイプが更新され、その逆も同様です。 テイク / パス モードでは、キューブが提示された値で盤面の中央に表示されます。この値は引き続き編集できます。

ゲームの段階——序盤、中盤、レース、ベアオフ——は、blunderDB が盤面だけから計算するラベルである。編集はできず、コマンドラインの ph: トークンで検索できる（ph:race、繰り返し可：ph:race ph:bearoff）。四つの境界のうち三つは GNU Backgammon がネットワークを振り分けるのに使うものであり、四つ目、すなわち序盤の終わりは blunderDB の取り決めである：どちらの側も出発点から四つを超える駒を動かしておらず、ベアオフした駒がなく、バーにも駒がない限り、局面はまだ序盤にある。

このラベルは blunderdb repair コマンドで再計算される。このバージョンで初めて開かれたデータベースでは、その開いた時点で一度だけ計算される。段階が一度も計算されていないデータベースは ph: に対して何も返さない——誤った答えではなく、何も返さない。

like トークンは絞り込むのではなく並べ替えます。これがあると、結果は目標局面からの距離の昇順に並びます。like は現在の局面、like42 は番号42の局面です。ほかのトークンは、そうして並んだ集合を絞り込みます。s like42 E>80 は「42の近傍のうち、自分が間違えたもの」と読めます。距離は二つの局面を隔てるチェッカーの移動量、すなわちチェッカーピップで表す輸送距離であり、視点は手番の側です。

近傍とは同じ 問題 であって、同じ絵柄ではありません。並べ替えは目標のクラスの内側で行われます。すなわち、同じ決定の種類、キューブの決定であれば同じ形式（マネーかマッチか）、そして目標自身とは別のマッチです。同じゲームの中で前後に並ぶ局面は、最も近い構造でありながら決して近傍ではないからです。ダイス、スコア、キューブはクラスの外に残り、必要なときは通常のトークンで絞り込みます。like42* はクラスをすべての決定の種類と両方の形式に広げますが、目標のマッチを含めることはありません。like<12 は十二チェッカーピップを超えるものを除きます。何も見つからない並べ替えは、無関係な十局面ではなく、空のリストを返し、そう告げます。

編集モードでは、s like は描かれた盤を目標にします。覚えている局面をおおよそ描いて実行すれば、ライブラリが答えます。構造による検索が正確な描画を要求するのに対して、です。このとき盤は模様ではなく局面として読まれます。空のままにしたポイントは上がった駒として数えられ、これは実在の局面には正しく、描きかけの盤では計算を狂わせます。

それぞれの近傍は、どの局面に近いのかとともに、解析表の下に距離を示します。見ているものが近傍なのか偶然の一致なのかは、これで判断できます。上限があるのもそのためです。並べ替えはコマンドラインを通さずにも起動できます。すなわち CTRL-SHIFT-L、または盤のコンテキストメニューの近い局面という項目です。

トークンnは遭遇を数えます。n>3は、データベースで（すべての対局とすべてのプレイヤーを合わせて）少なくとも3回出現した局面を残します。これは「何を間違えたか」とは別の問いです。20回出現してそのうち19回うまく打たれた局面は、それでも暗記しておくべき局面です。数えるのは対局ではなく判断です。同じ局面が1つの対局に2回出れば、判断が2つあったので2と数えます。プレイヤーフィルターと組み合わせると、そのプレイヤーの出現だけを数えます。n>3 pl!"Alice"はAliceが少なくとも3回打つことになった局面を、pl"Alice"は彼女が戦った対局の局面を残します。op"Bob"も同様に、数をBobとの対局に限ります。

戦型 はフェーズと並ぶ二つ目の派生ラベルで、保存済みフィルタの束では立てられない問いに答えます。「ホールディングゲームでの自分のミスを見せてくれ」です。トークンは gt:、繰り返し可（gt:holding gt:mutualholding）、手番の側 から見た、その判断が置かれていた戦型です。

認識される十の戦型を、規則が処理する順に、狭いものから広いものへ並べます：

  • race — 双方の最後尾のチェッカーがすれ違い、もはや接触は起こりえません。GNU Backgammon の境界です。

  • bearin — 手番の側が自陣にチェッカーを戻している一方で、相手はまだその自陣にアンカーを持っています。

  • crunch — 手番の側が自分の 1 番・2 番ポイントの外に持つチェッカーが六個以下です。GNU Backgammon の規則で、閾値はその作者のものです。

  • backgame — 相手陣に二つ以上のアンカー。

  • acepoint — アンカーは相手のエースポイントの一つだけで、ピップで二十以上の遅れ。

  • blitz — 自陣を三ポイント以上作り、相手はバー上か、その自陣に打てるブロットがある。

  • primevprime — 双方が四ポイント以上のプライムを持ち、それぞれ相手のプライムの背後にチェッカーを閉じ込められている。

  • mutualholding — 双方が高いアンカーを持つ。

  • holding — 手番の側が高いアンカーを持ち、相手は持たない。

  • contact — 接触があり、上のどの戦型にも当てはまらない。序盤はここに入ります。

このうち三つの規則は GNU Backgammon 自身のもので、出典があります。残りは blunderDB の取り決め です。バックギャモンの文献は戦型を語りますが、その境界に数字を与えてはおらず、この問題について分類器間の一致度の測定も公表されていません。出典のない閾値 — ブリッツの自陣三ポイント、プライムの四ポイント、エースポイントゲームのピップ二十の遅れ — はしたがってコードに隠さずここに書かれ、版が付けられています。変えて blunderdb repair を走らせれば、データベース全体が付け直されます。

コレクションパネル

Collections、Tournaments、Anki、Transcription の各パネルでは、ヘッダーの + ボタンと、それが作成するものの名前（+ 新規コレクション、+ 新規トーナメント、+ 新規デッキ、+ 新規記譜）が唯一の作成操作で、入力欄が開きます。Collections と Tournaments のパネルでは、Esc または キャンセル で閉じます。マッチ一覧では、⌨ アイコンでマッチの記譜を開き、✎ アイコンでそのメタデータを修正します。

コレクションパネル（CTRL-B）で局面のコレクションを管理します。コレクションは作成、名前の変更、削除ができます。局面の追加や取り除き（Del キー、確認を求められます）も可能です。コレクションをダブルクリックすると、左キーと右キーでその局面をたどれます。 ss コマンドは開いているコレクションの局面の中を検索し、その後 Esc でコレクションに戻ります（ 検索パネル を参照）。コレクションの並び順、およびコレクション内の局面の並び順は、ドラッグ＆ドロップで変更できます。CTRL-B を押すか collection コマンドを実行するとパネルの表示・非表示が切り替わります。

開いたコレクションの見出しでは、局面数がリンクになっており、最初の局面から閲覧に戻します。このコレクションに含むのチェックボックスで、表示中の局面を追加または削除します。空のリストでは+ 新しいコレクションを提案します。

パイルは「あとで見直す」操作のコレクションです。盤面の外でのダブルクリック、bキー、またはツールバーのブックマークボタンで、表示中の局面がパイルに載り、同じ操作で外れます。盤面の隅のブックマークが、その局面がパイルにあることを、ほかのメッセージなしで示します。この操作は、局面が表示されるすべての場所で使えます。レビュー、検索、編集、Eval、トランスクリプト、クイズ、デュエルです。盤面のリセットは、右クリックのメニュー（盤面のメニューを参照）から行います。パイルは通常のコレクションで、ほかと同じように名前の変更、並べ替え、エクスポート、空にすることができます。初回の使用時に作成され、削除された場合は作り直されます。まだライブラリにない局面（検索盤面や評価盤面の下書き）は、単独で持ち込んだ局面と同じようにその場でライブラリに書き込まれ、そのあとパイルに載ります。コマンドラインではcollection pileで同じ操作を行います。

コレクションは 生きた ものにできます。その内容は手作りのリストではなく 検索 の結果になり、開くたびに再評価されます。コレクション見出しの ◇ ボタンが直近の検索でそれを生きたものにし、◈ はすでにそうであることを示します。同じボタンでリストに戻せます。生きたものにしても何も壊れません。含まれていた局面は戻ったときにそのまま残っています。

ライブコレクションに表示される ❄ ボタンは、そのコレクションを固定します。その時点で検索が選ぶポジションが、検索の順序のまま通常のコレクションの内容となり、クエリは消去されます。ライブになる前に保持していたポジションは置き換えられます。

このバージョンがもう知らないトークンを含む問い合わせを持つ生きたコレクションは、データベース全体を返すのではなく、開くことを拒み そう告げます。保存された絞り込みが決して起こしてはならない唯一の故障が、黙って広がることだからです。

ライブコレクションは、データベースのエクスポート後もライブのままです。クエリはコレクションと共に運ばれ、受け取った側でファイル内のポジションに対して再評価されます。エクスポートがコレクションのポジションを含める場合、エクスポート時点でクエリが選ぶポジションが含まれます（上限は 5,000 ポジション）。ポジション、マッチ、トーナメントを番号で指定するクエリは、ファイル内の番号に書き換えられます。そのいずれかがファイルに含まれない場合、コレクションは固定され、エクスポート時点でクエリが選ぶポジションを持って書き出されます。

ライブコレクションに基づく間隔反復デッキは、セッションを開くたびにそのクエリを再実行します。前回以降に検索が選んだポジションがデッキに加わり、すでにあるカードはスケジュールを保ちます。評価は 5,000 ポジションの上限で制限されます。クエリがそれより多く選んだ場合、検索の順序で最初のものだけがデッキに入り、ステータスバーが実際に選ばれたポジション数とともにそれを知らせます。

ヘッダーの提案…ボタンは参照ポジションを開きます。これは学習すべきポジションの短いリストで、それぞれが多くのミスを要約するようにあなたのミスの中から選ばれます。最悪のミス 10 件を学習すると、同じ問題の 10 通りの変形や、他について何も教えない特異なポジションになりがちです。参照ポジションは、構造の近いあなたの複数のミスの中心にあり、その教訓がすべてに役立ちます。

  • ミスは学習プランのものです。MWC で数値化され、ファミリー(ゲームプラン、性質、テーマ)ごとに整理されます。同じファミリーの 2 つのミスは、like 距離で最大 12 チェッカーステップ以内なら隣接しています。キューブのミスの隣接は同じスコアのものだけです。

  • 各ポジションの価値は、その隣接ポジションと自身の回収可能な MWC(損失から難易度を引いたもの)、つまりその教訓がすべてに役立つ場合に得られるものです。僅差の教訓(2 番目の選択肢のコストが半ミス未満)や不安定な判定(別の深さやロールアウトが異なる結果を示す)は半分として数えられます。裏付けるロールアウトがあれば表示されます。 各行の先頭の数字はカバーする MWC で、理由は教訓が半分として数えられるときに数えられる値を示します。

  • リストは多様です。選ばれたポジションは隣接ポジションをカバーし、それらは以降のポジションに何ももたらさず、提案されるポジションにほぼ重複するものはありません。処理済みのポジション(コメント付き、コレクション内、Anki カード、または「学習済み」マーク付き)は提案されず、その隣接ポジションはカバー済みとみなされます。

範囲はデータベース全体、現在のマッチ、トーナメント、または統計パネルのフィルターで、プレイヤーはこのフィルターのものです。サイズは 10、20、50 ポジションです。各行には、ファミリー、キューブの場合はスコア、カバーする MWC とその理由が表示されます。理由とは、要約するミスとマッチの数、あなたの判断の中でのファミリーの大きさ、自身の回収可能分、2 番目の選択肢との差です。行をクリックするとポジションが開き、チェックしたボックスはワンクリックでコレクション、Anki デッキ、またはクイズになります。コマンドラインでは blunderdb collection suggest(collection — コレクションを管理するを参照)を使います。

レッスン

レッスンとは、コーチが生徒のために一度だけ書き、データベースファイルで渡すステップの並びです(コマンドラインインターフェース（CLI） の lesson export コマンドを参照)。各ステップにはタイトルとテキストがあり、コレクション、ポジション、その両方、またはどちらも表示しないことができます。le コマンドはデータベースのレッスンをステータスバーに一覧表示し、le 2 はレッスン 2 を開き、le edit はレッスンエディタを開きます。

すると盤の上に読み取りバーが表示されます。レッスン名、ステップ番号、タイトル、そしてテキストです。前へと次へでステップを切り替えます。ステップは、表示するコレクションまたはポジションを盤に呼び出し、それを通常の操作で閲覧できます。閉じるでレッスンを終了します。コレクションまたはポジションが削除されたステップも、テキストは残ります。

バーのステップ完了ボックスは、現在のステップを完了としてマークします。もう一度クリックするとマークが外れ、バーは完了したステップの数を表示します。何かを書き込む操作はこれだけです。レッスンを読む、ステップを変える、レッスンを開くといった操作では、到達したステップも開いたことも記録されません。マークは開いているデータベース(生徒のもの)に書き込まれ、どのエクスポートにも含まれません。レッスンを含むファイルをインポートするとそのレッスンが作成され、同じ名前のレッスンがすでにある場合は変更されません。

レッスンエディタは、le edit (レッスン 2 なら le edit 2) または閲覧バーの編集ボタンで開きます。左にレッスンの一覧と新規作成用のフィールド、右に選択したレッスンの名前と説明、続いてそのステップが表示されます。各ステップにはタイトル、テキスト、一覧から選ぶコレクション、ポジションがあります。現在のポジションはボード上に表示中のポジションをステップに付け、ポジションを外すはそれを外します。ステップを保存は変更を書き込み、矢印でステップを 1 つ移動でき、ステップを追加は末尾に 1 つ追加します。読むはエディタを閉じてレッスンを最初のステップで開きます。Webページとして書き出すはレッスンを単体の HTML ファイル 1 つに保存します(タイトル、説明、各ステップのテキストとボード、各ポジションの保存済み解析をクイズの答えのように折りたたんだもの、フッターの透かしの出所)。そのまま公開でき、スクリプトもネットワーク呼び出しも含みません。削除はレッスンとそのステップを消しますが、ステップが表示していたコレクションやポジションには触れません。レッスンはコマンドラインや API からも作成・変更できます(レッスン)。

バックアップ（エクスポートウィンドウまたはコマンドラインによるライブラリ全体のエクスポート）は、すべてのレッスンを持ち出します。エクスポートウィンドウでは、レッスンの行でレッスンを一つずつ選びます。チェックを入れたレッスンは、その手順が示すコレクションとポジションとともに出力され、ファイルは他のエクスポートと同様に透かしを付けたり、パスワードで保護したり（.dbx）できます。このチェックボックスがない部分エクスポート（ポジション、コレクション、マッチの選択）では、レッスンは持ち出されません。
