付録：統計モデル — XG / gnuBG / blunderDB の整合

このページでは、blunderDB が表示する指標——PR（Performance Rating）、Snowie Error Rate、MWC の損失、運、勝敗——をどのように計算し、それらが eXtreme Gammon（XG）および gnuBG（公開された基準）とどう一致するかを説明します。

    • PR（Performance Rating）

    • Snowie Error Rate

    • MWC 損失（Match Winning Chance）

    • 運（luck）

    • 勝敗

    • エラーとブランダー

    • 既知の残差

正式な定義

PR（Performance Rating）

PR は、カウントした判断 1 回あたりの平均エクイティ誤差を、eXtreme Gammon に倣って 500 倍した値です。

\[\mathrm{PR} = \frac{\sum_i |\mathrm{error}_i|}{\mathrm{N_{counted}}} \times 500\]

  • 分子は正規化エクイティ（スコア時の EMG）で表した誤差の総和で、各誤差はそのマッチで指した手のものです。

  • 分母 \(N_\text{compté}\) は XG の規則に従って判断を数えます。強制でないチェッカー移動、提案されたダブル、テイクとパス、および近い「ノーダブル」です。これらの規則、その理由、限界は PR (Performance Rating) で詳しく説明します。

  • 係数 500 は XG の慣例です。ミリポイントへの換算ではありません。平均誤差 0.010 のエクイティ、つまり 10 ミリポイント (mpt) が PR 5.0 になります。一方、1 つの局面の誤差はミリポイント、すなわちエクイティの 1000 分の 1 で読むのが適切です。後述のブランダー閾値、検索フィルタ e> と E>、Stats パネルの大きさのヒストグラムがそうです。

Snowie Error Rate

Snowie の ER は PR と同じ分子を用いますが、分母は両プレイヤーのチェッカームーブの数であり、強制手を含み、いかなる集計規則も適用しません。

\[\mathrm{SnowieER} = \frac{\sum_i |\mathrm{error}_i|}{N_\text{P1} + N_\text{P2}} \times 500\]

参照：gnubg/formatgs.c:415–424。

Snowie ER はツール間でより安定しています。分母が判断のカウント規則に依存しないためです。XG ↔ gnuBG ↔ blunderDB の突き合わせ用の指標として使います。

重要

「プレイヤー」フィルタは分子にしか効きません。プレイヤーを選ぶと、合計されるエラーはその人自身の決定に限られますが、分母はフィルタが残した対戦における両者のチェッカープレイ数のままです。これが Snowie ER と PR の違いであり、次の性質の理由でもあります。2人の対戦だけを収めたデータベースでは、2人の Snowie ER の和は、フィルタなしの Snowie ER にちょうど一致します。

注釈

プレイヤーの Snowie ER は通常 PR の約半分です。分母には両プレイヤーの手が含まれるのに対し、PR はそのプレイヤーの決定のみを使用するためです。

MWC 損失（Match Winning Chance）

MWC 損失は、プレイヤーのエラーの累積効果を、マッチに勝つ確率のパーセンテージポイントで表します。各決定について、EMG エラーは現在のスコアにおける MET（Match Equity Table）を使用して MWC に変換されます：

\[\mathrm{MWCLoss} = \sum_i \mathrm{eq2mwc}(\mathrm{erreur}_i, \mathrm{score}_i)\]

テイクまたはパスは、ダブル前のキューブで換算します。ダブルを提案した側の判断や XG と同じです。換算とその限界は 判断あたりの MWC 損失とマッチのグラフ で詳しく説明します。

運（luck）

ある1ロールの運とは、実際に出た目がもたらしたものと、平均的にもたらされるものとの差です。

\[\mathrm{luck} = \mathrm{eq}(\text{出た目での最善手}) - \frac{1}{36}\sum_{d} \mathrm{eq}(\text{目 } d \text{ での最善手})\]

この和は、その1ロールの36通りの出目にわたります（ゲーム最初の手だけはゾロ目になりえないため30通り）。値が正なら有利な出目だったことを意味します。参照：gnubg/analysis.c:199–269（LuckNormal / LuckFirst、0 ply のキューブフル評価）。

重要

blunderDB は運を決して計算し直しません：内蔵の評価器はそのためのものではありません。対戦を分析したツールが書き込んだ値をそのまま用います——eXtreme Gammon なら ErrLuck、gnuBG なら LU プロパティです。両者が同じ規約（同じ単位、正なら幸運）を用いていることは確認済みです。

実際上の帰結：

  • 運を運ばない形式（BGF、Jellyfish の .mat）からは、値はまったく得られません。

  • すでにインポート済みの対戦にもありません。スキーマのバージョン 2.15.0 より前は運が保存されておらず、データベース内のどこからも復元できないからです。取得するには元ファイルを再インポートする必要があります。

  • 値がないことは不明を意味し、ゼロを意味しません。ゼロは本当に中立だった出目です。したがって運の平均は、運が判明している出目の数だけで割ります。

  • すべての出目の運がちょうどゼロになる対戦は、この点については未分析とみなします（eXtreme Gammon は「中立」にも「未計算」にも 0 を書き込むためです）。その対戦の出目は不明のままです。gnuBG では区別が明示的で、評価されていない出目には LU[-inf] が付きます。これらの出目も、値に変換せず不明のままにします。

勝敗

blunderDB はマッチ単位の勝者を保存しません。保存するのは各ゲームの得点だけです。したがって結果は表示時に、席ごとの得点を積み上げて導出されます。

  • N ポイントマッチ— 勝者は N に到達したプレイヤーです。誰も到達しなければ、その対戦は未了（記録の途切れ、投了）であり、誰の勝ちにも負けにも数えません。

  • マネーゲーム（目標点なし） — 勝者は得点の多い側です。同点なら勝ちでも負けでもありません。これは gnuBG のセッション結果の規約（+1 / 0 / −1、gnubg/relational.c）に従っています。

プレイヤータブを読むときに知っておくべき帰結：勝ち数 + 負け数は対戦数より少なくなりうるということです。その差が未了の対戦です。

エラーとブランダー

ある決定は、対応するエクイティエラーがライブラリのエラー閾値に達した時点でエラーとして数えられ、そのブランダー閾値に達した時点でブランダーとして数えられます。どちらも設定のライブラリタブで調整し、既定では0.050と0.100 EMG（50 と 100 ミリポイント）です。比較はその値を含みます。ちょうど 0.100 のエラーは既定の閾値ではブランダーであり、これはすべての画面（キューブの決定別の内訳、マッチの詳細、プレイヤー表）で同じです。また、同じ組がステータスバーのカウンターと、インポート後に提示される一覧にも使われます。

これらの閾値はライブラリごとに固有で、既定値は blunderDB 固有です。gnuBG は手を単一のカテゴリではなく三段階に分類します（0.03 疑問手、0.06 悪手、0.12 大悪手 — gnubg/gnubg.c:281–286）。eXtreme Gammon は自身の閾値を 0.020 と 0.080 に置いています。設定には三つのプリセットがあります：blunderDB（0.050 と 0.100）、XG（0.020 と 0.080）、GNUbg（0.040 と 0.080）。

カウントされる判断：XG と gnuBG

blunderDB は XG と同じ方法で判断を数えます (PR (Performance Rating))。gnuBG は別の規則に従うため、同じ解析から計算しても、その判断あたりの率を XG の PR と比較することはできません。

blunderDB ↔ XG ↔ gnuBG の対応

指標は以下の限界内で一致しています。これらは平均的な差ではなく、テストスイートで検証される上限です。テストは blunderDB の数値を、リポジトリの基準マッチに記録された数値とマッチごとに比較し、1 つでも差が上限を超えると失敗します。XG の基準は 7 点マッチ 5 つの両プレイヤー分、gnuBG の基準はそのうち 2 つです。これらの数値を出した eXtreme Gammon のバージョンは記録されていません。

既知の残差

基準マッチの 4 人のプレイヤーは差がより大きく、それぞれファイルが保持しない情報に起因します。

  • 未解析の手（2 人）。XG は評価しなかった手に −1000 の誤差を書き込み、カウントから外します。この値はインポート時に読まれず、blunderDB は保存された候補手からその手を評価します。blunderDB は判断を 1 つ多く数え、PR は最大 0.09、MWC 損失は最大 0.45 点ずれます。

  • ファイル外で判断されたベアオフ（1 人）。XG は、保存された候補手がすべての合法手を同じエクイティでカバーしているベアオフを判断として数えます。ファイルに保存されていない評価に基づいて判断したためです。blunderDB は判断を 1 つ少なく数え、PR は 0.02 ずれます。

  • チェッカー誤差の合計（1 人）。判断数とキューブは一致しますが、保存された手の誤差の合計が XG のチェッカー合計を数ミリポイント上回ります（2.150 対 2.147）。

注釈

SGF ファイル（gnuBG）は強制手の代替手を含まないため、blunderDB は SGF インポート時にすべての強制手を検出できません。これにより Snowie ER に構造的な差が生じます（分母がわずかに異なる）。

自分の数値を検証する

PR または MWC の値が XG の数値と乖離する場合は、以下の点を確認してください：

  1. 完全な解析 — PR は解析のあるポジションのみで計算できます。解析のないポジションはエラーゼロとしてカウントされますが、\(N_\text{counted}\) には含まれません。

  2. XG バージョン — XG はバージョン間で計算を変更する場合があります。blunderDB は最近のバージョンで観察された動作に合わせています。

  3. インポート形式 — gnuBG の SGF ファイルは、ファイルにすべてのキューブの決定の完全な解析が含まれていないため、キューブ指標でより大きな差が生じます（上記の表を参照）。

  4. データベースの移行 — blunderDB の更新後、既存のデータベースは自動的に移行されます。新しいバージョンでデータベースを開く前にバックアップを作成してください。
