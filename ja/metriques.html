指標と学習ツール

blunderDB があなたのプレイについて表示する各数値は、ひとつの問いに答えます。このページはそれらをまとめ、各数値について、答える問いと学習への貢献、定義、正確な式、何を判断として数えるか、単位、読み方、不確実性、限界、eXtreme Gammon (XG) と GNU Backgammon (gnuBG) の数値との違いを示します。数値を表示する画面は マニュアル で説明しており、リンクはそこへ誘導します。

このページの閾値とパラメータは、実際の結果を調べる前に決めました。後から調整すると、数値に期待どおりのことを言わせることになってしまいます。

判断の誤差と損失

すべての測定は、判断ごとの 2 つの量から出発します。

誤差 e は、インポートした解析 (XG または gnuBG。blunderDB は統計のためにマッチを再解析しません) の最善の判断と比べて、指した判断がエクイティで何を失ったかです。正規化エクイティで表し、±1 は現在のキューブに相当します。マネーでもマッチスコアでも同じです (スコア時の EMG)。千分の 1 (ミリポイント、mpt) に丸めます。

  • チェッカー移動：最善候補のエクイティから指した手のエクイティを引いた値。

  • ノーダブル：解析が示す「ノーダブル」の誤差。

  • ダブル：「ダブル、テイク」と「ダブル、パス」の誤差のうち小さい方。ダブルを提案した側は、相手の最善の応答で判断されます。

  • テイクまたはパス：指した応答と 2 つのうちの最善との差。

誤差はそのマッチで指した手のものです。2 つのマッチに現れ、異なる指し方をされた局面には 2 つの誤差があり、どちらも他方を上書きしません。指した手が解析のどの候補にも挙がっていない場合、誤差はありません。評価されず、すべてのカウントから外れます。

MWC 損失 ℓ は、同じ誤差をマッチの勝率 (Match Winning Chances) で表したものです。判断時のスコアとキューブ v では次のようになります。

\[\ell = e \times \frac{\mathrm{MWC}_{+v} - \mathrm{MWC}_{-v}}{2}\]

ここで \(\mathrm{MWC}_{+v}\) と \(\mathrm{MWC}_{-v}\) は、このスコアでプレイヤーが v 点を獲得または失った場合のマッチ勝率です。マッチ・エクイティ・テーブル (MET) は Kazaross-XG2 で、25 点を超える部分は Zadeh の式で延長しています。ポスト・クロフォードのスコアはそのまま読みます。テイクまたはパスは、ダブル提案者や XG と同様、ダブル前のキューブで換算します。ダブル後のキューブで換算すると、応答の誤差は 2 倍のコストになってしまいます。マネーゲームには MWC がなく、ℓ は存在しません。

この 2 つの量は加法的です。以下のすべての指標は、それらの和を異なる分母で割るか、基準と比較したものです。

PR (Performance Rating)

問い。 誰もが知っている尺度で、自分の実力はどのくらいか。PR はランキング、フォーラム、クラブで使われる数値で、自分の位置を知り、XG が解析した 2 つのマッチを比較できます。

式。 プレイヤーのカウントした判断について：

\[\mathrm{PR} = 500 \times \frac{\sum_i e_i}{N_\text{compté}}\]

係数 500 は XG の慣例です。PR 5.0 は平均誤差 0.010、つまりカウントした判断 1 回あたり 10 mpt に相当します。PR は単位のない平均で、低いほど良いプレイです。

判断として数えるもの。 規則は XG のものであり、その数値とマッチごとに照合して検証しています (付録：統計モデル — XG / gnuBG / blunderDB の整合)。

  • チェッカー移動が強制なのは、ロールで合法手が 1 つしかない場合、または解析がすべての合法手 (blunderDB の手生成器で数えます) をカバーし、すべてが千分の 1 まで同じエクイティの場合です。どの手でもコストがかからない選択は、判断ではありません。これは「強制ではないが影響のない」手 (勝負がついたレースの終盤、どれを選んでも同じベアオフ) に関する XG の規則です。合法手を数えられない場合は、候補が 1 つだけのときに限り、その手は強制となります。

  • ノーダブルは、プレイヤーがダブルに近かったときに数えます。ダブルしない場合のエクイティ (ND) が正であり、相手にとってのダブルの最善の結果 min(D/T, D/P) を 0.200 未満の差で上回っている場合です。D/T だけでなくこの最小値と比べることで、「強すぎる」局面も、パスの値から 0.200 以内にある限り判断として残ります。

  • 条件 ND > 0 は、手番のプレイヤーが劣勢で、ダブルを考える余地のない局面を除外します。XG も同様に除外しますが、そのマニュアルには書かれておらず、基準マッチがそれを示しています。

  • キューブ解析のないキューブ判断は、数えられるノーダブルになりません。

読み方。 Stats パネルのレベル帯 (Stats パネル) は blunderDB 独自の目安であり、公表された基準ではありません。PR はまず自分の PR と比較してください。同じ解析器、同じタイプの相手、同じ長さで比べます。

不確実性。 1 マッチの PR はノイズが非常に大きく、7 点マッチの標準誤差は PR で 1.5 程度です。blunderDB はマッチのゲーム、および集計のマッチを再標本化して 95 % 区間 (95 % 区間) を示します。

限界。 分子は何にも依存しませんが、分母は何を数えるかに依存します。0.001 と 0.200 の閾値は恣意的です。上達しなくても PR を下げることはできます。レースに判断を加えるために接戦のパスを選んだり、ベアオフで判断がひとつ増える手を選んだりする場合です。PR はキューブ 8 での誤差をキューブ 1 での誤差と同じ重みで扱い (エクイティはキューブで正規化されています)、DMP での誤差を 0-0 での誤差と同じに扱います。エンジンの不完全さを引き継ぎ、難しい局面を作る相手は他方の PR を押し上げます。MWC 損失 と 難易度 は、この 3 つの欠点に対応します。

XG と gnuBG。 XG ファイルでは、blunderDB の PR は、付録：統計モデル — XG / gnuBG / blunderDB の整合 で説明した差を除き、XG の表示精度の範囲で XG の PR と一致します。gnuBG は同じ和を別の数で割ります。合法手が複数あるすべての手と、独自の窓で近いと判断したキューブ判断です。したがってその判断あたりの率は、同じ解析でも XG の PR とは比較できません。Snowie Error Rate (付録：統計モデル — XG / gnuBG / blunderDB の整合) は両プレイヤーのすべての手で割ります。カウント規則に依存しませんが、PR のおよそ半分の値になります。

判断あたりの MWC 損失とマッチのグラフ

問い。 このマッチで、どの判断が私に損をさせたか。PR はすべての誤差を同じ尺度に載せ、ℓ は誤差が起きたスコアで重みづけします。5 点マッチの 4-4 での 0.040 の誤差は、17 点マッチの 0-0 での同じ誤差と同じコストではありません。学習のために、列とグラフはマッチを決めた少数の判断を示し、累積曲線はマッチがどこで傾いたかを示します。

定義。ℓ(判断の誤差と損失)を PR に数えられる各判断について求めます。マッチにおけるプレイヤーの損失は、これらの判断にわたる Σℓ です。集計対象外の判断(強制手、ウィンドウ外のノーダブル)には ℓ がありません。いずれにせよ、損失はゼロかほぼゼロだからです。

単位。 マッチ勝率のパーセンテージ。2.5 は MWC を 2.5 % 失ったことを意味します。

読み方。 トランスクリプトの MWC 列、判断ごとのバー、各プレイヤーの累積曲線は マッチパネル で説明しています。突出して高い孤立したバーは見直すべき判断です。着実に上昇する曲線は、事故ではなく平均的な誤差が重なったマッチを表します。

不確実性。 ℓ は解析に対して正確です。その不確実性は解析自体（深さ、ロールアウトの有無）と MET の不確実性です。

限界。 ℓ は MET に依存します。異なるテーブルを使う 2 つのソフトウェアは同じ損失を出しません。マネーゲームにはなく、データベースと異なる MET で計算された解析は統計の対象外のままです。評価されていない判断にはハイフンが付き、ゼロにはなりません。

XG と gnuBG。この合計は、XG がマッチについて表示する MWC 損失です。基準マッチでは、チェッカームーブ、ダブル、応答のいずれも XG の表示精度で一致します(差はテストスイートにより 0.06 パーセントポイント以内)。ただし、付録：統計モデル — XG / gnuBG / blunderDB の整合 に記載の既知の残差があるプレイヤーは例外で、最大 0.45 ポイントです。gnuBG も独自のエクイティで同じ換算を行います。gnuBG が解析したマッチでは、XG との数値の違いは公式ではなく解析によるものです。

MWC 損失（7 点等価）L₇ とエンジンに対する Elo

問い。 判断の数え方にかかわらず、自分の誤りでマッチをどれだけ失ったか。5 点マッチと 11 点マッチをどう比較するか。L₇ は判断数で割りません。簡単な判断を足しても操作できず、各誤差をそれが実際に失ったとおりに重みづけます。

定義。 完全なプレイの下では、マッチの勝率は偏りなく推移します。完全な相手に対して、マッチで MWC を L 失ったプレイヤーは、q = 0.5 − L の勝率を保ちます。FIBS の式のモデルによれば、実力が同じなら損失は長さ N の平方根に比例して増えます。そこで L を、トーナメントで最も一般的な長さである 7 点マッチに換算します。

\[L_7 = L \times \sqrt{7 / N} \qquad L_7^\text{agrégat} = \sqrt{7} \times \frac{\sum L}{\sum \sqrt{N}}\]

集計(複数のマッチ、1 人のプレイヤー、1 つのトーナメント)は、比を取る前に損失と長さの平方根をそれぞれ合算します。7 ポイントマッチは 1 ポイントマッチより重く、単一マッチはそのマッチ自身の値を返します。プレイヤーフィルターがない場合、マッチの 2 つの席はそれぞれ √N の重みを持ちますが、区間では 1 単位として扱われます。

エンジンに対する Elo は、FIBS の式を 7 点で逆算します。

\[D = \frac{2000}{\sqrt{7}} \log_{10} \frac{q}{1 - q}, \qquad q = 0{,}5 - L_7\]

線形化すると D ≈ −3474 × L / √N です。L₇ ≥ 50 % では q に有限の逆関数がありません。L₇ > 49 % から q は 1 % を下限とし(D ≥ −1509)、Elo は「≤」付きで表示されます。L₇ 自体に下限はありません。どちらも同じ順序でプレイヤーを並べます。

単位。 L₇：MWC のパーセンテージ。D：Elo ポイント。負の値で、プレイヤーとエンジンの間の期待される差です。

読み方。 12.3 %：エンジンに対して 50 % の勝率があるはずが、7 点マッチで 37.7 % しかなかったということです。バッジ、詳細、統計、トーナメント、進捗に表示されます (MWC 損失（7 点等価）)。

不確実性。 1 マッチではゲーム、集計ではマッチによる 95 % 区間 (95 % 区間) で、値と同じ変換を適用します。統計のマッチごとの行には区間がありません。単位が 1 つだからです。マッチの総括がゲームによる区間を示します。

限界。 √N モデルは 7 点未満とクロフォード付近では近似的です。L₇ は MET に依存します。マネーゲームには長さがないため L₇ もなく、画面は数値を表示する代わりにそのことを伝えます。実際のプレイヤーは半マッチ以上を失うことがあります。形勢が逆転した後の誤りが積み重なるためで、その場合 Elo は下限に達します。

XG と gnuBG。 7 点マッチでは、L₇ は XG が表示する MWC 損失そのものです。どちらのソフトウェアも、損失を基準の長さに換算したり Elo に変換したりしません。この Elo はエンジンとの差を測るもので、人間のプレイヤー間の FIBS や BMAB のレーティングではありません。

難易度、回避可能な誤り、超過、比

問い。 この誤りは許容できるものだったか。同じ 2 % の損失でも、自明な局面では不注意であり、4 つの手が千分の 1 の差で並ぶ局面ではどんな上級者でもする誤りです。学習のために、難易度は誤りを仕分けします。回避可能な誤り（不注意、覚え違いの規則）はすぐ直せるので先に扱い、難しい判断での損失は基礎的な取り組みの対象です。

定義。 難易度 d は、同じ局面で基準プレイヤーが平均して被る損失です。基準プレイヤーは各選択肢 i を、コストが高いほど低い確率で選びます。

\[\pi(i) = \frac{e^{-\Delta_i/\tau}}{\sum_j e^{-\Delta_j/\tau}}, \qquad d = \sum_i \pi(i)\,\Delta_i, \qquad \tau = 0{,}025\]

Δᵢ は、正規化エクイティで見た、最善に対する選択肢 i のコストです。選択肢は、チェッカー移動では解析の候補手、キューブを持つプレイヤーではノーダブルとダブル (最善の応答に対する)、ダブルを受ける側ではテイクとパスです。d は ℓ と同様に MWC に換算されるため、両者は同じ単位であり、指した選択肢のコストはちょうど ℓ です。

τ = 0.025 は強いプレイヤーの事前分布です。Δ だけ離れた 2 つの選択肢では、d = Δ / (1 + e^{Δ/τ}) は Δ ≈ 0.032 付近、つまり「疑問手」と「誤り」の間で最大になります。差 0.1 では 0.002 にしかなりません。0.01 間隔の 5 つの候補は d ≈ 0.012 となり、PR 6 程度のプレイヤーの平均誤差にあたります。

  • 回避可能な誤り：損失がデータベースの誤り閾値に達し、かつ d ≤ ℓ / 10 であるもの。2 つの選択肢では、基準プレイヤーは 10 回に 1 回もその誤りをしません。

  • マッチにおけるプレイヤーの超過：Σ(ℓ − d)。基準を超えて失った量です（基準より良かった場合は負）。

  • 比：Σℓ / Σd。1 は「基準と同じようにプレイ」、2 は「2 倍失う」を意味します。Σd < 0.5 % MWC の場合は示しません。簡単すぎるマッチではノイズしか測れないためで、超過は残ります。

対象。PR に数えられる判断のうち、損失が評価されて MWC に換算されるものです。それ以外では難易度は存在せず、ゼロになることもありません。したがって、強制手や PR のウィンドウ外のノーダブルには、損失も難易度もありません。数えられる判断の中で、自明な判断を別扱いする追加のしきい値はありません。その難易度は、もともとゼロに近いからです。

単位。 d と超過：MWC のパーセンテージ。比：単位なし。

読み方。 難易度を大きく上回る損失は、局面が許さなかった誤りです。難易度に近い損失は、誰にでも起こりうる誤りです。超過と比は PR を出会った局面の難易度で補正するため、一部は相手のスタイルを補正することにもなります (マッチパネル)。

不確実性。 1 マッチでは、超過と比は少数の判断に基づき大きく変動します。順位ではなく傾向を示します。

限界。 難易度はプレイヤーモデルと τ に依存し、これらは一度固定されます。変えるとすべての数値が変わります。解析が保持した候補手（XG では数個、gnuBG ではフィルタ次第）しか知らないため、欠けた選択肢は重みを持たず、d は下限になります。特に深さが浅い場合、解析の誤差を引き継ぎます。

XG と gnuBG。 どちらも難易度を計算しません。考え方はチェスの尤度指標 (Regan) に由来します。τ はプレイヤー集団で較正されていません。

95 % 区間

問い。 この数値は何かを語っているのか、それともノイズか。1 マッチでの PR 4.2 と 40 マッチでの PR 4.2 は同じ価値ではありません。区間は、何の根拠もないセルに学習計画を立てたり、1 マッチから順位を読み取ったりするのを防ぎます。

定義。 区間は、最大の独立した単位を再標本化します。マッチではゲーム、集計ではマッチです (全体の PR、フェーズ別のセル、ゲームプラン、ラベルとスコア、集計の L₇)。同じマッチのゲームは、相手、セッション、疲労を共有します。集計でそれらを別々に再標本化すると、区間が不当に狭くなります。プレイヤーフィルタがない場合、マッチの 2 つの席は同じ局面をプレイするので、1 つの単位になります。

式。 G 個の単位についての比 R = Σeᵤ / Σnᵤ (eᵤ は単位の誤差の和、nᵤ はその判断数) では、ブートストラップの分散を抽出なしで計算します。

\[\widehat{\mathrm{Var}}(R) = \frac{G}{G-1} \cdot \frac{\sum_u (e_u - R\,n_u)^2}{\left(\sum_u n_u\right)^2}\]

区間は R ± 1.96 × √Var で、下限は 0 を下回らず、その後は値と同じ変換を適用します (PR では × 500)。集計の L₇ も同じ規則に従い、e の代わりに L、n の代わりに √N を使います。マッチの L₇ は G 個のゲームの和で、分散は G/(G−1) × Σ(l_g − l̄)² です（l_g はゲーム g の損失）。計算は決定的で、同じデータベースは 2 つのストレージエンジンのどちらでも常に同じ区間を与えます。

必要なもの。 少なくとも 3 つの単位と、ゼロでない幅。2 つでは、ばらつきが自由度 1 に依存し、区間は数倍狭くなってしまいます。すべての単位が同じ比であることは、それらが一致していることを示すだけで、値が正確であることを示しません。区間がない場合、セルはグレー表示になり、サンプル数は見えるままです (Stats パネル)。

読み方。 大きく重なる 2 つの区間は何も区別しません。区間が全体の PR を上回ったままのファミリーは、確かな弱点です。

限界。 単位が少ないと正規近似は粗く、誤差の分布は非対称です（少数の大きな誤り）。3 つか 4 つの単位では、区間は目安にすぎません。

XG と gnuBG。 どちらも区間を示しません。

マッチの総括

問い。 マッチの後、何を見直すべきか。ダイスのせいで負けたのかプレイのせいか。誤りは焦りからか、知識の穴からか。画面：マッチの総括。

見直すべき 3 つの判断。 損失が算出されたプレイヤーの誤り（データベースの閾値）のうち、正の回避可能分 ℓ − d = ℓ × (1 − d/ℓ) が大きい上位 3 つ。損失に回避可能性を掛けたものです。難易度が不明なら 0 として扱います。同順位では損失の大きい方、次にマッチ内の順序です。基準プレイヤーもするであろう誤りは、学習時間をかける価値がありません。

終了したマッチの運を調整した結果。プレイヤーの MWC の点数で表します。

\[A = R - C, \quad R = \text{issue} - \mathrm{MWC}_\text{départ}, \quad C = \sum \text{chance de ses jets} - \sum \text{chance des jets adverses}\]

結果は勝ちが 1、負けが 0 です。開始時 MWC は初期スコアのもの (0-0 で 50 %) です。各ロールは損失と同様に、その局面のスコアとキューブで MWC に換算します。完全なプレイの下では、A の期待値は相手の損失から自分の損失を引いたものです。そのため総括は照合用に誤りの差を並べて示します。負けたマッチで A > 0：ダイスで負けた。A < 0：プレイで負けた。運は解析器が書いたものです (付録：統計モデル — XG / gnuBG / blunderDB の整合)。運がなければ行はなく、カバレッジ（プレイしたロールに対する測定したロール）が表示されます。部分的な運は A を偏らせるためです。マネーゲームや未完了のマッチにも行はありません。

急いだ誤りと熟考した誤り。 プレイヤーとタイプ（チェッカー、キューブ）ごとに、閾値はそのマッチでの、そのタイプの評価済み判断の既知の所要時間の中央値です。それより速く指した誤りは急いだ誤り、それ以外は熟考した誤りです。中央値はそのマッチでの自分自身のものなので、ペースには依存しません。速さと誤りに関係がなければ、誤りは半々に分かれます。急いだ誤りが多数なら規律、熟考した誤りが多数なら知識が必要です。

限界。 1 マッチは小さな標本です。PR と L₇ にはゲームによる区間が付きます（ゲームは 3 つ以上）。調整後の結果は MET とファイルの運に依存します。所要時間は、それを保持したマッチ（ボットと指したマッチ）にしか存在しません。

XG と gnuBG。 XG と gnuBG は各プレイヤーの運の合計を表示しますが、MWC での調整後の結果も、見直す判断の選択も、所要時間による分割もありません。

学習プラン

問い。 今、何に取り組むべきか。誤りをコストで並べると、どこで最も失ったかはわかりますが、どこで学習が最も報われるかはわかりません。本当に難しい局面のファミリーは誰にとってもコストがかかり、3 つの誤りは傾向にはなりません。画面：学習プラン。

定義。 ファミリーは、繰り返される誤りの組 (ゲームプラン、判断の種類、テーマ) です。メンバーはフィルタの誤り、すなわち誤り閾値以上のコストがかかるカウントされた判断です。テーマのない誤りはどのファミリーにも入りません。メンバーは ℓ と d を持つ場合に算出済みです。マネーゲームの誤りは「未算出」としてカウントされ、どの優先度にも入りません。

式。 回収可能な MWC とその区間：

\[R = \sum_i (\ell_i - d_i), \qquad R \pm 1{,}96 \sqrt{\textstyle\sum_i (\ell_i - d_i)^2}\]

R は、ファミリーの頻度に、難易度を超えた平均損失を掛けたものです。基準プレイヤーのようにこれらの局面を指した場合に取り戻せる量です。合計は符号付きで、クリッピングはしません。区間はメンバー数をポアソン計数として扱います。

プランに入るもの。 少なくとも 5 つの算出済みメンバーと、厳密に正の下限。プランは下限の降順で並びます。回収可能量が同じなら、より確かなファミリーが先になります。それ以外は「要確認」で、順位はありません。

単位。 フィルタ全体で累積した MWC のパーセンテージ。

読み方。 回避可能な誤りのファミリーは上がり、誰もが間違える局面のファミリーは下がります。新しいプレイヤーはまず「要確認」のファミリーを見ます。プランはノイズに向かって押しません。

限界。 テーマは blunderDB の分類器に由来します。誤って分類された誤りは誤ったファミリーに入り、テーマのない誤りはどこにも入りません。R は ℓ と d の限界（MET、候補手の切り捨て）を引き継ぎます。

XG と gnuBG。 どちらも学習プランを提供しません。

基準局面

問い。 プランに取り組むには、どの局面をコレクションに入れるべきか。最悪の誤り 10 件は、しばしば同じ問題の 10 の変形になります。良い基準局面は、あなたの回避可能な誤りの多くの中心にあり、明確な教訓を持ち、まだ学習されていないものです。画面：基準局面。

定義。 候補は、フィルタ内の算出済みでテーマのある誤りを局面ごとにまとめたものです。局面の超過は、その誤りの正の超過 ℓ − d の合計です。同じファミリー（キューブでは同じスコアも）の 2 つの候補は、like 距離で ρ = 12 ピップステップ以内にあるとき近傍です（ダイスの 1 振りは 8 から 16 に相当します）。

式。 候補 p のゲインは

\[G(p) = c(p) \times \sum_{q \,\in\, \text{voisinage}(p),\ q\ \text{non couverte}} \text{excès}(q)\]

MWC の割合で表され、代表性、頻度、回避可能なコストを 1 つの量にまとめます。c(p) は 1 から始まり、教訓が僅差（次善の手のコストが誤り閾値の半分未満）なら ½ 倍し、さらに不安定（別のキューブ解析の深さまたはロールアウトで異なる判定になる）なら ½ 倍します。両方が重なると ¼ です。確認するロールアウトは何も引き上げません。ゲインが同じときの順位決めに使います。

選択。 限界ゲインによる貪欲法です。選ばれた各局面は近傍をカバーし、近傍は後続の局面には何ももたらさなくなります。ほぼ重複する局面は、ファミリーの外でも除外されます。すでに扱った局面（コメント、Anki カード、コレクション、「学習済み」マーク）は提案されず、すでに選ばれたものとして数えます。

単位。 カバーした MWC。パーセンテージ。

限界。 半径と係数は固定されており、学習されたものではありません。like 距離は考え方ではなくチェッカー構造を比較します。同じ教訓でも構造が離れた 2 つの局面は互いをカバーしません。

XG と gnuBG。 同等のものはありません。

学習の前後

問い。 取り組んだことは、実戦で私のコストを減らしたか。測定がなければ、学習は印象で判断されます。努力しても動かないファミリーは、方法を変える必要があることを示します。画面：学習の前後。

定義。フィルターのテーマ別ファミリーはすべて、プランのものも「要確認」のものも測定します。ファミリーは、その局面のいずれかに対する最初の学習アクションの日(UTC)に学習済みとなります。「学習済み」マーク、評価を問わない Anki の復習、クイズへの回答が該当します。カードの作成や局面のコレクションへの整理は該当しません。前ウィンドウは、その日より厳密に前の日付のマッチ、後は厳密に後のマッチで、当日と日付のないマッチは除外されます。

式。 各窓で、損失率 r = Σℓ / N。ℓ はファミリーの誤りの損失、N は同じゲームプランかつ同じ種類のマッチでカウントされた判断です（テーマは誤りにしか存在しません）。ゲインとその区間：

\[\Delta = r_\text{avant} - r_\text{après}, \qquad \Delta \pm 1{,}96 \sqrt{\frac{\sum \ell^2_\text{avant}}{N^2_\text{avant}} + \frac{\sum \ell^2_\text{après}}{N^2_\text{après}}}\]

判定。 各窓に少なくとも 30 判断。なければ「不十分」です。Δ の下限が正なら「改善」、上限が負なら「悪化」、それ以外は「不確定」です。

単位。 100 判断あたりの MWC ポイント。

限界。 変化であって効果ではありません。ファミリーはコストがかかったから学習されます。平均への回帰がゲインを膨らませます。相手、フォーマット、ダイスは何も統制されません。

XG と gnuBG。 同等のものはありません。

符号付きバイアス

問い。 私はどちらの方向に間違えているか。「テイクしすぎ」は PR より修正しやすい指摘です。見直すべき規則に名前が付くからです。画面：符号付きバイアス。

式。 カウントされた各判断は x = +1（強気すぎる誤り）、−1（慎重すぎる誤り）、または 0 を持ちます。N 判断における 2 つのカウントを P と M とすると：

\[B = \frac{P - M}{N}, \qquad B \pm 1{,}96 \sqrt{\frac{(P + M)/N - B^2}{N}}\]

少なくとも 20 判断。下限が正なら「多すぎ」、上限が負なら「足りない」、それ以外は「均衡」です。P と M のコスト (mpt) がカウントに添えられます。符号とコストは、そのマッチで指した手のものです。

  • テイク / パス：キューブへの応答について。P = 誤ったテイク、M = 誤ったパス。B は、同じ局面での自分のテイク率からボットのテイク率を引いた値そのものです。

  • ダブル：PR にカウントされた、キューブ保持者のキューブ判断について。P = 早すぎるダブル（ノーダブル、または強すぎる）、M = 逃したダブル。バイアスはスコアのセルごと（自分の残り点数、相手の残り点数。ポスト・クロフォードは 1 として扱う。マネーゲームは別）にも示されます。

  • ブロット：接触のあるチェッカー移動について。x は（指した手の後の自分のブロット数 − 最善手の後の自分のブロット数）の符号です。手は残す盤面で識別します。見つからない手はカウントから外れ、その割合が表示されます。

単位。 割合の差。単位なし。

限界。 スコアのセルの大半は沈黙したままです。それが誠実な答えです。ブロットのバイアスは、露出度を考慮せずにブロットを数え、除外された手は中立な抽出ではありません。

XG と gnuBG。 同等のものはありません。XG と gnuBG はキューブの誤りをタイプ別（逃したダブル、誤ったテイクなど）に数えますが、区間も判定もありません。

トーナメントの総括

問い。 自分のレベルでプレイできたか。そうでなければ、どこで崩れたか。最終ラウンドか、長いマッチ終盤か、1 点が勝負を決めるスコアか、時計か。画面：トーナメントの総括。

定義。 通常のレベルは、トーナメント（その日付、なければ最初のマッチの日付）の前の 365 日間のポイントマッチでのプレイヤーで、トーナメントのマッチは除きます。5 マッチ以上が必要です。トーナメントと通常のレベルにはそれぞれ PR と L₇ があり、マッチによる区間 (95 % 区間) が付きます。

式。 Δ = トーナメント − 通常。標準偏差は √(σₜ² + σₕ²) で、各 σ は区間の上側の半幅から読みます。Δ の下限が正なら「悪い」、上限が負なら「良い」、それ以外は「いつもどおり」です。判定には区間と、両側それぞれ少なくとも 20 判断が必要です。なければ「不十分」で、数値は表示されます。

内訳(PR 単位):ラウンド別では、各マッチを全体の通常 PR と比較します。続いて、各セルを通常レベルの同じセルと比較し、マッチ内での判断の順位別(30 手ごとの区間:疲労)、スコア別(DMP、クロフォードゲーム、ポストクロフォード、その他)、ペース別(マッチでのあなたの所要時間の中央値の前後)に分けます。トーナメントに限定した学習プランのファミリーは最大 3 つです。

限界。 3 マッチのトーナメントが「悪い」と言うことはほとんどありません。意図したものです。両側は独立として扱われ、それが区間を広げます。規則は慎重です。時計の持ち時間は手ごとには記録されないため、残り時間によるプレッシャーは測れません。

XG と gnuBG。 同等のものはありません。
