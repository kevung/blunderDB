統計

stats — 繰り返されるミス

フィルターのミスをプランとテーマごとにまとめ、コストの大きい順に並べます。Stats パネルの Errors タブにある「繰り返されるミス」の表です（Stats パネルを参照）。全体の統計は引き続き list --type stats で取得します。

./blunderdb stats recurring --db <fichier> [options]

オプション：

  • --player <nom> — このプレイヤーの判断のみ。

  • --opponent <nom> — この対戦相手と対戦したマッチのみ。--playerと併用すると、もう一方の席。

  • --tournament <ids>、--from <AAAA-MM-JJ>、--to <AAAA-MM-JJ>、--decision-type all|checker|cube — list --type stats と同じフィルターです。

  • --limit <n> — テキストで表示するグループ数（既定は 20、0 ですべて）。

  • --format text|json — JSON は各グループをすべてのポジションの一覧とともに出力します。

  • --quiz — 最もコストの高い3グループのポジションから無作為に引いて表示します（--quiz-size <n>、既定は20）。これらはクイズと quiz_grade が判定する識別子です。JSONでは Quiz フィールド。

  • --deck <名前> — その名前のAnkiデッキを作り、最もコストの高い3グループのすべてのポジションを入れます。

  • --group <順位> — --quiz または --deck と併用：最初の3グループの代わりに、その順位（最もコストの高いものが1）のグループ。

チェッカープレイのテーマは gammon、blots、point、passive のいずれかで、キューブのテーマは offer_missed、offer_premature、answer_wrong_pass、answer_wrong_take のいずれかです。どのルールも名付けないミスは順位から外れ、プランごとに1行で別に一覧されます(JSON では Unthemed フィールド)。説明文が判断を下すのは60 mp以上、つまりミスのしきい値より上だけだからです。COST (PR) 列は、そのグループがフィルターの PR に占める割合です。

例：

./blunderdb stats recurring --db base.db --player "Alice"
./blunderdb stats recurring --db base.db --decision-type checker --format json
./blunderdb stats recurring --db base.db --quiz --format json
./blunderdb stats recurring --db base.db --group 1 --deck "Mon pire groupe"

stats plan — フィルターの学習プラン。ダッシュボードの 学習プランカード（学習プラン を参照）と同じで、誤りのファミリー（プラン × テーマ）を回収可能 MWC、つまりその誤りにわたる損失マイナス難しさの合計の順に並べ、95 % 区間を付けます。ファミリーがプランに入るのは、数値化された誤りが 5 件以上で、区間がゼロより上のときです。それ以外は別に、要確認として挙げられます（JSON ではフィールド Tentative）。テーマのない誤りと MWC のない誤り（フリーゲーム）は数えられるだけです（Unthemed、Unpriced）。

./blunderdb stats plan --db <fichier> [options]

stats recurring と同じフィルターオプションに加えて、次があります。

  • --limit <n> — テキストで表示するファミリーの数（既定は 10、0 ですべて）。

  • --quiz（--quiz-size <n>、既定は 20）、--deck <名前> — stats recurring と同様に、上位 3 ファミリーのポジションに対して働きます。

  • --queue — これらのファミリーの学習キューを、1 行に 1 ポジションで、基準プレイヤーとの差が最も大きいものから表示します（JSON：Queue）。

  • --family <順位> — --quiz、--deck、--queue と併用：上位 3 ファミリーの代わりに、この順位のファミリー（1 が先頭）。

./blunderdb stats plan --db base.db --player "Alice"
./blunderdb stats plan --db base.db --player "Alice" --quiz --format json
./blunderdb stats plan --db base.db --family 2 --queue

stats effect — 学習済みの各ファミリーの前後。ダッシュボードの学習の前後カード（学習の前後 を参照）と同じです。そのポジションのいずれかに対する最初の学習アクションの日付、その日の前後それぞれの、プランと種類が同じ 100 判断あたりの MWC 損失率、ゲインとその 95 % 区間、そして判定（improved、worse、undetermined、ウィンドウあたり 30 判断未満は insufficient）を示します。

./blunderdb stats effect --db <fichier> [options]

stats biases — フィルターの符号付きバイアス。符号付きバイアスカード（符号付きバイアス を参照）と同じです。テイク／パス、ダブル（全体とスコア別）、ブロットについて、それぞれ二つのカウントとそのコスト、バイアス、95 % 区間、判定（too_much、too_little、balanced、20 判断未満は insufficient）を示します。フリーゲームには専用の money 行があり、ポストクロフォードのスコアは 1 ポイントとして読みます。再現できなかったチェッカームーブの割合は表の下に示されます。

./blunderdb stats biases --db <fichier> [options]

stats recurring と同じフィルターオプション（--player、--opponent、--tournament、--from、--to、--decision-type、--format）。

./blunderdb stats effect --db base.db --player "Alice"
./blunderdb stats biases --db base.db --player "Alice" --format json

stats tournament — あるプレイヤーのトーナメントの総括で、トーナメントパネルの 総括 ボタンと同じものです（トーナメントの総括 を参照）。PR と MWC 損失（7 ポイント換算）を直前 365 日の普段のレベルと比べ、ラウンド別、マッチ内での判断の順位別、スコア別（dmp、crawford、post_crawford、other）、テンポ別（quick、considered）に示します。それぞれに 95 % 区間と判定（worse、better、usual、区間がない場合、片側が 20 判断未満の場合、または普段のマッチが 5 未満の場合は insufficient）が付き、続いてトーナメントのミスの類型が最大三つ示されます。

./blunderdb stats tournament --db <fichier> --id <n> [--player <nom>]... [--format text|json]

--player を指定しない場合、プレーヤーはトーナメントの対局に最も多く登場する人です。--player は繰り返して指定でき、複数のプレーヤーを 1 回の呼び出しで確認できます。JSON では、プレーヤーが 1 人ならオブジェクト、2 人以上なら指定した順のリストになります。プレーヤー数が変わるスクリプトは、常にリストを返す stats.tournamentReviews ルート (または GetTournamentReviews) を使います。

./blunderdb stats tournament --db base.db --id 3
./blunderdb stats tournament --db base.db --id 3 --player "Alice" --player "Bob" --format json

stats training — 判断クイズの PR、マッチの PR、Anki の定着率を、Stats パネルの トレーニング タブと同様に、暦のウィンドウごとにまとめて表示します(Stats パネル を参照)。

./blunderdb stats training --db <fichier> [options]

オプション：

  • --window week|month — 暦のウィンドウ(既定は week)。

  • --player <名前>、--tournament <ids>、--from <YYYY-MM-DD>、--to <YYYY-MM-DD>、--decision-type all|checker|cube — マッチのフィルタ。クイズと Anki のジャーナルにはプレイヤーがありません。

  • --format text|json — JSON にはクイズのセッション一覧も含まれます。テキストと JSON のどちらも、プレイプラン別のクイズPRを出力します。

各系列はサンプル数を保持します。判断のないウィンドウは、テキストでは破線、JSON ではカウント 0 となり、値としてのゼロにはなりません。

例：

./blunderdb stats training --db base.db --player "Alice"
./blunderdb stats training --db base.db --window month --format json

stats h2h — 2 人のプレイヤーの直接対決です。2 人が一緒に戦ったマッチ、各マッチおよび全体での各自の PR、最後まで行われたマッチの勝敗を示します。

./blunderdb stats h2h --db <fichier> --player <nom> --opponent <nom> [options]

stats contrast — 2人のプレイヤーがどちらも打った局面のうち、一方がうまく打ち（エラーのしきい値未満）、もう一方がそうでなかったもの。差が大きい順に並びます。プレイヤーは、その局面での最悪の手で判定されます。--limit Nはテキストの先頭N行を残し、JSONはposition_idを含むすべてを返します。

./blunderdb stats contrast --db <fichier> --player <nom> --opponent <nom> [options]

stats windows — 移動するカレンダー期間での PR です。月ごとに 1 行で、各行はその月と期間内のそれ以前の月を対象にします( --window month 、 quarter 、または月数)。

--by-phaseは各ウィンドウをゲームフェーズ（オープニング、ミドルゲーム、レース、ベアオフ…）ごとに分割します。各行の下に、フェーズごとにマッチ数、決定数、PR を示す行が付き、ウィンドウに限定した stats breakdownのフェーズ別内訳と同じ数値です。ウィンドウ内に集計された決定のないフェーズは表示されません。HTTP デーモンは、stats.prByWindowリクエストに "byPhase": trueが含まれるとき、これらを per_phaseで返します。

./blunderdb stats windows --db <fichier> [--player <nom>] [--window quarter] [--by-phase]

stats ranking — PR によるプレイヤーの順位です。PR が低い順で、カウントされた判断が --min-decisions 以上(既定は 500)のプレイヤーが対象です。PR が等しい 2 人は同じ順位になります。 --limit N は上位 N 人を残します。

./blunderdb stats ranking --db <fichier> [--min-decisions 1000] [--limit 20]

stats engines — データベースにある解析エンジンを、--engine が受け付ける正確な名前で表示します。Stats パネルの エンジン メニューと同じ選択肢です。

./blunderdb stats engines --db <fichier> [--format json]

共通オプション: --tournament <ids> 、 --from <YYYY-MM-DD> 、 --to <YYYY-MM-DD> 、 --decision-type all|checker|cube 、 --format text|json 、さらに出所フィルタの --engine <名前> (解析エンジン、正確な名前)と --min-depth <n> (解析の最小深度)があり、 list --type stats と list --type players も受け付けます。 h2h と windows はマッチごとの統計を読むため、各判断に対して働く出所フィルタは拒否します。

例：

./blunderdb stats h2h --db base.db --player "Alice" --opponent "Bob"
./blunderdb stats contrast --db base.db --player "Alice" --opponent "Bob"
./blunderdb stats windows --db base.db --player "Alice" --window quarter --format json
./blunderdb stats ranking --db base.db --min-decisions 1000 --limit 20
./blunderdb list --type stats --db base.db --player "Alice" --min-depth 3

stats matches — コーパスの数値が数えるマッチ。フィルタの下で、そのプレイヤー(--player なしでは全プレイヤー)に数えられた判断があるマッチを、古いものから新しいものへ並べます。その識別子は list --type matches --ids に渡せます。

./blunderdb stats matches --db base.db --player "Alice" --from 2025-01-01 --to 2025-03-31
./blunderdb list --type matches --db base.db --ids 12,15,31

stats tournaments — ダッシュボードのトーナメント数が数えるトーナメント：フィルターのもとでプレイヤー（--player がなければ任意のプレイヤー）のカウントされた判断を含むもの、ID 順。

./blunderdb stats tournaments --db base.db --player "Alice" --from 2025-01-01
./blunderdb stats tournaments --db base.db --format json

stats progression — 各マッチの PR を日付順に、各トーナメントの PR と直近 N 件の判断の移動 PR を表示します。Stats パネルの Progression タブに相当します(Stats パネル を参照)。

./blunderdb stats progression --db <fichier> [options]

オプション：

  • --player <nom>, --tournament <ids>, --from <AAAA-MM-JJ>, --to <AAAA-MM-JJ>, --decision-type all|checker|cube — list --type stats と同じフィルタです。

  • --format text|json — JSON にはマッチ、トーナメント、移動 PR が含まれます。

例：

./blunderdb stats progression --db base.db --player "Alice"
./blunderdb stats progression --db base.db --format json

stats breakdown — フィルタの PR を、ゲームのフェーズ、ゲームプラン、コメントタグ、スコア(アウェイ対アウェイ)、キューブアクションごとに分け、キューブミスの方向も示します。Stats パネルの 内訳 タブに相当します(Stats パネル を参照)。オプションは stats progression と同じです。

./blunderdb stats breakdown --db <fichier> [options]

例：

./blunderdb stats breakdown --db base.db --player "Alice"
./blunderdb stats breakdown --db base.db --format json

stats summary — 識別子を一切含まないフィルターのレベル：件数、PR（チェッカー、キューブ）とその 95 % 区間、7 ポイントマッチあたりの MWC 損失、ゲームフェーズ別・スコア別の PR で、各行に件数と区間が付きます。ポジション、マッチ、トーナメント、対戦相手、タグは一切現れず、最も高くついた決定も含まれません。公開プロフィールや名刺が何も漏らさずに示せる内容です。HTTP デーモンは stats.summaryルートでこれを提供し、stats.compute は変わりません。オプションは --player、--tournament、--from、--to、--decision-type、--format で、--window はありません。

./blunderdb stats summary --db base.db --player "Alice"
./blunderdb stats summary --db base.db --player "Alice" --format json

stats report — Stats パネルの HTML レポート(HTML レポート を参照)です。フィルタの指標と、コストの大きい上位 10 件の判断を図とともに、ブラウザーが PDF として印刷できる単一の自己完結ファイルにまとめます。HTTP デーモンは同じジェネレーターから、ルート stats.reportで提供します。

./blunderdb stats report --db <fichier> --html [options]

オプション：

  • --html — 必須:HTML が唯一の形式です。

  • --output <fichier> — 書き出すファイルです(デフォルト:標準出力)。

  • --lang <code> — レポートの言語:fr、en、de、el、es、fi、it、ja、ru(デフォルトは en)。

  • --player <nom>, --tournament <ids>, --from <AAAA-MM-JJ>, --to <AAAA-MM-JJ>, --decision-type all|checker|cube — フィルタ:レポートはその対象範囲を明示します。

図はここでは既定のパレットで描かれます。画面で選んだボードのパレットを使うのはグラフィカルアプリケーションだけです。

例：

./blunderdb stats report --db base.db --html --output rapport.html
./blunderdb stats report --db base.db --html --player "Alice" --lang fr
