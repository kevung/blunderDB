コマンド一覧

コマンドラインはステータスバーにあり、 スペース キーを押すと開きます。コマンドを入力すると、候補のリストが自動的に表示されます。 TAB キー（または Shift-TAB ）は候補を順に巡回してコマンドを補完し、 ESC はリストを閉じます（2回目の ESC でコマンドラインが閉じます）。 上 キーと 下 キーは引き続きコマンド履歴用に予約されています。

全体操作

コマンド

動作

new, ne, n

新しいデータベースを作成します。

open, op, o

既存のデータベースを開きます。

import_db, idb

別のデータベースをインポートして統合します。

export_db, edb

現在の選択を新しいデータベースにエクスポートします。

quit, q

blunderDB を終了します。

help, he, h

blunderDB のヘルプを開きます。

tutorial, tour

インターフェースのガイドツアーのカタログを開きます。

demo

ツールを試すためのサンプルデータベース（マッチ、トーナメント、コレクション、コメント、Anki デッキ、解析）を読み込みます。

meta

データベースのメタデータを表示します。

eval, epc

Eval パネル（Effective Pip Count、勝率、ベアオフでのキューブの判定）を開きます。epc はこのパネルの旧名で、そのまま残されています。

transcribe, tr

記譜パネルを開きます。入力中のマッチの下書きと、新しく始めるための手段が表示されます。

direct

大会を進行するために「大会」パネルを開き、また閉じます。そこで進行が開いている間、主要領域には盤面ではなく大会が表示され、他のタブに切り替えると盤面が戻ります。

met

Kazaross-XG2 のマッチエクイティ表を開きます。

cm

キューブ判断のマトリクスを開きます。5・7・9 点マッチのあらゆるスコアにおける現在の局面の判断を示します。

tags

タグの語彙を開きます。このデータベースで使われているタグと局面数が並び、クリックすると検索が走ります。

log

動作ログを開きます。ログファイルの末尾二百行を表示し、レポートに添えるためのコピーや、ログの入ったフォルダを開く操作ができます。

train

トレーニングパネルを開きます。引数を付けると開いて開始します：train scores（無作為に引いたスコアのスコアカード。train tp と train takepoint は別名）、train pips（両者のピップ数）、train bearoff（生成した局面での両者の EPC。train epc は別名）、train evaluation（生成した局面の勝率とキューブアクション。マネーゲーム）、train decision（表示中のリストから出題する解析済みの判断。手は盤上で打ち、キューブアクションはパネルで選びます。train quiz は別名）。

duel

デュエルパネルを開きます。blunderDB を審判（Arbiter）として、ボットと対局するマッチです（デュエルパネルを参照）。

tp2

キューブ値 2 のテイクポイント表を開きます。

tp2_live

ロングレース用のキューブ値 2 のテイクポイント表を開きます。

tp2_last

デッドキューブ値 2 のテイクポイント表を開きます。

tp4

キューブ値 4 のテイクポイント表を開きます。

tp4_live

ロングレース用のキューブ値 4 のテイクポイント表を開きます。

tp4_last

デッドキューブ値 4 のテイクポイント表を開きます。

gv1

キューブ値 1 のギャモン値表を開きます。

gv2

キューブ値 2 のギャモン値表を開きます。

gv4

キューブ値 4 のギャモン値表を開きます。

局面とナビゲーション

コマンド

動作

import, i

ファイル（xg, xgp, sgf, mat, txt, bgf）から局面やマッチを取り込みます。引数を付けると——import XGID=… または import OGID=…——ファイル選択を開かずに識別子を読みます。識別子がメッセージやフォーラム、スクリプトから来る場合のためです。

delete, del, d

現在の局面を削除する（確認あり）。削除はごみ箱を経由し、三十日間は取り消せる。

trash

ごみ箱を開く：削除されたものと、それを復元する手段。

resume

何も完了させていないインポート（アプリケーションの停止）を一覧し、フォルダまたはファイルをもう一度指定したうえで、選んだものを再開します。

[number]

指定したインデックスの局面に移動します。

[number]%

リストのその割合の位置へ移動します。0% は最初の局面、50% は中間、100% は最後の局面です。

grid, gr

コンタクトシートを開きます。閲覧中のリストをミニ盤面のグリッドとして、1ページ24局面ずつ表示します。サムネイルを選ぶとその局面が開きます。

list, l

現在の局面の解析を表示します。

comment, co

コメントを表示／記入します。

rollout, ro [fast|standard]

現在の局面をロールアウトし(設定のgammonNetタブで選んだ設定、または指定したプリセットで)、解析パネルを開きます。ro search [fast|standard] は確認ダイアログで総数を示した後、表示中の一覧に対して実行します。ro stop は実行中のロールアウトを停止します。

history, hi

検索パネルを開きます（検索履歴はその履歴タブにあります）。

stats, st

統計パネルを表示／非表示にします。

match, ma

マッチパネルを表示／非表示にします。

collection, coll

コレクションパネルを表示／非表示にします。

lesson, le [N | edit [N]]

引数なしでは、データベースのレッスンをステータスバーに一覧表示します。le N はレッスン N を最初のステップで開き、le edit はレッスンエディタを開き、le edit N はレッスン N を開いた状態でエディタを開きます(レッスン を参照)。

study, sq

横断学習キューを開きます。まだ何も処理されていないあなたのブランダーを、コストの大きいものから小さいものへ表示します(まだ何も処理されていないブランダーを参照)。

#tag1 tag2 ...

現在の局面にタグを付けます。

e

データベースのすべての局面を読み込みます。

blunders, bl [n]

現在の統計フィルターに従って、最悪のミス（エクイティ/MWC）を分析ビューに読み込みます。任意の数値で読み込む件数を指定できます（bl 50）。デフォルトは 10 件です。

m

最後に閲覧したマッチ内を移動します。

検索フィルタ

この表が検索文法の基準です。コマンドライン、フィルターライブラリ、そして blunderdb search の --query フラグは、いずれも同じトークンを読みます。CLI 相当 の列は、同じことをする search のフラグが存在する場合にそれを示します（コマンドラインインターフェース（CLI）を参照）。ダッシュは、この文法でしか表現できないフィルターであることを示します。

5つのトークンは値を自分では持ちません。値は検索用の盤面から読み取ります。cube と score はそこに置かれたキューブとスコアを、d は決定の種類を、D と D1 はダイスを、x は 除く タブに描かれた構造を受け取ります。したがって出目をトークンに書くことは決してありません。D65 は存在せず、数字を持つのは除外の形（xD65）だけです。盤面のないコマンドラインでは、これらのトークンは空の盤面と比較されます。そこでは第3列のフラグを使ってください。

トークンのうち like だけは、絞り込むのではなく並べ替えます。目標局面からの距離の昇順に結果を並べ、ほかのトークンはすべて、そうして並んだ集合を絞り込みます。

エラーとエクイティはエクイティの千分の1単位で数えます——下の表でいう ミリポイント です。E>100 は、少なくとも 0.1 ポイントを失った手を残します。1ポイントは 1000 ミリポイントです。

完全な検索の例を二つ：

  • s p>30 w40,60 xco — 30 ピップ以上遅れており、勝率が 40 % から 60 % の間で、コメントがないもの。

  • s ph:race E>50 co:xg — レースで、少なくとも 50 ミリポイントを失った手であり、eXtreme Gammon から来たコメントがあるもの。

識別子 x のトーナメント内を検索します（例: tn1）。

--tournament-ids

tnx,y

識別子 x から y のトーナメント内を検索します（例: tn1,3）。

--tournament-ids

tn'名前'

名前が 名前 のトーナメントから検索します。大文字・小文字は区別せず、* は任意の文字列に一致します（例：tn'open*'）。

--tournament-name

rd:x

ラウンド x のマッチから検索します（例：rd:3、rd:決勝）。ラウンドの文字列は大文字・小文字を区別せずに比較され、* は任意の文字列に一致します。繰り返し指定可能（rd:1 rd:2）で、いずれかに一致すれば対象になります。

--round

ml:x

マッチの長さが x ポイントである場合です。ml:7、ml:5,9、ml>5、ml<9 の形式を使えます（境界値を含む）。

--match-lengths

md:x..y

マッチの日付。ポジションの match_date 列（そのポジションに到達する最も古いマッチの日付）から読み取ります。解析の作成日（T）ではありません。各境界は年・月・日のいずれか（2024、2024-06、2024-06-15）で、その期間全体を含みます（境界値を含む）。md:2024-01..2024-12 は 2024 年 1 月 1 日から 12 月 31 日までです。md:2024（その年全体）、md>2024-06、md<2024-06 の形式も使えます。

--match-date

idx

識別子 x のポジションを検索します（例: id12）。

--position-ids

idx,y

識別子 x から y までのポジションを検索します（例: id5,10）。

--position-ids

pl'名前'

指定したプレイヤーが（どちらの席でも）参加した対局のポジションを検索します（例：pl'Alice'）。大文字・小文字は区別せず、* は任意の文字列に一致します（pl'Ali*'）。

--player

pl!'名前'

このプレイヤーが下した判断のみ対象です。手番のプレイヤーとは、マッチでその名前の席に着いているプレイヤー（プレイヤー 1 またはプレイヤー 2）のことです。大文字・小文字とワイルドカードの規則は pl と同じです。

--player --seat-only

op'名前'

このプレイヤーが pl のプレイヤーの対戦相手であるマッチのみ対象です（pl'Alice' op'Bob'：Alice 対 Bob、どちらの席でも可。pl! を付けると Alice の判断のみ）。pl がない場合、op 単独で pl と同様にどちらかの席のプレイヤーを指します。大文字・小文字とワイルドカードの規則は同じです。

--opponent

pr>x

判断を下したプレイヤーのマッチ PR が x 以上である場合です。マッチごとの統計のうち、そのプレイヤーの席の値を読み取ります（対戦相手の PR ではありません）。PR のないマッチは除外されます。pr>8、pr<5、pr4,9 の形式を使えます（境界値を含む）。

--pr

ad:xg

ポジションに記録されている解析のエンジンと深さ。エンジン：xg、gnubg、bgblitz、hedgehog、gammonnet（エンジン名の先頭部分、大文字・小文字は区別しません）。深さ：3ply（ちょうど 3 プライ）、3ply+（3 プライ以上）、book（オープニングブック）、rollout（ロールアウト。XG Roller と Roller++ を含む）。繰り返し指定可能です。エンジン同士、深さ同士はいずれかに一致すればよく、エンジンと深さの両方が一致する必要があります（ad:xg ad:gnubg ad:3ply+）。

--analysis

like, like42, like<12, like42*

結果を絞り込むのではなく、目標局面からの距離の昇順に並べ替えます。like は現在の局面を、like42 は番号42の局面を取り、like<12 は十二チェッカーピップを超えるものを除き、like42* は目標のクラスをすべての決定の種類と、マネーとマッチの両方の形式に広げます。検索パネルを参照。

—

pl、pl!、op、tn、m、t の値は、二重引用符またはアポストロフィで始まり、そのどちらかで終わります。引用符を含みながら完全な値にならないトークンは無視され、blunderdb search --query がそれを報告します。タグにはアポストロフィを含められます（#l'ouverture）が、二重引用符は含められません。セミコロンは ID とタグのリストの区切りです。どの値にも現れず、ma1;2 はトークンではありません（ma1 ma2 と書きます）。

ターミナルから転記する

コマンドラインに転記用のコマンドはありません。操作は 記譜 タブで入力します。アプリケーションの外では blunderdb call (APIで記譜する) を使います。例: blunderdb call transcriptions.apply --db base.db --if-match 3 --json '{"id":1,"gesture":{"Kind":"validate"}}'。--if-match は直前の呼び出しが返したリビジョンを指定します。呼び出しごとに独自のセッションとなり、sessionId はなく、呼び出しをまたいだ取り消しもできません。
