# T3.1 — Volet métadonnées, autocomplétion, tournoi, transcripteur, inversion [M]

Le document a des champs d'en-tête saisissables « plus tard » (`fonctionnel.md` § 1.1) :
joueurs, événement, lieu, manche, date, transcripteur, tournoi. Sans volet dédié, ils ne sont
jamais saisis et le `.mat` exporté a des en-têtes vides que T0.4 sait pourtant rendre.

**Tranche verticale** : composant de volet → autocomplétion des Players existants → geste
« changer une métadonnée » et « inverser les joueurs » dans `transcriptionStore` → tests →
doc.
**Prérequis** : T1.9 (enregistrer/exporter ; les métadonnées doivent exister avant qu'un
export en tire parti, sinon la fiche livre un formulaire qui ne sert à rien).
**Livrable** : un volet dépliable dans le panneau Transcription saisit tous les champs
d'en-tête ; les noms de joueurs et le tournoi s'autocomplètent depuis la base ; un bouton
inverse les deux joueurs et retourne le plateau.

## Travail
- Nouveau volet dans `TranscriptionPanel.svelte` (dépliable, comme le volet Métadonnées du
  panneau principal, `toggleMetadataPanel`) : champs `player1`, `player2`, `event`,
  `location`, `round`, `date`, `transcriber`, `tournament_id`.
- `player1`/`player2` et le champ tournoi utilisent `frontend/src/components/
  EntityAutocomplete.svelte`, déjà employé par `MatchPanel.svelte` (`:714, :932`) et
  `TournamentPanel.svelte` (`:727`) pour le même besoin (liste filtrée, clavier ou souris,
  Entrée pour valider un nom non existant), pas de nouveau widget.
- `transcripteur` par défaut : `metadata.user` de la base (binding déjà exposé pour
  l'identité), modifiable ici sans toucher au réglage global.
- Geste « inverser les joueurs » dans `pkg/blunderdb/transcript/` : échange `player1`/
  `player2`, inverse tous les `side` des Actions, et le plateau affiché se retourne (le
  Replay redonne la même partie vue de l'autre côté), Replay complet depuis la première
  Action comme tout geste qui change une valeur d'en-tête.
- i18n : nouvelles clés de champs dans les neuf JSON (`i18nKeys.sync.test.js`,
  `i18nOrphanKeys.sync.test.js`).

## Recette
- Test unitaire du geste « inverser » : sur un document de deux Actions, les `side` sont
  inversés et `player1`/`player2` échangés ; le Replay produit le même score, lu de l'autre
  côté.
- Test composant : taper un nom déjà présent dans `GetAllPlayers` (ou équivalent) le propose
  dans la liste ; taper un nom absent puis Entrée le garde tel quel (comportement standard
  d'`EntityAutocomplete`, `onSubmit`).
- Export `.mat` (T0.4) : après saisie complète, `RenderMAT` produit les en-têtes `[Player 1]`,
  `[Player 2]`, `[Site]`, `[Round]`, `[EventDate]`, `[Transcriber]`.

## Invariants touchés
- CLI/GUI/server parity : les métadonnées vivent dans le document JSON (`transcript.Document`),
  pas dans un état frontend séparé ; le CLI (T3.4) doit pouvoir les lire de la même ligne.
- i18n : clés dans les neuf langues, jamais seulement le français source.
