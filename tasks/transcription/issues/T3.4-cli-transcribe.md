# T3.4 — `blunderdb transcribe` : rejouer, vérifier, rendre [M]

Le paquet `transcript` (T0.2) sait rejouer un document et détecter ses Incohérences, mais
rien ne l'expose hors de l'interface graphique. `fonctionnel.md` § 5 promet qu'« un `.mat`
importé peut être rejoué par le paquet pour en signaler les Incohérences
(`blunderdb transcribe --check`, lot 3) » : c'est cette commande.

**Tranche verticale** : sous-commande CLI (`internal/cli/cli_transcribe.go`) → paquet
`transcript` (déjà écrit par T0.2, aucune nouvelle règle métier) → sortie texte/JSON → tests
→ `handlers()`, `CLI_USAGE.md`, `doc/source/cli.rst`.
**Prérequis** : T0.2 (paquet `transcript` : `Replay`, Incohérences, `FromMAT`, `RenderMAT`).
**Livrable** : `blunderdb transcribe --mat fichier.mat --check` rejoue le fichier et liste ses
Incohérences ; `blunderdb transcribe --mat fichier.mat --render out.mat` le rend à l'identique
(aller-retour) ; les deux sortent en texte ou JSON.

## Travail
- `internal/cli/cli_transcribe.go` : nouveau fichier, un par sous-commande selon la
  convention du paquet (`aliases.go`, en-tête) : `flag.FlagSet`, `Usage` avec exemples, sortie
  `text`/`json` via `--format`, sur le modèle de `cli_verify.go` qui accepte déjà `--mat` pour
  comparer un fichier `.mat` à un match.
- La commande n'ouvre pas nécessairement une base : `transcript.FromMAT` lit le fichier
  directement (comme `gnubgparser.ParseMAT`, déjà utilisé sans base par
  `pkg/blunderdb/ingest/gnubg.go:49`) ; `--db`/`--match` optionnels pour rejouer un Match déjà
  enregistré à la place d'un fichier.
- `--check` : `transcript.Replay` sur le document obtenu, liste des Incohérences avec leur
  position dans le document (numéro d'Action, partie) ; code de sortie non nul si des
  Incohérences bloquent l'aller-retour, zéro sinon (bloquant vs. informatif à trancher avec la
  table de `fonctionnel.md` § 1.4 : aucune n'est refusée, donc `--check` **rapporte**, ne
  refuse jamais l'entrée elle-même).
- `--render` : `transcript.RenderMAT` sur le document, écrit le fichier de sortie ; utile pour
  vérifier l'aller-retour `ParseMAT(RenderMAT(doc)) == doc` sur un fichier réel en dehors des
  tests Go.
- **Câblage obligatoire, sous peine de blocage CI** : `"transcribe": cli.runTranscribe` dans
  `handlers()` (`internal/cli/cli.go`), jamais une seconde liste, `main.go` route déjà par
  `cli.IsCommand` ; une section dans `CLI_USAGE.md` (modèle des sections `## Verify Command`,
  `## Export Command`) ; une entrée dans `doc/source/cli.rst` (modèle de la section « verify,
  vérifier l'intégrité ») avec ses huit `.po`. `scripts/doc-inventory.sh` (déclenché
  par le skill `release-blunderdb`) bloque si l'une des trois manque.
- `internal/cli/cli_dispatch_test.go` (parité `handlers()` / table de sous-commandes) et
  `internal/cli/cli_doc_sync_test.go` couvrent une partie de cette synchronisation
  automatiquement ; ne pas ajouter de test qui la refait à la main.

## Recette
- `go test ./internal/cli/...` : `cli_dispatch_test.go` voit `transcribe` dans `handlers()` ;
  un test dédié vérifie `--check` sur un `.mat` du dépôt (`testdata/`) sans Incohérence
  (sortie vide, code 0) et sur un `.mat` synthétique avec un coup illégal injecté (sortie non
  vide).
- `scripts/doc-inventory.sh` passe (commande présente dans `handlers()`, `CLI_USAGE.md`,
  `cli.rst`, et `blunderdb help`).
- `blunderdb transcribe --mat x.mat --render y.mat` puis `diff x.mat y.mat` : identiques sur
  les `.mat` réels du dépôt (mêmes fixtures que le test d'aller-retour de T0.2).

## Invariants touchés
- « Une seconde liste de commandes est un bug » (CLAUDE.md, Project Overview) : `transcribe`
  n'existe qu'une fois, dans `handlers()`.
- CLI/GUI/server parity : la commande n'ajoute aucune règle, elle appelle le paquet
  `transcript` déjà partagé par le binding Wails (`ApplyTranscriptionGesture`, lot 1).
- Documentation : `.rst` modifié + huit `.po` dans le même commit, jamais l'un sans les
  autres (règle « Documentation » de `CLAUDE.md`).
