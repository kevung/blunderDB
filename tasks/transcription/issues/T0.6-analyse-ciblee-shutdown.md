# T0.6 — Lot gammonNet ciblé sur un match ; `shutdown` annule les lots [S]

`AnalyzeMissingWithGammonNet` balaie aujourd'hui **toute** la base sans analyse ; un
enregistrement de transcription (T1.9) veut analyser seulement les positions du match qui
vient d'être écrit, pas relancer un balayage complet à chaque correction. Par ailleurs
`shutdown` ferme la base sans annuler un lot gammonNet ou bearoff en cours : sur SQLite en
connexion unique (CLAUDE.md, « Notes & Gotchas »), une goroutine du lot qui écrit encore
pendant la fermeture est une course, pas seulement un lot perdu.

**Tranche verticale** : Go (`database` + `internal/gui`), pas de Svelte propre — c'est
T1.9 qui appellera le lot ciblé depuis l'interface ; cette fiche livre la fonction et
corrige `shutdown`, testables sans elle.
**Prérequis** : — (indépendante ; consommée par T1.9).
**Livrable** : un appel Go peut analyser les positions sans analyse d'un seul match ;
fermer l'application pendant un lot gammonNet ou bearoff en cours ne laisse plus une
écriture concurrente à la fermeture de la base.

## Travail

- `pkg/blunderdb/database/db_gammonnet_batch.go` : nouvelle fonction
  `positionIDsWithoutAnalysisForMatch(matchID int64) ([]int64, error)`, sur le modèle de
  `positionIDsWithoutAnalysis` (`:46-65`) — même requête, filtrée par
  `JOIN move mv ON mv.position_id = p.id JOIN game g ON mv.game_id = g.id WHERE g.match_id
  = ?` avant le `NOT EXISTS`.
- Même fichier : `AnalyzeMatchWithGammonNet(ctx context.Context, matchID int64, ply,
  pruneK, candidates, jobs int, yield func(), onProgress func(done, total int))
  (GammonNetBatchSummary, error)` — même corps que `AnalyzeMissingWithGammonNet`
  (`:90-96`), mais appelant `positionIDsWithoutAnalysisForMatch(matchID)` puis
  `d.analyzeIDsWithGammonNet` (`:231`), inchangée.
- `internal/gui/gammonnet_batch.go` : `StartGammonNetMatchBatch(matchID int64, ply,
  pruneK, candidates int)`, sur le modèle de `StartGammonNetBatch` (`:43-53`) — même appel
  à `a.runGammonNetBatch` (`:93`), `a.effectiveBatchJobs()` et
  `a.waitForInteractiveEvaluation`, mais vers `a.db.AnalyzeMatchWithGammonNet(ctx, matchID,
  ...)` ; profondeur canonique 2-ply, `k = 12` fixés côté appelant (T1.9), pas ici.
- `internal/gui/run.go` : `shutdown` (`:74-86`) ferme les binds sans rien annuler d'abord.
  Changer la signature en `shutdown(app *App, binds []interface{})`, appelée `shutdown(app,
  extraBinds)` (`:40`), et dans le corps, avant la boucle `for _, bind := range binds`,
  appeler `app.CancelGammonNetBatch()` (`internal/gui/gammonnet_batch.go:142`) et
  `app.CancelBearoffGeneration()` (`internal/gui/bearoff.go:259`) — les deux existent déjà,
  seul le point d'appel manque.

## Recette

- `go test ./pkg/blunderdb/database/... -run TestAnalyzeMatchWithGammonNet` (nouveau) :
  une base avec deux matchs, l'un sans analyse ; `AnalyzeMatchWithGammonNet` sur le premier
  n'analyse QUE ses positions, le second reste sans analyse après l'appel.
  `CountPositionsWithoutAnalysis` (existant) confirme que le compte global baisse
  exactement du nombre de positions du match ciblé.
- `go test ./internal/gui/... -run TestShutdown` (nouveau ou étendu) : démarre un lot
  gammonNet (mock ou base minuscule), appelle la fonction `shutdown` retournée, vérifie que
  `CancelGammonNetBatch`/`CancelBearoffGeneration` sont appelés avant que les binds ne
  ferment leur `Close()` — un test qui espionne l'ordre d'appel, pas seulement l'absence de
  panique.
- `go build ./...` : le nouveau paramètre de `shutdown` ne casse pas `Run` (`run.go:40`).

## Invariants touchés

- « Parallelism is production behaviour, not a test tool » : le lot ciblé réutilise
  `analyzeIDsWithGammonNet` sans toucher à son ordonnancement (goroutines `NumCPU`,
  somme pondérée en ordre de jet croissant) — seule la liste d'ids qui l'alimente change.
- « The GUI opens the user's `.db` file directly … single connection » (Notes & Gotchas) :
  c'est précisément le risque que l'annulation avant `Close()` referme — une écriture du
  lot après la fermeture de la connexion unique.
- « Import cancellation is context-based … not a flag » : le lot ciblé annule par
  `context.Context` comme les lots existants, pas par un booléen supplémentaire.
