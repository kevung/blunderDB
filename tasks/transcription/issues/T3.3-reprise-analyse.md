# T3.3 — Reprise de l'analyse à la réouverture de la base [S]

Le lot gammonNet ciblé (T0.6, T1.9) peut être interrompu par une fermeture avant sa fin ; le
Match transcrit reste alors avec des positions sans analyse et rien ne le signale au prochain
lancement. Le rattrapage existant (`ConfigModal.svelte`, bouton « analyser les positions
manquantes ») porte sur la base entière et est manuel : il ne cible pas le dernier brouillon
et personne ne pense à l'ouvrir juste après une transcription.

**Tranche verticale** : détection à l'ouverture de la base → proposition dans la barre
d'état → relance du lot ciblé déjà écrit (T0.6) → test.
**Prérequis** : T1.9 (enregistrer/remplacer déclenche déjà le lot ciblé une première fois ;
cette fiche est le second déclenchement, après coupure).
**Livrable** : rouvrir une base dont le dernier Match transcrit a des positions sans analyse
fait apparaître dans la barre d'état une proposition de terminer ; accepter relance le même
lot ciblé que T1.9, avec sa progression et son annulation.

## Travail
- Détection au chargement d'une base : identifier le `match_id` du dernier brouillon
  **enregistré** (`transcription.match_id` le plus récent, non nul) et compter ses positions
  sans analyse via le même chemin que `AnalyzeMissingWithGammonNet` restreint à ce match
  (filtre déjà posé par T0.6, `db_gammonnet_batch.go`).
- Barre d'état (`statusBarModeStore` / composant de barre d'état existant) : si le compte est
  non nul, un message propose de terminer, avec un bouton, sur le modèle du bouton
  `startGammonNetCatchUp` de `ConfigModal.svelte:584`, mais déclenché automatiquement à
  l'ouverture plutôt qu'ouvert par l'utilisateur dans les réglages.
- **Aucun état n'est stocké pour cela** (`fonctionnel.md` § 4) : la détection est un comptage
  à chaque ouverture, jamais un drapeau écrit en base ni un fichier `.ckpt` ; si l'utilisateur
  ignore la proposition, elle réapparaît à la prochaine ouverture tant que des positions
  manquent.
- Le lot relancé est exactement celui de T1.9 (progression, annulable, `shutdown` l'annule) :
  cette fiche ne réécrit pas `AnalyzeMissingWithGammonNet`, elle ajoute un second appelant.

## Recette
- Test (Go ou composant selon où vit le comptage) : une base dont le dernier `transcription`
  enregistré pointe vers un match à positions incomplètes propose la reprise ; une base à jour
  ne propose rien.
- Ignorer la proposition puis rouvrir la base la fait réapparaître (aucun état persistant).
- Accepter la proposition lance le même binding que « Enregistrer » relance en T1.9 ;
  `shutdown` (T0.6) annule proprement si l'utilisateur ferme pendant la reprise.

## Invariants touchés
- Parallélisme production (CLAUDE.md) : le lot ciblé reste le batch `NumCPU` de
  `AnalyzeMissingWithGammonNet`, jamais le chemin `WithWorkers` du panneau d'évaluation
  live ; cette fiche ne fait qu'appeler le même lot une seconde fois.
