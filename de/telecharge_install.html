1. Download und Installation

blunderDB ist eine einzige ausführbare Datei, die keine Installation erfordert.

Die neueste Version von blunderDB ist unter der MIT-Lizenz verfügbar:

  • für Windows: https://github.com/kevung/blunderDB/releases/latest/download/blunderDB-windows-0.36.0.exe

  • für Linux: https://github.com/kevung/blunderDB/releases/latest/download/blunderDB-linux-0.36.0

  • für Mac: https://github.com/kevung/blunderDB/releases/latest/download/blunderDB-macos-0.36.0.zip

Für die Offline-Nutzung können Sie diese Dokumentation auch im PDF-Format herunterladen: https://github.com/kevung/blunderDB/releases/latest/download/blunderDB-0.36.0-de.pdf

Bemerkung

blunderDB verwendet Webview2 für die Darstellung der grafischen Benutzeroberfläche. Sehr wahrscheinlich ist Webview2 bereits nativ auf Ihrem Betriebssystem vorhanden. Andernfalls bietet der erste Start von blunderDB an, es herunterzuladen und zu installieren. Ein Eingreifen des Benutzers ist nicht erforderlich.

Die übrigen Dateien der Seite sind die rohen Linux-Binärdateien (siehe unten), die winget- und Homebrew-Manifeste (siehe Paketmanager für Windows und Mac (in Vorbereitung)), die Dokumentation als PDF in neun Sprachen und die .sha256-Prüfsummen.

1.2. Einen Download überprüfen

Jede veröffentlichte Datei wird von ihrer SHA-256-Prüfsumme begleitet, in einer gleichnamigen Datei mit der Endung .sha256. Laden Sie beide in denselben Ordner und prüfen Sie, dass die erhaltene Datei die veröffentlichte ist:

sha256sum -c blunderdb_x.y.z_amd64.deb.sha256        # Linux
shasum -a 256 -c blunderDB-macos-x.y.z.zip.sha256   # macOS

Get-FileHash .\blunderDB-windows-x.y.z.exe -Algorithm SHA256   # Windows

Unter Linux und macOS gibt der Befehl OK aus; unter Windows vergleichen Sie den angezeigten Wert mit dem Inhalt der .sha256-Datei. Diese Prüfung ist die Garantie, die ohne Codesignatur zur Verfügung steht (siehe Abschnitt 16 und Abschnitt 17).

Jede veröffentlichte Datei wird zusätzlich von einer Herkunftsattestierung (SLSA, über Sigstore) begleitet, die belegt, dass sie tatsächlich vom offiziellen GitHub-Build-Lauf des Repositorys erzeugt wurde, ohne dass ein Schlüssel verwaltet werden muss:

gh attestation verify blunderdb_x.y.z_amd64.deb --repo kevung/blunderDB

1.3. Installation unter Linux

Für Linux werden mehrere Formate angeboten. Die untenstehenden Pakete und Archive machen blunderDB automatisch ausführbar: Im Gegensatz zur über einen Browser heruntergeladenen Rohdatei entfällt das Ausführen von chmod +x bei jedem Download oder Update. Sie legen außerdem einen Eintrag im Anwendungsmenü an.

Bemerkung

Die Pakete .deb und .rpm verknüpfen die Erweiterung .dbx (eine mit Passwort exportierte Datenbank, siehe Eine Datenbank weitergeben: Herkunft und Passwort) mit blunderDB: ein Doppelklick auf eine von jemandem erhaltene .dbx-Datei öffnet sie direkt. Die Erweiterung .db einer gewöhnlichen Datenbank wird bewusst nicht verknüpft — sie ist zu allgemein und wird von anderer Software mitbenutzt — lässt sich aber weiterhin normal über das Menü Öffnen von blunderDB öffnen.

1.3.1. Native Pakete (.deb / .rpm)

Empfohlene Methode unter Debian, Ubuntu und Linux Mint (.deb) sowie Fedora und openSUSE (.rpm). Der Paketmanager installiert automatisch die passende webkit2gtk-Abhängigkeit. Ersetzen Sie x.y.z durch die heruntergeladene Version:

sudo apt install ./blunderdb_x.y.z_amd64.deb     # Debian / Ubuntu / Mint
sudo dnf install ./blunderdb-x.y.z.x86_64.rpm    # Fedora / openSUSE

1.3.2. Arch Linux (AUR)

Das Paket blunderdb-bin ist im AUR verfügbar und wird von AUR-Helfern automatisch aktualisiert:

yay -S blunderdb-bin      # ou : paru -S blunderdb-bin

1.3.3. Flatpak

Das Bundle blunderDB-x.y.z.flatpak läuft auf jeder Distribution, auf der Flatpak installiert ist. Es baut auf der GNOME-47-Laufzeitumgebung auf, die Flatpak bei Bedarf von Flathub herunterlädt:

flatpak install ./blunderDB-x.y.z.flatpak
flatpak run io.github.kevung.blunderDB

blunderDB ist noch nicht auf Flathub veröffentlicht: Das Bundle wird aus der heruntergeladenen Datei installiert und aktualisiert, indem man das der nächsten Version installiert. Die Anwendung hat Zugriff auf das persönliche Verzeichnis, um Datenbanken zu öffnen und zu speichern. Die Befehlszeile (Befehlszeilenschnittstelle (CLI)) erreicht man mit flatpak run io.github.kevung.blunderDB <Befehl>.

1.3.4. .tar.gz-Archiv

Für andere Distributionen. Das Entpacken eines Archivs bewahrt das Ausführbar-Bit, sodass kein chmod nötig ist:

tar xzf blunderDB-linux-webkit2gtk-4.1-x.y.z.tar.gz
cd blunderDB-linux-webkit2gtk-4.1-x.y.z
./blunderDB

Bemerkung

Die ausführbare Datei im Archiv heißt blunderDB, mit Großbuchstaben. Die Pakete .deb, .rpm, AUR und Flatpak installieren zusätzlich den kleingeschriebenen Link blunderdb, den Namen, den die Dokumentation der Befehlszeile (Befehlszeilenschnittstelle (CLI)) verwendet; das Archiv enthält denselben Link neben der ausführbaren Datei. Um ihn in Ihrem PATH zu haben: ln -s "$PWD/blunderDB" ~/.local/bin/blunderdb.

1.3.5. Rohbinärdatei (fortgeschrittene Methode)

Die Rohbinärdatei https://github.com/kevung/blunderDB/releases/latest/download/blunderDB-linux-0.36.0 bleibt verfügbar. Da ein Browser beim Herunterladen das Ausführbar-Bit entfernt, müssen Sie es vor dem ersten Start wiederherstellen:

chmod +x ./blunderDB-linux-x.y.z

Bemerkung

Es werden zwei Linux-Varianten je nach Version der webkit2gtk-Bibliothek veröffentlicht. Wenn Sie die Fehlermeldung libwebkit2gtk-4.0.so.37: cannot open shared object file erhalten, verwendet Ihre Distribution webkit2gtk-4.1: Verwenden Sie das .deb/.rpm-Paket, das AUR-Paket oder laden Sie die dedizierte Version https://github.com/kevung/blunderDB/releases/latest/download/blunderDB-linux-webkit2gtk-4.1-0.36.0 herunter. Native Pakete wählen die richtige Abhängigkeit automatisch aus.

1.4. Docker-Image (Servermodus)

Der Servermodus (Headless-Modus (Server)) braucht die Desktop-Anwendung nicht: Jede Version veröffentlicht das Image ghcr.io/kevung/blunderdb-serve in der GitHub-Registry, für linux/amd64 und linux/arm64, unter dem Versions-Tag und unter latest:

docker pull ghcr.io/kevung/blunderdb-serve:x.y.z

Start, Konfiguration und die Warnung zum authentifizierenden Proxy sind in Veröffentlichtes Image beschrieben.

1.5. Paketmanager für Windows und Mac (in Vorbereitung)

Unter Linux lässt sich blunderDB bereits über den Paketmanager installieren (AUR, .deb, .rpm). Das Gegenstück für Windows (winget) und für Mac (Homebrew) ist in Vorbereitung: die Manifeste liegen jeder Release bei (blunderDB-winget-manifests-x.y.z.zip und blunderdb-x.y.z.rb auf der Release-Seite), sind aber noch nicht in den öffentlichen Repositories eingereicht. Solange das nicht der Fall ist, funktionieren die folgenden Befehle nicht; sie beschreiben die geplante Installation:

winget install KevinUnger.blunderDB        # Windows, une fois publié

brew tap kevung/tap                        # Mac, une fois le tap créé
brew install --cask blunderdb

Weder das winget-Paket noch der Cask ändern die Natur der ausführbaren Datei: Sie bleibt nicht signiert, und die unten beschriebenen Hinweise gelten unverändert. Unter Mac vermeidet brew install --cask --no-quarantine blunderdb die Blockade durch Gatekeeper beim ersten Start.

1.6. Hinweise für Windows und Mac

Warnung

Unter Windows kann es vorkommen, dass das Betriebssystem Bedenken hat, blunderDB auszuführen. Siehe Abschnitt 16, um zu verstehen, warum, und um etwaige Blockaden zu umgehen.

Warnung

Unter Mac kann es vorkommen, dass das Betriebssystem Bedenken hat, blunderDB auszuführen. Siehe Abschnitt 17, um zu verstehen, warum, und um etwaige Blockaden zu umgehen.
