Glossar

Die folgenden Begriffe kehren im gesamten Rest der Dokumentation wieder — Handbuch, Benutzerhandbuch, FAQ, CLI. Diese Seite fasst sie an einem Ort zusammen, statt sie in jedem Abschnitt neu zu definieren.

Stellung

Ein Entscheidungspunkt im Backgammon: Brett, Doppler, Würfel, Spielstand und Matchmarkierungen. Eine zweimal importierte Stellung zählt nur einmal — ihre automatisch berechnete Identität erkennt sie, niemals die Datei, aus der sie stammt.

Einzeln importierte Stellung

Eine Stellung, die allein in die Datenbank gelangt ist — vom Brett geschrieben oder aus einer Stellungsdatei gelesen — statt durch ein Match eingebracht zu werden. Diese Eigenschaft ist dauerhaft: Eine so importierte Stellung bleibt es, selbst wenn danach ein Match importiert wird, das sie enthält.

Markierte Stellung

Eine Stellung, die der Nutzer in der Software, aus der das Match stammt, als studierenswert markiert hat — heute zeichnet nur eXtreme Gammon diese Markierung zugbezogen auf. Eine markierte Doppler-Entscheidung markiert beide daraus entstehenden Stellungen: das Doppeln und die Annahme/Ablehnung.

Analyse

Was eine Engine (eXtreme Gammon, GNUbg, BGBlitz oder der eingebettete gammonNet-Evaluator) über eine Stellung geschlossen hat, gespeichert und später wieder gelesen. Eine Stellung trägt eine Analyse pro Engine; das Importieren einer Analyse überschreibt niemals die einer anderen Engine, noch eine bereits vorhandene Analyse (siehe Import: was geschrieben wird, was es niemals ist).

Bewertung

Das Ergebnis einer Berechnung, die der eingebettete Evaluator an der gerade auf dem Brett stehenden Stellung durchführt, ob gespeichert oder nicht. Eine Bewertung gilt nur so lange, wie sich die Stellung nicht ändert; wird sie gespeichert, wird sie zu einer Analyse.

Referenzsystem

Die Skala, in der eine Zahl zu einer Stellung ausgedrückt wird. Money beantwortet „wie viele Punkte ist das wert“, wobei ein Gammon immer zwei Punkte wert ist. Match beantwortet „wie viel vom Match ist das wert“, auf einer normalisierten Skala, in der ein Gammon wert ist, was der Spielstand daraus macht — fast alles bei 2-away/4-away, nichts für einen Führenden bei 1-away. Das Referenzsystem ist eine Eigenschaft der Stellung, niemals eine Anzeigeeinstellung: Der Away-Spielstand legt es fest.

Normalisierte Equity

Die Match-Equity, ausgedrückt auf der Skala 2 × MWC − 1, wobei ±1 den gewonnenen oder verlorenen aktuellen Doppler darstellt. Es ist die Skala, die blunderDB bei einem Spielstand anzeigt und speichert, niemals die rohen Gewinnwahrscheinlichkeiten.

EMG

Das Kürzel, unter dem eXtreme Gammon und GNUbg die oben genannte normalisierte Equity bezeichnen, und unter dem die Statistiken von blunderDB Fehler zählen: „ein Fehler von 0,100 EMG“ ist ein Fehler von 0,100 auf dieser Skala. Beide Begriffe benennen dieselbe Größe.

Away-Spielstand

Wie viele Punkte ein Spieler noch braucht, um das Match zu gewinnen, aus der Sicht dieses Spielers. Zwei Werte sind Sentinels statt Zählwerte: -1 bedeutet, dass es kein Match gibt — das Referenzsystem ist money — und 0/1 unterscheiden das Spiel nach Crawford (0) vom Crawford-Spiel selbst (1), bei gleicher Distanz zum Sieg.

Regime

Welche Art von Antwort das Panel zu einem Rennen gibt, immer auf dem Bildschirm angegeben, statt dem Leser zum Erraten überlassen:

  • exakt — aus einer zweiseitigen Bearoff-Datenbank gelesen, niemals geschätzt;

  • bewertet — vom eingebetteten Evaluator berechnet, der den Verlauf durchspielt;

  • geschätzt — eine kalibrierte Zusammenfassung eines Verlaufs, gültig für eine Gewinnwahrscheinlichkeit, niemals für ein Doppler-Urteil.

Bearoff-Datenbank

Eine Tabelle von Rennantworten, zweiseitig (das Doppler-Urteil) oder einseitig (das EPC). blunderDB erzeugt einen Teil davon selbst beim ersten Start (bis zu 6 Steine pro Spieler); breitere Domänen werden über den Reiter Bearoff oder die CLI erzeugt. Eine erzeugte Datenbank gilt als verifiziert, wenn ihr Fingerabdruck genau dem entspricht, den GNUbg erzeugt.

EPC (Effective Pip Count)

Eine klassische, einseitige Schätzung der Anzahl der Würfe, die nötig sind, um alle Steine eines Spielers abzutragen — korrigiert um die Verschwendung (wastage) gegenüber dem reinen Pip Count.

Stellungstatsache

Eine Größe, die dem Brett selbst gehört, unabhängig von jeder Wahl, die ein Spieler treffen könnte: Pip Count, EPC, Gewinn-/Gammon-/Backgammon-Chancen, cubelose Equity. Wahr vor dem Wurf.

Baseline vor dem Wurf

Der Vektor aus Gewinn-/Gammon-/Backgammon-Chancen und cubeloser Equity, angezeigt über der Liste der Kandidatenzüge, sobald die Würfel gefallen sind. Der Abstand zwischen dieser Zeile und einem Zug misst das Würfelglück, niemals das Verdienst des gespielten Zugs.

Entscheidung

Die Antwort auf die Frage, die das Brett stellt: die Rangfolge der Kandidatenzüge, wenn Würfel gefallen sind, oder sonst die drei Doppler-Optionen und ihr Urteil. Eine Stellung stellt niemals beide Fragen zugleich.

Urteil

Welche Option einer Doppler-Entscheidung die richtige ist: kein Doppel, Doppel/Annahme, Doppel/Ablehnung oder zu gut (zum Doppeln). Zwei Sonderfälle bleiben nie leer: keine Entscheidung (das Regime ist dazu nicht befugt) und abgelehnt (die Engine hat die Stellung abgelehnt, typischerweise ein Spielstand außerhalb der Reichweite ihrer Tabelle).

Zu gut (zum Doppeln)

Das Urteil, das besagt, dass die Stellung so günstig ist, dass ein Doppel den Gegner zur Ablehnung veranlassen würde, während Weiterspielen ohne Doppeln mehr einbringt — ein Doppler, den man besser behält.

Glück

Der Beitrag des Würfelwurfs zur Equity eines Zugs, aus der Quelldatei beim Import gelesen (eXtreme Gammon, GNUbg) und niemals von blunderDB neu berechnet. Formate, die es nicht mitführen (BGF, Jellyfish .mat), liefern es nie, und der Import ist nicht rückwirkend.

Blunder

Ein Zug oder eine Doppler-Entscheidung, dessen Fehler (der Equity-Abstand zur besten Wahl) einen Schwellenwert überschreitet; der Befehl bl (oder blunders) lädt direkt die schlimmsten Fehler einer Suche.

Millipunkt (mpt)

Ein Tausendstel eines Equity-Punkts: Ein Fehler von 0,100 Equity ist 100 mpt wert. Dies ist die Einheit, in der sich die Größen einer Stellung ablesen lassen — die Blunder-Schwelle, die Suchfilter e> und E>, das Histogramm der Fehlergrößen, das durchschnittliche Glück pro Wurf. Der PR liest sich nicht auf dieser Skala: Sein Faktor ist 500 und nicht 1000, sodass ein PR von 5,0 einem durchschnittlichen Fehler von 10 mpt pro Entscheidung entspricht.

PR (Performance Rating)

Die durchschnittlichen Fehlerkosten eines Spielers, Zug- und Doppler-Entscheidungen zusammen: der durchschnittliche Equity-Fehler pro gezählter Entscheidung, multipliziert mit 500 wie bei eXtreme Gammon und GNUbg. Ein PR von 5,0 entspricht somit 0,010 verlorener Equity pro Entscheidung. Siehe Anhang: Statistikmodell — Abgleich XG / gnuBG / blunderDB für die genauen Zählregeln (Parität mit eXtreme Gammon und GNUbg).

Snowie Error Rate

Derselbe Zähler wie beim PR (die Summe der Fehler), aber geteilt durch die Anzahl der gespielten Züge statt der Anzahl der gezählten Entscheidungen — stabiler von Tool zu Tool. Siehe Anhang: Statistikmodell — Abgleich XG / gnuBG / blunderDB.

MWC-Kosten

Ein Doppler-Fehler, ausgedrückt in Prozentpunkten der Match Winning Chance statt in Equity — die natürliche Größe, um denselben Spieler bei unterschiedlichen Spielständen zu vergleichen.

Sammlung

Eine benannte, geordnete Menge von Stellungen, die der Nutzer von Hand zusammenstellt, Drag-and-Drop eingeschlossen. Die Zugehörigkeit zu einer Sammlung ist eine ausdrückliche Geste, anders als bei einer einzeln importierten Stellung (siehe Sammlungen-Panel).

Anki-Deck

Eine Menge von Stellungen, die in Karten verwandelt wurden, die per verteilter Wiederholung (FSRS-Algorithmus) wiederholt werden. Siehe Anki-Panel.

Wiederholungskarte

Eine Stellung aus einem Anki-Deck, dargestellt als Frage: Das Brett ist die Frage, die gespeicherte Analyse ist die Antwort, verborgen bis zur Geste, die sie enthüllt.

Kommentar

Freier Text, der an eine Stellung angehängt ist, sei er vom Nutzer getippt oder wörtlich aus einer importierten Datei übernommen — die beiden sind nicht zu unterscheiden. Ein #Stichwort in einem Kommentar ist ein Tag, durchsuchbar wie jeder andere Text.

Spieler

Ein Name genau so, wie er in einem importierten Match erscheint. blunderDB errät nicht die Person hinter dem Namen: derselbe Mensch, der unter zwei Schreibweisen unterschreibt, ist zwei verschiedene Spieler, bis zu einer ausdrücklichen Zusammenführung („Spieler zusammenführen“).

Wasserzeichen

Die signierte Erklärung, angebracht von demjenigen, der eine Datenbank exportiert, darüber, was sie ist und woher sie kommt. Fälschungssicher, aber nicht unentfernbar, zeichnet sie niemals etwas auf der Empfängerseite auf. Siehe Eine Datenbank weitergeben: Herkunft und Passwort.

Aussteller-Identität

Der Schlüssel, der die Wasserzeichen einer Person signiert — von selbst beim ersten angebrachten Wasserzeichen erzeugt, und von einer Maschine zur anderen als einzelne Datei übertragbar.

Geschützte Datei (.dbx)

Eine exportierte und passwortverschlüsselte Datenbank, einmal geöffnet und danach gewöhnlich. Sie schützt die Datei beim Transport, nicht ihren Inhalt: Wer das Passwort erhält, kann sie öffnen.

Tenant

Im Servermodus der Eigentümer einer Menge von Stellungen, Matches und Sammlungen. Nichts, was ein Tenant speichert, ist jemals für einen anderen sichtbar. Auf dem Desktop gibt es nur einen einzigen, impliziten: die Person, deren Datei es ist. Siehe Headless-Modus (Server).
