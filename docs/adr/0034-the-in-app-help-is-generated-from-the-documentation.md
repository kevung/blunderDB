# The in-app help is generated from the documentation

## Status

accepted — 2026-09-03. Answers fiche H.7 (#249) and closes the lint-exclusion finding
of fiche D.15 by removing its cause rather than its symptom. Amended 2026-09-06: the
*manual* tab, named under *Consequences* as a later step, is now generated too — from
`manuel.rst` whole, with no section manifest (see *The manual tab, amended*). Three of
the four help tabs are generated by this decision. The *About* tab is deliberately
never generated.

## Context

`frontend/src/i18n/help/*.js` was **11 920 lines of hand-written HTML across nine
languages** (1 322–1 326 per file), four tabs each, injected into `HelpModal.svelte`
with `{@html}`. Measured on the day this was written:

- **81 % of each file was a copy of the documentation.** In `fr.js`, the *shortcuts*
  tab (507 lines) and the *commands* tab (570 lines) restated, as HTML tables,
  `doc/source/raccourcis.rst` (337 lines) and `doc/source/cmd_mode.rst` (266 lines) —
  the same shortcuts, the same commands, the same filter tokens, written a second time
  in nine languages by hand.
- **Nothing kept the two in step.** `helpVocabulary.sync.test.js` locked the commands
  table to `commandVocabulary.js`, and the per-language `h3`/`li`/`tr` counts to
  `fr.js`. Neither of those touches the documentation: the help could restate every
  command correctly and still describe them wrongly, in a wording the manual had
  abandoned two releases earlier.
- **It did.** Fiche H.6 (#248) measured it: the watermark and the whole controlled
  distribution of 0.31.0 had **zero occurrences** in the nine help files; the panel had
  been renamed *Eval* and the help still said *Bearoff* seven times out of eight, and
  *Calculatrice EPC* once. Fixing that was nine files edited by hand, one language at a
  time, with nothing to say when it was complete.
- **The drift ran both ways.** `raccourcis.rst` documented sections the help never had
  (view tabs, the tournaments panel) and ten notes on exact behaviour (what `TAB` does
  once focus sits on a control, why `MAJ-J`/`MAJ-K` run opposite to `j`/`k`, what
  BACKSPACE resets in the Eval panel). `cmd_mode.rst`'s filter table carried `xD65`,
  `pl'nom'`, `T>x` and the `E>x` aggregation note, none of which the help had. The
  hand-written help was not a shorter digest of the manual; it was an older copy of it.
- **The two sides had incomparable translation tooling.** The `.rst` side has eight
  gettext catalogues, `scripts/doc-po-update.sh`, `scripts/doc-i18n-check.sh` and a
  release gate that must end on *all translations complete*. The help side had eight
  files edited by hand: no completeness check, no fuzzy marking, no way to tell a
  translated tab from a copy-pasted French one.
- **The files were excluded from eslint** (they exceed espree's parser limits) and
  injected with `{@html}`. Fiche D.15 found the exclusion had been hiding a real hole:
  the About tab spliced `{appVersion}`/`{dbVersion}` into raw HTML with no escaping.

## Decision

**The help bundles are a build artefact of the documentation, not a source file.**
`cmd/help-gen` (Go, standard library only) renders `frontend/src/i18n/help/<lang>.js`
for the nine documentation languages; `make help` runs it and
`TestHelpBundlesAreCurrent` fails when a committed bundle no longer matches what the
documentation says. Each file opens with a `// GENERATED FILE` banner and is never
edited by hand.

**A tab is generated when the documentation already states it exhaustively; it stays
prose when it is editorial.** The two reference tabs are rendered from the `.rst`:

| tab | source |
|---|---|
| `shortcuts` | `doc/source/raccourcis.rst` |
| `commands` | `doc/source/cmd_mode.rst` |
| `manual` | `doc/source/manuel.rst` |
| `about` | `frontend/src/i18n/help/prose/<lang>.html` (hand-written, permanently) |

The criterion is not the size of the duplication but its *kind*. An exhaustive list —
every shortcut, every command, every filter token — goes stale one row at a time and
nobody notices a missing row; that is the duplication which produced every one of
H.6's findings. An editorial page (the manual digest) and application metadata (About:
version, author, licence, credits) are not restatements of a reference list and have no
`.rst` to be generated from — About never will have one.

**Sphinx is not in the loop, and neither is Python.** The generator reads the `.rst`
sources and the `.po` catalogues directly. Sphinx's gettext builder extracts each
`csv-table` **cell** as its own `msgid` (verified against the committed catalogues), so
a cell-level lookup is all a translation needs. The generator understands the constructs these
three documents are written in — sections, paragraphs, bullet lists, `csv-table`, the
`note`/`tip`/`warning`/`important`/`caution` admonitions, indented bodies (parsed by
re-entering the same reader, which is what carries the manual's definitions and the
directives nested inside them) and the one `math` block, reproduced verbatim — plus
inline `` ``literal`` ``,
`` `interpreted` ``, `*emphasis*`, `**strong**`, `:ref:` and reStructuredText's
backslash escapes (including the `\ ` the Japanese catalogues use to separate markup
from adjacent CJK text).

**A missing translation is an error, never a French fallback.** Every string the
generator emits in a non-French bundle is looked up in that document's catalogue; a
missing `msgstr` aborts the run. The failure mode this replaces — French text quietly
served under a foreign flag — is the one that made the drift invisible.

**The bundles are committed, not built at `npm run build`.** Building them at frontend
build time would put Python, Sphinx and `doc/requirements.txt` on the critical path of
every `wails dev` and of four CI runners (`ubuntu-latest`, `ubuntu-22.04`,
`windows-latest`, `macos-latest`). Committed, they cost a reviewable diff and a Go test
that needs nothing but the repository.

**Escaping is the generator's job, and the check runs on the shipped corpus.** Every
string taken from a `.rst` or a `.po` is HTML-escaped **before** the inline-markup pass,
which can only emit the fixed tag vocabulary written in `render.go`; nothing from the
sources can become an element. `src/__tests__/help.safety.test.js` then inspects the
nine generated bundles for what `{@html}` would execute — scripts, inline event
handlers, `javascript:`/`data:` URLs, unhardened links — and for interpolation
placeholders other than the two `HelpModal` escapes itself. That suite, not the eslint
exclusion, is now what stands between the help corpus and `{@html}`.

## Considered options

- **Run Sphinx (`-b html`, per section, nine languages) at `npm run build`**, the
  fiche's option (a) taken literally. Rejected on its runtime, not on its shape — the
  shape is what this decision adopts. Sphinx at frontend-build time makes a Python
  toolchain a hard dependency of `wails dev` and of the Windows and macOS CI builds; and
  its HTML is docutils' full output (section anchors, permalinks, headerlinks, tabular
  admonitions, `figure::` images that are not in the app bundle), which needs a
  stylesheet-reduction pass that then becomes its own thing to maintain. Reading the
  `.rst` and `.po` directly gives the same single source with none of that.
- **Reduce the help to a table of contents plus deep links to the site**, the fiche's
  option (b). It deletes the most lines and it does end the drift. Rejected on offline
  mode, and specifically: blunderDB is a desktop binary whose help is opened with `?`
  *while the application is in front of you* — at a club, at a tournament table, on a
  laptop with no network. What the reader wants at that moment is precisely the
  exhaustive lists (which shortcut, which filter token), the part a link cannot serve
  offline and the part a browser tab serves worst. It would also have traded a stale
  help for an empty one: the fix for H.6's findings would have been "go online", which
  is not a fix. The About tab, finally, has no page on the site to link to.
- **Keep the help hand-written and add a test comparing section titles to the `.rst`**,
  the fiche's complement to option (a). Rejected as a standalone answer: it catches a
  *missing section*, and not one of H.6's findings was a missing section — they were
  stale sentences inside sections that existed. The test is worth having, and it now
  exists in a stronger form (the commands table is compared to `commandVocabulary.js`
  in all nine languages), but as the whole answer it would have left the duplication and
  bought a guard against the failure mode that did not occur.
- **Generate the `.rst` from the help instead.** Rejected: the documentation is the
  richer, published, translated artefact, and gettext works on `.rst`. Inverting the
  direction would mean re-deriving eight catalogues from HTML fragments.

## Consequences

- **Hand-maintained help HTML falls from 11 920 lines to 2 348** (the prose fragments),
  −80 %. The two generated tabs are ~9 400 lines of artefact written once, in French, as
  603 lines of `.rst`.
- **The help inherits the documentation's translation tooling.** A shortcut added to
  `raccourcis.rst` reaches nine languages through `scripts/doc-po-update.sh` and is
  gated by `scripts/doc-i18n-check.sh` ending on *all translations complete*, the same
  gate the online docs already pass at every release. There is no second, untooled
  translation surface any more.
- **The help gained content it never had**: the view tabs and tournaments-panel
  shortcuts, the ten behavioural notes, the complete filter table — rendered as
  admonition blocks and `<code>` spans that `HelpModal.svelte` now styles.
- **`make help` is required when `raccourcis.rst` or `cmd_mode.rst` changes**, and
  `go test ./cmd/help-gen` fails until it is run — the same shape as
  `scripts/build-demo-db.sh`/`TestDemoDatabaseIsCurrent`.
- **The `manual` tab, amended (2026-09-06).** It is generated from `manuel.rst`,
  whole. The follow-up above proposed a *section manifest* keyed on `.. _label:`
  anchors, to choose which sections the modal shows; that was rejected on measurement
  when the time came to write it. By then the hand-written digest had drifted **eight
  sections** behind the manual — the trash, the tags, the micro-drills, the cube
  matrix, the watched folder, the guided tours, the view tabs, the metadata panel —
  in nine languages, with nothing to catch it. That is H.6's failure mode returning to
  the one tab the first pass left hand-written, which settles the question the manifest
  was meant to keep open: a manifest is a second list to maintain, and a list nobody
  updates is exactly what drifted. The modal now shows the manual's own prose, which
  the ADR named as the price and which is the right price: it is the text the release
  process already audits, translates and gates. The manual's six `figure::` images are
  skipped, as unknown directives always were — the app is in front of the reader, the
  screenshots are on the site.
- **The help bundles grow from ~445 kB to ~1.7 MB across the nine languages**, English
  (static, the per-tab fallback) from ~50 kB to ~150 kB. The other eight are fetched
  only when the modal opens (#207), so the cost at startup is English alone; the
  binary carries the rest in `frontend/dist`. That is the price of the manual being
  present offline rather than a link, which is the same trade this ADR made when it
  rejected the table-of-contents option.
- **1 859 lines of hand-written digest are deleted**; the prose fragments fall to the
  About tab alone (595 lines across nine languages).
- **Two latent defects surfaced the moment a richer document went through the reader**,
  both fixed here: `scanTargets` did not recognise an *overlined* title, so every
  `:ref:` into `mode_headless.rst` failed to resolve; and `:ref:`text <label>`` never
  matched, because `inline()` escapes before it substitutes and the angle brackets were
  already `&lt;`/`&gt;` by then. A third was in the documentation, not the generator:
  `.. _panneau_matchs:` sat fourteen lines above its title, in the middle of a
  paragraph about collections, so the cross-reference to the retention rule resolved to
  the wrong section. The reader is now a check on the sources, not only a consumer.

- **A construct the reader does not know disappears silently.** Unknown directives are
  skipped whole (that is what lets `scanTargets` walk documents this reader cannot
  parse). The mitigation is bounded: these two documents use five constructs, and adding
  a sixth is a reviewable `.rst` change whose absence from the help is visible on the
  next `make help` diff. A *changed* string is not silent — the `msgid` lookup fails and
  the generator stops.
