Idempotency

Most methods need no special mechanism at all: reads have no side effect, and positions.save (like the rest of positions.*) is naturally idempotent through its Zobrist content hash — saving the same position twice returns the same row, never a duplicate. 3 methods lack that property (two calls are two distinct effects) and accept an optional Idempotency-Key header: a call retried with the same key returns the first attempt’s result instead of repeating its effect — see the “(Idempotency-Key)” mark in the table above. No other method needs or accepts that header.
