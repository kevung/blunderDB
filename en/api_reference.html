Idempotency

Most methods need no special mechanism: reads have no side effects, and the writes of positions.* are idempotent in effect thanks to the Zobrist hash of the content — saving the same position twice returns the same row, never a duplicate. 48 methods accept an optional Idempotency-Key header: those whose two calls are two distinct effects, and positions.save, whose response says whether the call created the position (created) and would say so wrongly if replayed after a lost response. A call replayed with the same key returns the result of the first attempt instead of repeating its effect — see the “(Idempotency-Key)” mark in the table above. No other method needs or accepts this header.

Conditional reads

Methods marked “(ETag)” return an ETag header. Sending it back in If-None-Match gets a body-less 304 response as long as nothing the method reads has changed — see Tournament direction and events.

Timecodes of a transcription

A transcriptions.apply gesture can carry the video instant at which it is made, in milliseconds from the start of the media: TickMS, read only when HasTick is true (0 is an instant). enter_die makes it the timecode of the roll (the first die key counts); enter_play, validate, dance, double, take, pass and resign make it the timecode of the action, on a new action only: an in-place correction keeps the timecodes it had. The set_timecode gesture sets TickMS (with HasTick) and RollTickMS (with HasRollTick) on the cursor’s action; a negative value clears the timecode. The set_video gesture attaches the video source named by VideoSource (http(s) URL or local path), and an empty string detaches it; set_header also sets it when its header names one, but never clears it.

The seek_cursor gesture puts the cursor on the action of rank At, the end of the document past the last one, without writing anything or stacking on the undo stack: this is how the cursor follows a playing video. A decision_ms accompanied by decision_estimated is an estimate: a play without an action timecode, measured from the roll to the next action’s first instant.

The rendered state carries the source in header.video_source, the timecodes of each action in roll_tick_ms and tick_ms, and, on each annotated action, the durations decision_ms and cube_decision_ms: measured by the Arbiter when they are, otherwise deduced from the timecodes. A timecode earlier than the previous one is flagged by the timecode_backwards inconsistency and leaves the durations that depend on it unknown.
